## 1. P0：⋯ 菜单看不见（必须修）

### 现象

点地址栏右侧 ⋯，四项（历史记录 / 书签 / 页面内查找 / 优化内存）出现在辅助功能树里、也能被程序点到，但**屏幕上完全不渲染**。

### 根因

Sparo 的网页是 `WebContentsView` 原生子视图，永远绘制在 shell DOM 之上。`.nav-menu` 是 `position:absolute; top:calc(100%+6px)`，展开后正好落在网页区 → 被原生视图盖住。原来的书签菜单之所以没这个问题，是因为它走的是**主进程原生菜单** `popupBookmarksMenu()`。

### 改法：改回主进程原生菜单

**1）`src/main/browser.ts`**

在 `popupBookmarksMenu()`（约 L2135）上方新增：

```ts
openNavMenu(): void {
  const loc = this.settings.locale;
  const template: MenuItemConstructorOptions[] = [
    { label: tx(loc, "nav.history"), click: () => this.openHistory() },
    { label: tx(loc, "bookmark.menu"), click: () => this.popupBookmarksMenu() },
    { type: "separator" },
    {
      label: tx(loc, "nav.find"),
      click: () => {
        try {
          this.window.webContents.focus();
          this.window.webContents.send("spark:open-find");
        } catch {
          /* ignore */
        }
      },
    },
    {
      label: tx(loc, "mem.optimize"),
      click: () => {
        const r = this.discardInactiveTabs();
        this.window.webContents
          .executeJavaScript(
            `window.__sparkToast && window.__sparkToast(${JSON.stringify(r.message)})`,
          )
          .catch(() => undefined);
      },
    },
  ];
  Menu.buildFromTemplate(template).popup({ window: this.window });
}
```

- `Menu`、`MenuItemConstructorOptions`、`tx` 本文件已经导入，别重复 import。
- 文案 key 全部已存在（`nav.history` / `bookmark.menu` / `nav.find` / `mem.optimize`），**不要新增 i18n key**。

在 `spark:bookmarks-menu` 注册（约 L2114）旁边加：

```ts
handle("spark:nav-menu", async () => this.openNavMenu());
```

**2）`src/main/shell-preload.ts`**

在 `openBookmarksMenu` 下面加一行：

```ts
openNavMenu: () => ipcRenderer.invoke("spark:nav-menu"),
```

**3）`src/renderer/shell.html`**

- 删除 `#navMenu` 整块 DOM（L1509-1523）与 `.nav-menu` / `.nav-menu.hide` 及只给它用的 `.menu-item` / `.menu-sep` / `.menu-hint` 规则（L283-295 及相邻规则）。删除前先全文搜一遍，确认没有别处再用这些 class。
- `#navMoreWrap` 若只用于定位菜单，也一并删掉，`#btnNavMenu` 直接放在 `.bar` 里。
- 删除 JS：`navMenu` / `navMenuBtn` / `setNavMenuOpen` / `btnHistory.onclick`（约 L2241）/ `btnMem` 绑定（约 L3737-3738）/ `btnFind.onclick`（约 L3868）/ `btnBmMenu.onclick`（约 L3872）/ 文档点击关闭逻辑（L3853-3875）。
- 新增唯一绑定：

```js
const btnNavMenu = document.getElementById("btnNavMenu");
if (btnNavMenu) btnNavMenu.onclick = () => window.sparkShell.openNavMenu();
```

- `optimizeMemory()` 如果只剩 `btnMem` 一个调用点，删除函数本体；还有别的引用就留着。
- `#btnNavMenu` 的 `aria-haspopup="true"` 保留，`aria-expanded` 因原生菜单无法同步，删掉该属性。

## 2. P1：侧栏拖拽热区太窄

### 现象

`.side-resizer` 现在是 `left:-3px; width:6px`，而 `.sidebar` 有 `overflow:hidden`，左侧 3px 被裁掉；剩下 3px 紧贴网页原生视图边缘，实机自动化抓不住，人工也很难一次拖中。

### 改法（`shell.html`）

```css
.side-resizer {
  position: absolute;
  left: 0;
  top: 0;
  bottom: 0;
  width: 8px;
  cursor: col-resize;
  z-index: 30;
}
```

- `::after` 的可视线仍画在 `left: 1px`（1px 竖线），不要变粗。
- 拖动逻辑（`pointerdown/move/up`、300–480 夹取、双击回 340、松手落盘）**一行都不许改**。

### 验收

`npm run start` 后：把鼠标放到侧栏左边缘，光标变成左右箭头；按住向左拖，侧栏变宽、网页区跟着变窄；双击回 340；收起后再展开宽度还原。
