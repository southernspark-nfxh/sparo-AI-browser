## 0. 现状问题

同一个"登录/填密钥"一共 4 套实现：

| # | 位置 | 形态 |
|---|---|---|
| 1 | 欢迎卡 `#welcomeHome` | 三张选择卡 |
| 2 | 输入框锁屏 `#lockHome` → `#lockCloud` / `#lockByok` | 两套完整表单（邮箱+验证码 / 服务商+模型+地址+密钥） |
| 3 | 右上角头像浮层 `#userPop` | 纯导航（没有表单，合格） |
| 4 | 设置抽屉 `.ds-panel[data-panel=common]` | `#dsByokFields` + `#cloudLoggedOut` |

要留的是 **4**（设置·模型），2 里的两套表单全部删掉，2 只剩一张引导卡，1 和 3 只保留"跳转"。

---

## 1. 目标

1. 全项目只有**一处**邮箱/验证码输入、**一处**密钥输入（都在设置·模型里）。
2. 未配置模型时，输入框上方只显示：一句说明 + 一个主按钮「去设置模型」。
3. 欢迎卡三个选项、头像浮层三个入口，全部跳到设置·常用，不再有第二套表单。
4. 删除约 60 行锁屏 DOM 与对应 JS，页面不报 `null` 错。
5. 云端登录、BYOK 保存、锁解除三条链路仍然可用。

- **不许动云端 IPC**：`cloudSendCode`、`cloudVerify`、`cloudLogout`、`cloudRefresh`、`cloudCheckout` 的名称与参数不变。

- 不许改 `paused` / `need-setup` 的判定逻辑。

## 6. 验收（`npm run start`，必须用真实动作走完三条链）

### 链路 1：未配置 → 去设置 → 保存 Key → 解锁

- [ ] 首次打开（或清掉设置后），输入框被锁，只有一句说明 + 一个「去设置模型」按钮
- [ ] 点按钮，设置抽屉在「常用」打开，能看到「自己的 Key / 云端模型」两张卡
- [ ] 选「自己的 Key」，填服务商、模型、密钥，保存成功
- [ ] 关掉抽屉，输入框解锁，可以正常发一句话
- [ ] 控制台没有任何 `Cannot read properties of null`

### 链路 2：云端登录

- [ ] 抽屉里选「云端模型」，出现邮箱 + 验证码两个框（全项目唯一一处）
- [ ] 发送验证码有提示，登录成功后显示邮箱与点数
- [ ] 退出登录后能回到未登录态

### 链路 3：其它入口都跳同一处

- [ ] 欢迎卡「试用云端模型」→ 设置·常用，模式卡在云端
- [ ] 欢迎卡「使用自己的模型」→ 设置·常用，模式卡在自己的 Key
- [ ] 头像浮层「登录试用」→ 同上
- [ ] 头像浮层「填写自己的密钥」→ 同上

### 视觉

- [ ] 输入框锁屏区域高度明显变小，不再顶掉对话区
- [ ] 抽屉只有一处登录表单，没有重复的邮箱框
