## 1. `FIELD_VALUE_SCRIPT` 没导入（P0，会直接抛 ReferenceError）

**文件**：`d:\download\sparo上架应用商店版\src\main\analyzer\execute-primitives.ts`

```ts
const r = await browser.execute(`(${FIELD_VALUE_SCRIPT})(${JSON.stringify(ref)})`);
```

文件顶部的 import 块（L4–L14）里**没有**这个符号。常量本体在 `src\main\page-scripts.ts` L2288：

```ts
export const FIELD_VALUE_SCRIPT = `(function(ref){
```

**后果**：`readField()` 一旦执行就 `ReferenceError: FIELD_VALUE_SCRIPT is not defined`，填表后的「读回校验」整条路径全废。`npm run build` 不会报错（esbuild 不做类型检查），所以一直没被发现。


注意是**值导入**，不能用 `import type`。路径是 `../page-scripts.js`（从 `src/main/analyzer/` 上一级）。

**自检**：

## 2. deepseek 把数组当字符串 trim（P0）

**文件**：`d:\download\sparo上架应用商店版\src\main\agent\deepseek.ts`

**现状**：`ChoiceContent` 类型是 `string | ImagePart[] | null`（L59），但三处直接 `.trim()`：

| 行号 | 现写法 |
|---|---|
| L444 | `(data?.choices?.[0]?.message?.content \|\| "").trim()` |
| L506 | `(choice.content \|\| "").trim()` |
| L576 | `(final?.choices?.[0]?.message?.content \|\| "").trim()` |

**后果**：多模态模型返回数组内容时 `trim is not a function`，整轮对话崩。纯文本模型不触发，所以测试没覆盖到。

**改法**：新增一个私有方法（类内，`safeRun` 附近即可）：

```ts
private contentText(content?: string | ImagePart[] | null): string {
  if (!content) return "";
  if (typeof content === "string") return content.trim();
  return content
    .filter((p) => p && p.type === "text" && typeof p.text === "string")
    .map((p) => String(p.text))
    .join("\n")
    .trim();
}
```

`ImagePart` 的实际字段以 `src\main\agent\vision.ts` 为准；如果字段名不是 `text`，按真实定义改，**不要猜**。

三处替换成 `this.contentText(...)`。

**红线**：L500 的 `content: choice.content ?? null` 不许动——那是回传给工具循环的原始结构。

**测试**：补一条单测，`content` 传 `[{ type: "text", text: "你好" }]` 时返回 `"你好"`，传字符串时照旧。
