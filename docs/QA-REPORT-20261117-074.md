## 5. 多账号（任务书 §3.5，真机补了 A3）

隔离实例初始 `list_envs` 为 0。

1. `create_env`，名字「QA环境A」。得到 id `5816e76e`。
2. `navigate({ url: "https://example.com", envId: "5816e76e" })`。标签 `ec30f8b3` 带 `envId`，标题 Example Domain。
3. 在该标签执行：`document.cookie="iso_probe=A"`，`localStorage.setItem("iso","A")`。读回 `iso_probe=A` / `A`。
4. 不带 `envId` 再开一张 `https://example.com`（标签 `c3e95acf`）。读回 cookie 空字符串，localStorage `null`。
5. 回到 `ec30f8b3`，探针还在。

A1（分区隔离）、A2（`create_env` + 带 `envId` 的 `navigate`）在这份安装包上成立。

**A3 与文档不符，这是本轮唯一新的功能问题。**

`delete_env({ envId: "5816e76e" })` 返回 `env 5816e76e deleted`。之后：

- `list_envs` 为 0。配置项没了。
- `list_tabs` 里 `ec30f8b3` 仍在，而且仍带 `envId: 5816e76e`。
- 磁盘 `%TEMP%\sparo-qa-074\Partitions\env_5816e76e` 还在，49 个文件。`Network\Cookies` 20,480 字节。
- 删除之后再在这张标签执行读 cookie，结果仍是 `iso_probe=A`。

[MULTI-ACCOUNT.md](./MULTI-ACCOUNT.md) 写的是：删除环境会删掉配置；磁盘上 `Partitions/env_<id>/` 留空壳，不含有效登录态；这个号在本机就不再可用。

实测：配置删了，分区不是空壳，标签还在用这份登录态。人如果删环境时期望「这个号立刻不能用」，做不到。标签一直开着，Cookie 就一直能用。

建议二选一，本轮没改代码：

- `delete_env` 时关掉该环境的标签，并清掉对应 partition；或
- 改文档，写明「已打开的环境标签要关掉才真正失效，磁盘分区会留下」。
