## 1. R8-1 采样前置（规划方执行，Cursor 不执行）

真实认领会先保存草稿，属于写操作。采样必须由用户当场明确同意，规划方只读采样，Cursor 不得在真实账号上代跑。采样内容：

1. 在用户指定的**测试采集记录**编辑页点一次「保存并认领」（该动作会真实保存草稿，可能留下速卖通草稿；不拿有料商品试）。
2. 弹窗出现后只读采样：
   - 弹窗标题、容器结构（ant-modal / 自定义）；
   - 店铺选择控件类型（下拉 / 单选 / 列表）、候选店铺名与值来源、默认选中项；
   - 确认、取消按钮的确切文字；是否还有采集箱、分组、分类等必选项；
   - 弹窗里的错误提示和重复认领提示文案。
3. 若用户同意完成一次认领，继续采样成功后落点：
   - 是当前标签跳转、新开标签，还是弹窗内提示；
   - 成功后的 URL 形态（是否含草稿号）；
   - `draftId`、`shopId`、`recordId` 能否从页面标记（`data-draft-id` / `data-draft-shop-id` / `data-record-id`）读到，还是只能从 URL 读；
   - 认领后采集箱列表是否出现该草稿（R7 判重会命中标题，停 `ambiguous`，不会自动二次认领）。
4. 采样结果回填本任务书附录 A。**附录 A 没填完之前，R8-3 不动 live 认领代码。**

用户不授权采样时：本轮只交 R8-2、R8-4、R8-5 的可测部分和 R8-3 的骨架，`claim` 继续停等，真机挂 R9。

## 2. 任务

### R8-2 认领弹窗只读探针与候选匹配（纯函数）

- 新模块 `dxm-smt-claim.ts`（命名可调，但必须独立）：
  - `SMT_CLAIM_TEXT`：按钮文字、弹窗标题、确认/取消文字等集中成常量，采样后回填；
  - `READ_CLAIM_DIALOG_SCRIPT`：**只读**。返回弹窗是否出现、标题、候选店铺（名称 + 值/ID）、当前选中项、确认按钮是否存在、弹窗错误文案。不点任何控件；
  - `pickClaimShop(options, target)` 纯函数：按 `shopId` 精确匹配优先，其次按店名精确匹配；唯一命中返回该候选，0 条或多条都返回停等，并列出候选名，不默认第一个；
  - `claimDialogOpened(read)` / 失败原因映射：弹窗没出现、控件结构对不上、候选读不到、确认按钮找不到，各给一句人话。
- 选择器一律走「已核对标记」常量；常量没回填时 live 层必须停等，不猜。

### R8-3 live 认领实现（附录 A 回填后开写）

`dxm-smt-live.ts` 的 `claim` 按以下顺序实现，**只在 `port.tabId`（采集编辑页）上操作**：

1. 确认当前标签仍是采集编辑页（`crawlEditUrlId`），不是就停等，不新开标签、不导航。
2. 点击「保存并认领」（只认文字精确匹配、不在表格行内的按钮）。点击前写日志，点击后不重复点。
3. 轮询等弹窗（上限 10 秒、间隔 400ms）：
   - 弹窗没出现 → 返回 `ok:false`、`blocker:"entry"`，原因「点保存并认领后没有出现认领弹窗，已停等」；
   - 弹窗出现但结构对不上 / 读不到候选 → `ok:false`、`entry`，原因一句人话。
4. 按目标店铺匹配候选：
   - 唯一命中：选中该候选（控件是搜索框就先填店名再选，是列表就点该行）。**只允许选中目标店铺这一下**；
   - 0 条或多条：不选、不点确认，返回 `ok:false`、`entry`，原因写明没有匹配或匹配了哪几家。
5. 点确认（只认附录 A 记下的确认按钮文字），轮询等落点（上限 10 秒）：
   - 弹窗报错 / 仍在弹窗 → `ok:false`，带回弹窗错误原文；
   - 成功但页面没进草稿编辑页 → `ok:false`、`timeout`，原因「认领已提交，但没有进入草稿编辑页，已停等」。
6. 读回草稿三证（优先级按附录 A）：页面 `data-draft-id` / `data-draft-shop-id` / `data-record-id`，缺失再从 URL 读。三项任一读不到，返回 `ok:false`、`timeout`，不猜、不把空值当成功。
7. 返回 `{ ok:true, draftId, shopId, shopName, recordId, message }`。写 `claimedDraftId` 和 `state: claimed` 由现有 listing 逻辑完成，R8 不改。

硬边界：

- 不刷新、不重开、不把编辑页导航走；不新开标签做认领（认领必须在用户正看的采集编辑页上完成）。
- 认领失败不重试、不点第二次；恢复靠现有「先判重、再决定」逻辑。
- 弹窗里只允许「选目标店铺」和「点确认」两个动作；取消只在用户要求时由人点，代码不点。

### R8-4 授权门与侧栏提示词

- `dxm_smt_prepare` 新增可选参数 `claimConsent`（字符串，用户当次明确认领的原话）。
- `dxm-smt-listing.ts` 走到 `port.claim` 之前判断：`claimConsent` 为空 → 直接停等 `waiting_human`，文案「认领需要你当场确认，已停等，没有点保存并认领」，认领零调用；非空才调用。
- 授权只对这次准备有效，不落盘布尔值（同 `paidConsent` 模式）。
- `free-soul.ts` 与 `strategies/skills/dxm-smt-listing.json` 补一句：用户明确说「认领」「保存并认领」后，才把用户原话放进 `claimConsent` 再跑 prepare；用户没说就不带。`claimConsent` 不是店铺名，不能自己编。
- 决策点先登记再合码：#43 认领授权门、#44 认领后编辑页没跟上就停等（本任务书已同步写入 `docs/DECISION-POINTS.md`）。

## 6. 真机验收（规划方复审时执行，需用户当场授权）

1. 用户指定一条测试采集记录和目标店铺；带 `SPARO_DXM_SMT_PREVIEW=1` 重启开发版。
2. 侧栏说「认领这条到 PetLifeGlobal」→ 模型带 `claimConsent` 跑 prepare。
3. 期望：判重 `absent` → 认领弹窗选店 → 确认 → 读回三证 → 工作单落 `claimedDraftId` → 停在写字段/翻译入口，不再报「无法判重」或「认领入口没有已核对标记」。
4. 页面全程只在采集编辑页操作；没有新开标签做认领，没有刷新。
5. 认领后到采集箱确认草稿存在（只读）；再跑一次 prepare 同记录 → 判重应停在 `ambiguous`，不再二次认领。
6. 广告或弹窗挡住按钮时停等，不硬点。
