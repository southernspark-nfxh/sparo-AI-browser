# 媒体工作台 · 改版设计稿

> 输入：两路调研（现代数据控制台范式 / 中文新媒体矩阵工具工作台）。
> 现状：`src/renderer/studio.html`，350 行，纯文本卡片，`textContent` 拼接，内容榜 `JSON.stringify`。
> 本文只定设计与信息架构，不含实现。方向选定后再动代码。

---

## 0. 诊断：为什么现在难看

不是缺渐变、缺动效，是缺四样东西：

| 缺失 | 现状 | 后果 |
|---|---|---|
| 层级 | 标题、正文、元信息、状态全是一个字号一种颜色 | 扫不出重点 |
| 结构 | 数据是字符串拼的 `"阅读 338 点赞 6 收益 0.29 元 partial"` | 数字无法排版、无法对齐 |
| 诚实 | 缺失与 0 只在文字上不同 | 用户分不清"没有"和"是零" |
| 骨架 | 六个模块平铺，没有"先看什么" | 打开不知道从哪下手 |

**核心判断：** 竞品的工作台不是"表单集合"，而是**以账号资产为骨架、以发布队列为动脉、以数据异常为警报**的三层结构。我们现在三样都没有。

---

## 1. 信息架构：六个一级收成五个

现状六个：总览、稿件、分发、台账、数据、互动。

问题：「分发」和「台账」被拆成了两个一级，而「账号」缺失。发稿→预检→确认→看队列，是一条连续的流程，不该跨三个导航。

目标五个：

```
工作台   发稿   数据   评论   账号
```

| 一级 | 吸收了什么 | 说明 |
|---|---|---|
| 工作台 | 原「总览」 | 默认首页，四块：今日待办 / 账号异常 / 昨日数据 / 最新评论 |
| 发稿 | 原「稿件」「分发」「台账」 | 中间编辑 + 右侧四张平台卡 + 底部动作栏；台账变成"发布队列"抽屉 |
| 数据 | 原「数据」 | 一张表 + 平台列，不做四张并列卡 |
| 评论 | 原「互动」 | 三栏收件箱 |
| 账号 | 新增 | 四平台登录态、失效重登。竞品全部把它设为一级，因为登录态是所有功能的前提 |

不放一级的：
- **素材** → 发稿页右侧抽屉
- **设置** → 右上角
- **发布队列** → 右上角常驻入口，点开为右侧抽屉

> 竞品融媒宝有 9 个一级导航，那是功能逐年堆叠的结果，不是设计目标。抄它会直接变成"每个入口都像补丁"。

## 2. 布局骨架

```
┌ 顶栏 56px ─────────────────────────────────────────────────────┐
│ 媒体工作台   环境：默认 ▾      [发布队列 2]      ⟳    ⚙        │
├ 侧栏 232px ─┬ 内容区 max 1440 / padding 32 ────────────────────┤
│ 工作台      │ 页面头：标题 20px + 一句说明 + 主操作              │
│ 发稿        │ KPI 行：4 张（容器查询 4→2→1）                    │
│ 数据        │ 两栏：8 栏主图 · 4 栏待办/最新评论                 │
│ 评论        │ 内容榜：6 列表格，44px 行高                        │
│ 账号        │ 页脚：数据截至 + 刷新状态                          │
└─────────────┴──────────────────────────────────────────────────┘
```

数值：

| 项 | 值 |
|---|---|
| 侧栏宽 | 232px；窗口 <1100px 收成 64px 图标轨 |
| 内容最大宽 | 1440px，居中 |
| 页面左右留白 | 24px（<1280）/ 32px（≥1280） |
| 栅格 | 12 栏，gutter 24px |
| 顶栏高 | 56px |
| 间距基准 | 4px，阶：4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 圆角 | 控件 6px / 卡片 10px / 抽屉 14px |

**侧栏要比内容区暗一档**（Linear 2026 改版的做法）：默认注意力留给数据，不被导航抢。

**导航选中态**：accent 8% 透明底 + 圆角 6px + 文字从 muted 转 ink + 左侧 3px 实色竖条（用 `box-shadow: inset 3px 0`，不占布局）。必须带 `aria-current="page"`。

## 3. 页面线框

### 3.1 工作台（默认首页）

不做数据大屏。四块：

```
┌ 今日待办 ──────────┐ ┌ 账号异常 ──────────────────┐
│ 3 篇草稿未发       │ │ 大鱼号   登录失效   [重新登录] │
│ 2 条发布失败 [查看] │ │ 百家号   昨日数据未更新        │
└────────────────────┘ └────────────────────────────┘
┌ 昨日数据 ──────────┐ ┌ 最新评论 ──────────────────┐
│ 阅读 6,570  ↑12.4% │ │ 头条号   3 条未读  [去回复]   │
│ 净增粉丝 +72       │ │ 百家号   1 条未读             │
└────────────────────┘ └────────────────────────────┘
```

规则：
- 阅读合计标「相加，非去重」
- 涨跌百分比只在四平台全 `full` 时显示；任一 `partial` 只给绝对值
- 净增粉丝用有符号数（`+72` / `-5`）
- 待办数字可直接点进对应页

### 3.2 发稿（核心页）

```
┌─ 编辑区（8 栏）──────────────────┬─ 平台卡（4 栏）─────────────┐
│ 标题  [5–30 字]            24/30 │ ✅ 头条号   完整       [展开] │
│ 摘要  [0–120]             36/120 │ ⚠️ 百家号   缺封面     [展开] │
│ ┌──────────────────────────────┐ │ ✅ 大鱼号   完整       [展开] │
│ │                              │ │ ☐ 搜狐号   未选择            │
│ │        正文（Markdown）       │ │                              │
│ │                              │ │ ── 展开后只显示该平台差异 ── │
│ │                              │ │ 封面：○自动 ○单图 ○三图      │
│ └──────────────────────────────┘ │ 平台标题  0/64               │
│ 图片区  [拖入]  3 张·2 张不同     │ 分类 / 原创 / 赞赏            │
│ 首发平台 ▾                        │ 红字：缺封面会导致发布失败    │
├──────────────────────────────────┴──────────────────────────────┤
│ [保存]  [预览]  [预检]                              [发布 →]     │
└─────────────────────────────────────────────────────────────────┘
```

三条关键决策：

1. **平台勾选放右侧，不放顶部 Tab。** 让"选平台"和"改该平台参数"在同一视觉区域，不用来回跳。
2. **右侧四张可折叠卡，卡片头直接显示完整度/缺什么。** 比竞品"点进去才知道缺封面"前进一步。当前只展开一个，不是四张全摊开。
3. **共性留在中间，差异放平台卡。** 标题、正文、封面主图是共性；平台标题、分类、摘要、原创、赞赏是差异。避免四个平台重复填四遍。

### 3.3 发布体检单（竞品的空档，我们的强项）

点「发布」不直接发，先出这一屏。这是产品跟"无人值守工具"的分界线，也是我们现在确认单的升级版。

```
┌ 发布前检查 ─────────────────────────────────────────┐
│ ✅ 头条号   标题 24/30  封面已选  广告已勾           │
│ ⚠️ 百家号   缺封面（必填）                 [去设置]  │
│ ✅ 大鱼号   正文 3 张不同图  三图封面                │
│ ⚠️ 搜狐号   创作声明未确认                [去设置]   │
│ ─────────────────────────────────────────────────── │
│ 2 个平台可发，2 个平台各缺 1 项                      │
│              [返回修改]   [仍然发布这 2 个平台]      │
└─────────────────────────────────────────────────────┘
```

规则：
- 逐平台列出：字数、封面、必勾项、必不勾项、人工补项
- 越界**只标红，不自动缩短**
- `⚠️` 行默认跳过，其余默认勾选
- **不出现定时、不出现时间**（P1 不做定时与一键错峰）
- 人点确认后，进入发布队列，不是弹个 toast 就结束

### 3.4 发布队列（常驻右上）

竞品把失败暴露在发布之后，只有一个成功 toast。我们要常驻：

```
┌ 发布队列 ────────────────────┐
│ 头条号  ✅ 已发布  12:04      │
│ 百家号  ⟳ 发布中              │
│ 大鱼号  ⏸ 排队中              │
│ 搜狐号  ❌ 失败  COVER_NOT_PICKED │
│         [重试]  [查看详情]     │
└──────────────────────────────┘
```

失败必须带 `errorCode` + 人话说明，不能只给红点。

### 3.5 数据

**一张表 + 平台列，不做四张并列卡。** 四个平台字段不一致（阅读 / 播放 / 推荐 / 收益），卡片会导致高度不齐、无法排序。

```
┌ 数据 ────────────────────────────────────────────────────────┐
│ [全部平台 ▾]  [近 7 天 ▾]              [立即刷新]  [导出]     │
│ ⚠ 昨日数据每日 14:00 前更新               [一键重登]          │
│ ┌总阅读 6,570┐ ┌净增粉丝 +72┐ ┌本月收益 ¥3.69┐ ┌异常 2┐     │
│ └────────────┘ └────────────┘ └──────────────┘ └──────┘     │
│ ┌────────┬──────┬────────┬──────┬────────┬────────┬────────┐ │
│ │平台    │日期  │阅读    │点赞  │收益    │更新    │状态    │ │
│ ├────────┼──────┼────────┼──────┼────────┼────────┼────────┤ │
│ │头条    │11-11 │338     │6     │¥0.29   │14:02   │部分    │ │
│ │百家    │11-11 │2,284   │19    │¥3.40   │13:58   │部分    │ │
│ │大鱼    │  —   │—       │—     │—       │  —     │未实测  │ │
│ │搜狐    │  —   │—       │—     │—       │  —     │未实测  │ │
│ └────────┴──────┴────────┴──────┴────────┴────────┴────────┘ │
└──────────────────────────────────────────────────────────────┘
```

六块视图（P2）：总览卡、趋势、内容榜、平台对比、收益拆分、异常。
总览卡只放**阅读、净增粉丝、收益、异常**，不含待回评论。

### 3.6 评论

三栏收件箱：

```
┌ 账号（含未读）─┬ 评论列表 ──────────────┬ 回复区 ────────────┐
│ 头条  3 未读   │ 张三  这篇写得真好      │ 选择左侧评论        │
│ 百家  1 未读   │ 11-11 14:02 · 《标题A》 │                    │
│ 大鱼  只读     │ ─────────────────────── │ 回复内容            │
│ 搜狐  只读     │ 李四  学到了            │ ┌────────────────┐ │
│                │ 11-11 12:30 · 《标题B》 │ │                │ │
│                │                         │ └────────────────┘ │
│                │                         │ [填入平台回复框]    │
└────────────────┴─────────────────────────┴────────────────────┘
```

规则：
- 左栏带未读红点；中栏支持"按时间 / 按内容"两种排序
- 右栏按钮是**「填入平台回复框」**，不是「发送」。工作台没有发送按钮，也没有「我已发送」
- 大鱼、搜狐：左栏标「只读」，选中后右栏显示「只读，回复未开」
- 空状态给明确下一步（"请选择左侧评论"），不要只留白
- 是否回复只认下一次 GET 能看到该回复

## 4. 设计 token

### 4.1 中性色（浅色 / 暖灰）

| Token | Hex | 用途 |
|---|---|---|
| `--gray-0` | `#FFFFFF` | 卡片面 |
| `--gray-50` | `#FAF9F6` | 页面底 |
| `--gray-100` | `#F3F1EC` | 侧栏 / 表头 |
| `--gray-200` | `#E5E1D8` | 分隔线 |
| `--gray-300` | `#D2CDC2` | 强边框 |
| `--gray-400` | `#A8A29A` | 禁用文字 |
| `--gray-500` | `#7A756C` | 三级文字 |
| `--gray-600` | `#5C5850` | 二级文字 |
| `--gray-800` | `#24231F` | 标题 |
| `--gray-900` | `#1C1B18` | 主文字 |

### 4.2 中性色（深色，表面阶梯）

| Token | Hex |
|---|---|
| `--bg` | `#0A0B0D` |
| `--surface-1` | `#111317` |
| `--surface-2` | `#171A1F` |
| `--surface-3` | `#1D2127` |
| `--line` | `#252A31` |
| `--text` | `#E8EAED` |
| `--muted` | `#9AA1AB` |
| `--subtle` | `#6E7681` |

深色**不用阴影，用 1px 发丝线 + 顶部 1px 高光**。

### 4.3 语义色

| 语义 | 浅色 | 深色 |
|---|---|---|
| success | `#15803D` | `#3FB950` |
| danger | `#B42318` | `#F85149` |
| warning | `#B54708` | `#D29922` |
| info | `#1D4ED8` | `#6E79F0` |

只用三种状态色，不要给平台各配一种彩色。平台区分靠小 logo 或文字，不靠色块。

### 4.4 字号阶

| 用途 | 字号 / 行高 | 字重 | 字距 |
|---|---|---|---|
| 页面标题 | 20 / 28 | 600 | -0.01em |
| KPI 主值 | 32 / 36 | 600 | -0.01em |
| 区块标题 | 15 / 22 | 600 | 0 |
| 正文 / 表格 | 14 / 22 | 400 | 0 |
| 标签 | 12 / 16 | 500 | 0.01em |
| 来源脚注 | 11 / 16 | 400 | 0 |

数字一律 `font-variant-numeric: tabular-nums`，否则 999→1,000 时卡片会抖。

### 4.5 技术手段

Electron 35 = Chromium 134，以下全部原生可用，**不引入任何框架**：

```css
@layer reset, tokens, base, layout, components, utilities;
```

- 双主题：`--bg: light-dark(#FAF9F6, #0A0B0D)` + `color-scheme: light dark`
- hover / 选中：`color-mix(in oklab, var(--accent) 8%, transparent)`
- KPI 栅格用**容器查询**，不用媒体查询（Electron 窗口宽 ≠ 屏幕宽）
- 状态用 data 属性收口：`[data-state="missing"]`、`[data-platform="toutiao"]`，JS 只改属性

## 5. 组件规范

### 5.1 KPI 卡（六层）

```html
<article class="kpi" data-state="partial" data-platform="toutiao">
  <p class="kpi__label">昨日阅读 <span class="chip">头条号</span></p>
  <p class="kpi__value"><span class="num">338</span></p>
  <p class="kpi__delta is-up">↑ 12.4% <span class="cmp">较前日</span></p>
  <p class="kpi__foot">来源：头条号后台 · 截至 11-11 14:02</p>
</article>
```

硬规则：
- **一个数字没有对比就是废话**，`+12%` 必须写明对比窗口
- **箭头管涨跌，颜色管好坏**，两者解耦
- **品牌色不染数字**，数字只有 ink 和语义两套色
- 一张卡最多 3 个可见数值，一行最多 4–6 张

### 5.2 状态词表（统一一套，不许混用）

| 状态 | 界面文字 | 视觉 | 操作 | 含义 |
|---|---|---|---|---|
| `ok` | — | 正常 | — | 数据完整 |
| `partial` | 部分数据 | 橙色小圆点 | — | 有字段未对齐 |
| `stale` | 未更新 | 灰色 | [刷新] | 是旧数据，等一等会好 |
| `missing` | 未获取 | 灰色 | [重试] | 抓取失败，点一下能修 |
| `unsupported` | 平台未提供 | 浅灰 + tooltip | 无 | 永远没有，不要给按钮 |
| `login_missing` | 登录态缺失 | 红色 | [重新登录] | 需要人介入 |
| `error` | 请求失败 | 红色 | [重试] | 接口报错 |

**这三条必须分开**：`stale`（等）、`missing`（修）、`unsupported`（没有）。竞品普遍把它们混成"未获取"，用户不知道该等还是该修。

### 5.3 缺失 vs 0

| | 真实 0 | 缺失 |
|---|---|---|
| 字符 | `0` | `—`（em dash） |
| 字号 | 与正常一致 | 降一档 |
| 颜色 | ink | `--text-subtle` |
| 辅助 | 无 | 11px「平台未提供」 |
| 可访问 | 读作 0 | `aria-label="平台未提供"` + `title` |

数据层给每个指标带 `availability: ok | missing | stale | error`，渲染层只认这个字段，**从根上断掉 `undefined → 0` 的兜底**。图表里缺失点用断线，不落到 0 轴。

### 5.4 表格

| 项 | 值 |
|---|---|
| 表头高 | 44px，sticky |
| 行高 | 44px |
| 单元格 padding | 16px |
| 数字列 | 右对齐 + tabular-nums |
| 文本列 | 左对齐 |
| 分隔 | hairline 行线 + hover 4% 底色；**不要同时上斑马纹** |
| 列数 | 默认 6–7 列，其余进「自定义列」 |

内容榜必须是真表格：`标题 | 平台 | 阅读 | 互动 | 发布 | 状态`。现在那行 `JSON.stringify` 是调试输出，必须删。

### 5.5 五种页面状态

| 状态 | 视觉 | 文案 |
|---|---|---|
| 加载 | 与最终布局同尺寸骨架块，**不要整块 spinner** | 无 |
| 空（新用户） | 图标 + 一行说明 + 一个主操作 | "还没有数据，先登录头条号" |
| 真实 0 | 正常渲染 `0`，平静 | — |
| 缺失 | `—` + 灰字说明 | "平台未提供" |
| 错误 | 保留旧值 + 红色小图标 + 重试 | "未获取到新数据，仍显示 10:30 的结果" |

**刷新失败绝不把数值替换成 0，保留旧值并写清"截至几点"。**

## 6. 视觉方向（三选一）

三套共用布局与组件，只换 token。

### A｜编辑部白纸（克制编辑风）

暖白纸 `#FAF9F6`，卡片纯白，藏青强调 `#1F3A5F`。标题用衬线（Source Han Serif SC），正文 Inter + 思源黑体。卡片 padding 24px，KPI 主值 40px，行高 52px。

适合：内容主编、以单平台为主、要截图或打印汇报、每天看两三次。

### B｜夜间控制台（深色专业风）

画布 `#0A0B0D`，卡片 `#111317`，强调 `#6E79F0`。全无衬线，1px 发丝线不用阴影。卡片 padding 20px，KPI 主值 32px，行高 44px。

适合：多账号运营、晚上值班、一屏看四平台、每天用一小时以上。

### C｜仪表盘（高密度数据风）

冷白 `#F6F8FB`，强调 `#2563EB`。基础字号 13px，KPI 26–28px，行高 40px，6 列 KPI。

适合：代运营团队、习惯表格而不是卡片的人。

> **建议**：B 做主形态，A 做浅色模式（共用一套 token，成本很低）；C 只作为「数据」页的第二档密度，不做全站默认——13px 中文长时间读会累。
