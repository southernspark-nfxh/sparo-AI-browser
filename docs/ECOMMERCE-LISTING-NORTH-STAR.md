## 0. 北极星

**一个商品，从一个未编辑的页面开始，到用户只需要点头。**

量化成一个数：**人工填写次数 = 0**。

除「审核」外，用户不该在页面上动手。用户还要去改别的地方，就是我们没做完，不是用户没耐心。

## 1. 成功的三层定义

一条 listing 算「合格完成」，三层全过，缺一层都不算：

| 层 | 判据 | 反面 |
|---|---|---|
| L1 平台不拦 | 红星字段无缺失、无「请选择」残留、无中文报错 | 点保存弹红框 |
| L2 数据是对的 | 价格算得出、重量换算对、库存不爆顶、两行 SKU 一致 | 数字填了但填错 |
| L3 人只审三样 | 图 OK、译文 OK、价合理 | 用户还要去改分类/属性/模板 |

## 2. 素材的用法（重要）

历史 skill 是**数据源**，不是路线图。

- 只取：图片几张多大、价格公式、库存上限、标题规则、字段结构、控件坑位。
- 不取：它们的执行路径、它们的「这条路走不通」结论、它们的失败流程。
- 素材之间存在矛盾时，**以本机实测为准**，并把矛盾登记进 §4。

## 3. 合格清单

列含义：**判据** = 怎么算过；**证据** = 从页面哪里读到；**归属** = 改不动时算谁的。

### 3.0 数据基线（对照物，先于一切）

审核的前提是"有东西可比"。所以**采集阶段必须落一份基线并随任务走**，缺基线不许开始编辑：

```json
{
  "sourceUrl": "1688 offer 地址",
  "cost": 12.5,
  "costCurrency": "CNY",
  "weightRaw": "50",
  "weightUnitRaw": "g",
  "sizeRaw": { "length": 12, "width": 8, "height": 5, "unit": "cm" },
  "titleRaw": "原始中文标题",
  "imageCount": 23,
  "stockRaw": 9999
}
```

硬规则：

- `weightUnitRaw` **必须照抄页面上的单位**，不许推断。出现 g / kg 之外的单位，停手问人。
- `sizeRaw` 原样记录，不换算、不四舍五入。
- 基线缺失或不完整 → **不许进入编辑**，因为没有东西可以对照。

**对照物一共三份，缺一份复检就是在自证自明：**

| # | 名字 | 何时产生 | 存什么 | 用来干什么 |
|---|---|---|---|---|
| 1 | **采集基线** `baseline.json` | 采集 1688 原页时 | 成本、`weightRaw`+`weightUnitRaw`、`sizeRaw`、原标题、图片数、库存 | 保存前大脑审的唯一原始依据 |
| 2 | **改前快照** `prefill.json` | 打开编辑页、动任何字段之前 | 9 区全量现有值（含采集带过来的价格初值） | 判断哪些是采集带来的、哪些是空的；**反推价格公式** |
| 3 | **目标值** `target.json` | 算完之后、写入之前 | 本次要写的每个字段的期望值（价格、重量、库存、包装尺寸…） | 保存后复检比对「实际写入」 |

三份都落盘到任务的 ledger 目录，跟这条商品绑定。删掉任何一份，这条商品立刻降级为「不许自动保存」。

#### 3.0.1 采集箱阶段实测事实（2026-11-12，draft id `220114600887277934`）

| 事实 | 证据 | 对流程的影响 |
|---|---|---|
| 草稿 `currencyCode = CNY` | 列表接口 `POST /api/smtProduct/pageList.json` 返回 | 价格币种确定，人民币 |
| 草稿价格是**汇率换算后的货源价**，不是定价公式结果 | 同一条草稿 `productPrice = 0.87`，代入公式应 ≈ 14.8 | **定价必须由我们算**，不能沿用采集值 |
| 草稿标题是**中文**，一个字都没翻 | 标题 30 字符，`/[\u4e00-\u9fa5]/` 命中 30 | 翻译是必经步骤，不是可选项 |
| 草稿可以没有变种行 | `tr[class*=skuDataItem_]` 取到 0 行，图 27 张 | 建变种要单独一步，不能假设已存在 |
| 非激活标签读不到 DOM | 同一页：非激活 `len=0`／骨架 `len=2138`；`switch_tab` 后 `len=6257`、379 个已填输入 | **读页前必须先 `switch_tab` 激活** |
| 同一标签内换 `id` 会被弹回旧 id | `navigate` 请求 `...542`，`confirmed` 后 url 仍是 `...920` | 换商品必须**新开标签**，不能复用当前标签改 id |
| 1688 源头页当前读不到正文 | `detail.1688.com` 打开后 `len≈2152`，无价格区间 | 基线可能得从采集箱记录里取，或要求登录后再采 |

## 5. 必须由人完成的动作

- **「保存并移入待发布」**：技能只点「保存」，不点带认领/移入性质的按钮。
- **认领到店小秘**：属于第三目标，本期不做。
- **图片翻译结果抽检**：翻译是提交给平台的异步任务，提交成功 ≠ 译好。技能负责提交并报「已提交 N 张」，人工看结果。
- 任何一次保存若回执非 0，停手交人，不重试第三次。

## 6. 分期

### P0 · 一页编辑到底（质变，当前唯一目标）

从采集来的一个商品页，编辑到 §3 全绿 → 保存 → 用户只审核。

拆成可独立验收的五步：

1. **落基线**：采集来源页，按 §3.0 存 `baseline.json`。**缺基线不许开工**
2. **改前快照**：动任何字段之前，把编辑页现有 9 区数据完整读出来落 `prefill.json`（尤其价格字段初值，用来反推公式口径）
3. **算 + 落目标值 + 填**：按基线算，先写 `target.json`，再逐区写入并当场回读，不一致立刻停
4. **大脑审（保存前，不可省）**：按 §6.1 出 `audit.json` → 模型 `verdict`，非 `pass` 不许进第 5 步
5. **保存 + 复检**：`code:0` 后才刷新，按 §3 全量复检并对比 `target.json` / `baseline.json`，输出「过了 N 项 / 差哪几项」

### 6.1 两道审核的分工

两道都要，不许合并，也不许用同一套判据。

| | 保存前 · 大脑审 | 保存后 · 脚本复检 |
|---|---|---|
| 谁做 | 模型（意识） | 脚本（潜意识） |
| 性质 | 判断 | 事实 |
| 对照物 | `baseline.json` + `prefill.json` + `target.json` | `target.json` + `baseline.json` |
| 审什么 | 价格是否按公式且量级合理；重量单位有没有反；标题译文是否通顺且无中文残留；主图是否 6 张且首图白底；**图片翻译是否真已完成（异步任务状态，不是"已提交"）**；规格与基线是否一致；属性是否与分类匹配 | 页面写入值 == `target.json`；关键项再与 `baseline.json` 比一次；两行 SKU 一致 |
| 输出 | 逐条「过 / 疑点 + 理由」，有疑点**不保存** | 结构化 diff，不一致即失败 |

**硬闸门（这是流程能不能算数的关键）：**

脚本在保存前必须把三份对照物打包成一份 `audit.json` 交给模型：

```json
{
  "baseline": { "cost": 12.5, "weightRaw": "50", "weightUnitRaw": "g", "sizeRaw": {…}, "titleRaw": "…" },
  "computed": { "price": 43.21, "currency": "?", "weightKg": 0.05, "stock": 2000 },
  "prefill":  { "priceField": "…", "weightField": "…", "stockField": "…" },
  "visible":  { "title": "…", "mainImageCount": 6, "translationStatus": "done|pending|unknown", "skuRows": 2 }
}
```

模型必须回一个 `verdict: pass | block` + `reasons[]`。**保存动作只在 `verdict == pass` 时执行**；`block` 或缺失 verdict，脚本直接拒绝保存——不是"建议"，是结构上过不去。

为什么必须分两道：脚本判不了"这个英文标题能不能卖"，模型也不该被用来逐字比 23 个数字——前者是判断，后者是重复劳动。

为什么不能只留一道：只脚本 = 数字全对但页面在卖一个荒唐的价；只模型 = 模型说"看着没问题"而实际写歪了一位。

### P1 · 批量（量变）

采集箱 10 / 50 条：一条命令排队跑，断点续跑，账本记录每条成败。
前置：P0 单页必须稳定，否则批量只会放大错误。

## 7. 验收

- **V1**：P0 跑完，页面 §3 全绿，用户不点任何填写类控件即可保存/移入待发布。
- **V2**：用户只审「图、译文、价」三样，且每样都能一句话说清在哪看。
- **V3**：任一环节失败，输出人话理由 + 具体差项，不出现「失败」「错误」这类无信息量的词。
- **V4**：保存前大脑审真的拦得住——故意把成本填错一个量级，它必须拒绝保存并说出是哪一项。
- **V5**：保存后刷新复检，与基线逐项相等（不是只跟"我以为写的"相等）。
