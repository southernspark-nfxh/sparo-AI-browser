## 3. 统一行为约定

### 3.1 `--env` 的语义

推荐命令形态：

```powershell
node publish.mjs --platform baijiahao --article <目录> --env ad0fe9db --dry-run
node video.mjs --platform baijiahao --video <mp4> --title "<标题>" --env ad0fe9db --dry-run
```

规则：

1. `--env` 后必须跟非空值；缺值是参数错误，不能静默当成未传。
2. 对外文档以 canonical `envId` 为标准输入。
3. 名称解析可以复用同一名册解析函数：输入为 id 时按 id 精确匹配；输入为环境名时按归一后的全名精确匹配，最终向下游只传 canonical `envId`。
4. 未传 `--env` 且用户没有点名账号：保留原有默认登录态行为，不擅自挑选环境。
5. 用户明确点名账号时：外部 Agent 必须先查名册再组命令；解析失败就停止，不能省略 `--env` 再跑一次。
6. 脚本收到非法、失效或不存在的 `--env` 时也必须自己失败关闭，不能只依赖上游 Agent 自觉。

### 3.2 名称归一只做明确等价，不做模糊猜测

至少覆盖：

- `百家号二` = `百家号2`
- `百家号三` = `百家号3`
- 去除首尾空白后比较；
- 阿拉伯数字与对应汉字数字归一后再做全名相等比较。

不得做：

- 编辑距离、包含匹配或「最接近名称」推荐式自动选择；
- 因只找到一个百家号环境，就把用户说的另一个名字强行映射过去；
- 解析失败后新建环境；
- 「另一个 / 第二个 / 还是用那个」等指代不清时自行猜账号。无法唯一确定就列出候选并询问。

建议统一错误码：

| 场景 | 错误码 | 必须附带的诊断 |
|---|---|---|
| 名册中没有目标 | `ENV_NOT_FOUND` | 用户输入、当前可用环境 id/name |
| 归一后命中多个 | `ENV_AMBIGUOUS` | 全部候选 id/name |
| 标签环境与目标不一致 | `ENV_MISMATCH` | expectedEnvId、actualEnvId、tabId |
| 页面账号名无法读取 | `ACCOUNT_NAME_UNAVAILABLE` | envId、tabId、页面 URL |
| 发布前账号名发生变化 | `ACCOUNT_MISMATCH` | expectedAccountName、actualAccountName |
| 续跑找不到同环境编辑页 | `NO_EDITOR_TAB` 或现有续跑错误码 | 目标环境、已检查标签及排除原因 |

这些错误都必须在任何提交动作之前返回结构化失败结果。

### 3.3 页面账号名校验的正确含义

本地环境名与站点账号名不是同一字段，**不要**拿 `envName === accountName` 做判断。

本轮采用两层证据：

1. **环境身份**：以 `list_tabs` / 标签元数据里的 `envId` 为准，核对当前编辑标签确属目标环境；URL 和页面昵称不能替代环境校验。
2. **站点身份**：适配器读取页面可见账号名。打开目标编辑页后记录 `expectedAccountName`，真正提交前重新读取 `actualAccountName`，要求二者非空且完全一致。

这样可以同时拦截：

- 开了默认或其他环境的标签；
- 续跑拿到了同 owner、不同环境的草稿；
- 任务执行中标签被换到别的账号；
- 页面尚未加载出账号身份就误提交。

本轮不新增「环境名 ↔ 平台昵称」持久绑定表。验收时另外核对已知事实：`百家号2 / ad0fe9db` 页面应显示「图一乐研究所」。

### 3.4 提交前硬门的覆盖范围

- 显式传 `--env` 的真实发布、定时发布：硬门必须通过，缺失任一证据就停止。
- `--dry-run`：也要执行环境解析、开页 / 复用、环境与账号名硬门，只跳过最终提交及提交后验证，便于无发布验收。
- 未传 `--env` 的旧默认账号流程：保持兼容，不要求环境名与页面昵称相等；不得因为本轮改动被自动绑到某个非默认环境。
- 百家号图文和百家号视频必须实现页面账号名读取。其他平台若走显式环境真实提交但适配器无法读取账号名，按 `ACCOUNT_NAME_UNAVAILABLE` 失败关闭，不得假装已校验。

### P0-B 在 MCP 封装层补齐环境与名册能力

**主要位置：`scripts/sparo.mjs`，必要时配合现有标签工具函数。**

1. 增加 `list_envs` 调用封装，保留服务端返回的 `id`、`name`。
2. 增加唯一的名称归一 / 解析入口，输出：
   ```js
   { ok: true, envId, envName }
   ```
   或带上述错误码的结构化失败。
3. `tabs()` / `tabRows()` 不得丢掉标签的环境字段；所有调用点使用同一字段名。
4. 调整 `nav()` 参数，使显式环境任务的两个分支都把 `envId` 传给 `navigate`：
   - 不带 `tabId` 的新开 / 复用分支；
   - 带 `tabId` 的导航分支。
5. 建议用 options 对象传递环境，避免继续增加含混的位置参数；所有旧调用点必须同步检查。
6. 未指定环境时维持默认行为；指定环境后不允许中途变成空值。

### P0-C 图文入口与上下文接入 `--env`

**位置：`scripts/publish.mjs`、`scripts/engine.mjs`。**

1. `parseArgs()` 增加 `--env`，更新 `USAGE`、缺值错误和自检。
2. 在打开、认领或复用任何标签之前完成名册解析。
3. `runPublish()` 的 `ctx` 至少携带：
   ```js
   {
     envId: "",       // 未指定环境时才为空

     expectedAccountName: "",
   }
   ```
4. 后续日志、失败报告和成功报告都带 `envId`、`envName`；读到页面账号名后带 `accountName`。
5. 台账增加相同字段，确保事后能回答「这篇到底用哪个环境、哪个站点账号执行」。旧台账读取保持兼容，不要求迁移历史记录。

### P0-D 图文开页、复用和 `--from` 续跑全部按环境过滤

**位置：`scripts/page.mjs`、`scripts/engine.mjs`。**

1. `openWriteTab()` 新建编辑页时调用：
   ```js
   navigate({ url: ctx.writeUrl, envId: ctx.envId })
   ```
   显式环境任务不得退化成只传 URL。
2. 所有可复用编辑页候选必须同时满足：
   - 平台 host / writeMark 匹配；
   - `editExisting` 排除规则通过；
   - owner 属于本技能；
   - **显式环境任务中 `tab.envId === ctx.envId`**。
3. 默认账号任务只复用默认登录态标签，不得因某环境标签 URL 相同就拿过来。
4. `navigate` 前后的快照、`created`、URL 变化及活动标签判断，都要保留环境字段并做同一过滤。
5. `--from` 续跑在 `runPublish()` 里找编辑页时使用完全相同的条件；不能只在首次 `openWriteTab()` 修环境。
6. 发现「同 owner、同平台、不同 env」的候选时，不接管、不导航、不填稿；诊断中列出被排除的 tabId/envId。
7. 找不到正确编辑页时失败关闭，不得去掉 `envId` 重新调用一次。

### P0-E 视频独立链路接入同一个环境

**位置：安装版合并后的 `scripts/video.mjs` 及其直接调用的公共模块。**

4. 视频自己的编辑页复用、已有任务恢复或续跑逻辑，全部增加 `owner + envId` 过滤。
5. 视频若调用公共 `nav()`，也必须走 P0-B 的新接口，不能存在另一条无环境导航分支。
6. 封面生成、上传、填标题等现有行为不变；不要为了本任务重构视频流程。
7. 视频结果和失败诊断同样输出 `envId`、`envName`、`accountName`。

### P0-F 在最终提交前设置统一硬门

**位置：图文引擎公共步骤、视频最终提交入口、百家号适配器。**

   - 重新读取 `actualAccountName`；
   - 与 `expectedAccountName` 做全等比较。

   - 立即发布；

7. 校验失败不点发布、不点定时、不保存为新草稿，不尝试默认账号兜底。
8. 保持 R3 已有约束：不用 `window.focus()` / `restore()`，不抢前台，不破坏原活动标签恢复。

## 8. 最容易改错的地方

1. **只改图文，不改视频。** 视频有自己的 `openOwnEditor()`，不会自动继承图文修复。
2. **只改首次开页，不改续跑。** `--from` 会直接找旧编辑页，仍可能拿到别号草稿。
3. **只校验 owner，不校验 env。** 同一技能在不同进程中 owner 可以相同，仍可能跨账号。
4. **解析失败后省略 `--env` 重试。** 这正是回退默认账号的隐蔽入口，必须禁止。
5. **拿 `百家号2` 和「图一乐研究所」直接比较。** 一个是本地标签，一个是站点昵称，不能直接相等。
6. **只在任务开始时读一次账号名。** 最终提交前必须重新读环境和账号名。
7. **dry-run 直接跳过整个提交步骤，连同硬门一起跳过。** 应先验收硬门，再只跳过点击和提交后验证。
8. **把安装版视频能力覆盖没。** 两边是双向分叉，不是单向旧副本。
9. **为了测试点一次真实发布。** 本轮 DoD 不需要真实提交，且明确禁止。
