3. **A–H 缺口闭合表**：每个原任务书检查项对应结论和证据；不允许空项。
4. **原问题复核表**：保留 / 修订 / 升级 / 降级 / 撤销 / 未验证，并写理由。
5. **新增问题清单**：仅列补审新发现且证据足够的问题；无则写“无新增”。
6. **真实会话证据**：R1–R4，R5 如未执行须写未验证。
7. **S-01 独立安全结论**：通过 / 阻断 / 未验证及依据。
8. **恢复能力矩阵**：按 M5 原表填写，不作超范围概括。
9. **原报告勘误表**：包括交叉引用、过宽表述和最终分级变化。
10. **最终问题统计与剩余未验证项**：数量必须与清单一致。

## 九、停止与阻断规则

出现以下情况立即停止相关测试并记录，不得强行完成：

1. 无法证明当前实例是 0.7.7。
2. 测试可能读写用户生产数据，或需要关闭用户现有 Sparo。
3. 即将发生保存、认领、发布、付费、删除、登录或验证码操作。
4. 店小秘仍为 0×0 视口，无法隔离环境故障。
5. 需要修改代码、技能或配置才能继续。
6. 需要运行 `npm run pack`、`npm run dist` 或生成/覆盖可分发安装包才能继续。
7. 证据只能来自推测，或历史任务无法回查却准备写成确定事实。

停止后仍应交付补审报告，但状态写“阻断”，列出解除阻断所需的环境或授权，不编造通过结果。
