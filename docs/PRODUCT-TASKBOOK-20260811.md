# Sparo 能力扩展 · 产品任务书

> 版本：v0.1 · 2026-08-11  
> 状态：**待确认后开工**  
> 范围：AI 客服助手、网页情报分析、图片下载、自动填表基建（含 Hermes 调度）

---

## 1. 一句话定位

Sparo 继续做「人机同窗的手」：把客服会话、采购/竞品情报、基础浏览器能力、通用填表，变成 **MCP 可调用的稳定原语**；大脑仍可由侧栏模型 / Hermes / OpenClaw 驱动。

原则不变：

- **默认同窗可见** — 人能随时 Pause / 接管  
- **高风险动作要闸门** — 自动回复、下单、发帖默认需确认；「全自动」是可选模式  
- **站点特化 + 通用分析并存** — 高频场景做 skill/原语；未知页走 `analyze_page` → `execute_primitives`

---

## 2. 需求总览与优先级

| # | 需求 | 价值 | 难度 | 建议优先级 | 类型 |
|---|------|------|------|------------|------|
| A | 右键下载图片 / 另存为 | 基础体验，天天用 | 低 | **P0** | 浏览器基建 |
| B | 自动填表基建被 Hermes 真正用上 | 已有能力变「可用」 | 中 | **P0** | Agent 编排 + 文档/Skill |
| C | AI 客服：动机分析 + 建议回复 → 半自动 → 全自动 | 商家刚需，差异化 | 高 | **P1**（先半自动） | 新模块 |
| D | 网页情报：1688 搜品 / 竞品锁定与摘要 | 电商场景深 | 高 | **P1～P2**（先通读+抽取） | 新模块 + 站点 skill |

推荐落地顺序：**A → B → C（半自动）→ D（MVP）→ C/D 加深**。

## 3. 需求 A · 图片下载（基础能力补齐）

### 3.1 现状

页面内右键无「图片另存为 / 复制图片地址」等常规菜单；Electron 默认上下文菜单未接好。

### 3.2 目标

在页面 WebContents 上提供与 Chrome 接近的图片相关菜单：

- 图片另存为…（选路径保存）
- 复制图片 / 复制图片地址
- （可选）在新标签打开图片  
- （可选）用当前下载目录一键保存

非图片区域：至少保留「复制 / 粘贴 / 全选 / 检查元素(dev)」基础项，避免整页右键空白。

### 3.3 实现要点

- `webContents.on('context-menu', …)` 根据 `params.mediaType === 'image'` / `params.srcURL` 组装 `Menu`
- 另存为走 `dialog.showSaveDialog` + `session.downloadURL` 或 `net.fetch` 写文件  
- CSP / blob: / 跨域：blob 与 data URL 用 fetch+write；失败时提示「请复制链接」
- 验收：百度图 / 小红书封面 / 1688 主图 三类源至少 2 类可另存成功

### 3.4 工时粗估

0.5～1.5 人日。

## 4. 需求 B · 自动填表基建「真正被调动」

### 4.1 现状（已有）

| 能力 | 说明 |
|------|------|
| `analyze_page` | 字段/按钮分类、必填检测、打 `data-spark-ref` |
| `execute_primitives` | payload 模糊匹配 → fill/click/upload + mini-QA + strategy-cache |
| 文档 | `docs/UNIVERSAL-ANALYZER.md`、`AGENTS.md` 有一句指引 |

### 4.2 问题判断（为何 Hermes「没调动」）

多半不是工具坏了，而是 **编排层不知道何时用**：

1. MCP tool 描述偏短，Hermes 更爱 `fill`/`click` 穷举  
2. 没有「通用填表」Skill 作为默认路径（小红书有 `xhs_*`，未知站没有）  
3. Agent 系统提示 / Sparo `sparo_info` 未强制推荐 analyzer 闭环  
4. 缺少端到端验收脚本给 Hermes 当样例（「给 payload → 一键填」）

### 4.3 目标

Hermes（或任意 MCP Agent）在「未知表单 / 多字段页」上默认走：

```text
analyze_page →（可选）把 required_fields 给用户确认 → execute_primitives({ payload })
```

而不是盲目 `snapshot` + 多次 `fill`。

### 4.4 解题框架（先题型，再解题）— 产品化表述

把「填表」拆成可识别题型，再选策略：

| 题型 | 特征 | 策略 |
|------|------|------|
| T1 单页短表 | 少数字段、无弹层 | analyze → execute_primitives |
| T2 多步向导 | 下一步/分页 | 分步 analyze；每步 payload 子集 |
| T3 富文本/编辑器 | contenteditable / TipTap | 站点 inject 优先；否则 soft-fill |
| T4 上传+表单 | file input | upload 原语 + 其余字段 |
| T5 门户/iframe | 跨域框 | CDP frame refs（`xN.e*`）+ wait_for |
| T6 强站点特化 | 小红书长文等 | 禁止通用循环，走 `xhs_*` / skill |

交付物：

1. **Skill**：`universal-form-fill`（参数：`payload`，内部调 analyzer）  
2. **强化 MCP 描述** + `sparo_info` / `AGENTS.md` 决策树  
3. **题型探针**（可先做轻量）：`analyze_page` 返回里增加 `form_pattern` 建议字段  
4. **验收脚本**：`scripts/accept-analyzer.mjs`（百度搜索框或本地 fixture）  
5. **Hermes 侧**：一份「填表 Playbook」短文，说明必须先 `match_skill` / `analyze_page`

### 4.5 验收

- 未知站：只说「按这个 JSON 填」→ Hermes 调用 `execute_primitives`（或 skill）且成功率 ≥ 手动逐步 fill  
- 小红书长文：仍优先 `xhs_*`，不退化成通用循环  
- strategy-cache 命中第二次同页更快

### 4.6 工时粗估

2～4 人日（含文档与 Hermes playbook，不含大改分析器算法）。

## 5. 需求 C · AI 客服（动机分析 + 自动回复）

### 5.1 场景

商家用 Sparo 开着 IM / 旺旺 / 企业微信网页版 / 店铺后台客服页；客户询价、要资料、砍价、售后时：

1. **感知**新消息  
2. **动机分析**（询价 / 比价 / 要优惠 / 售后投诉 / 无效咨询…）  
3. **生成回复**（可带商品链接、价格口径、话术库）  
4. **发送**：默认「人确认后发」；可选「托管全自动」

### 5.2 产品分层（强烈建议分阶段）

| 阶段 | 名称 | 行为 | 风险 |
|------|------|------|------|
| C0 | 旁路建议 | 只读会话 → 侧栏展示动机 + 推荐回复；人复制或一键填入输入框，**不自动点发送** | 低 |
| C1 | 半自动 | 填入输入框并高亮；发送仍需人点或 `request_approval` | 中 |
| C2 | 托管自动 | 白名单意图 + 置信度阈值内自动发送；其余升级人工 | 高 |
| C3 | 多会话编排 | 多买家队列、营业时间、人设/知识库 | 高 |

**本期建议做到 C0～C1**；C2 必须带显式开关 + 审批策略，避免「默认全自动」伤品牌。

### 5.3 架构草图

```text
[客服网页 DOM]
    ↓ poll / MutationObserver / 录制 skill
[cs_watch / cs_inbox_snapshot]     ← Sparo 原语（手）
    ↓
[动机分类 + 回复生成]              ← 侧栏 LLM 或外部 Hermes（脑）
    ↓
[cs_draft_reply] → 可选 cs_send（审批后）
```

关键设计：

- **站点适配层**：先选 1 个切入点（建议：**1688 旺旺网页** 或用户实际在用的客服页），用 skill + 选择器/CDP；不要第一期「通吃所有 IM」  
- **话术/知识库**：`%APPDATA%/sparo/cs-kb.json`（价格口径、禁答项、运费、退换货）  
- **动机标签**：固定枚举 + 置信度；低置信度强制人工  
- **安全**：自动发送默认关；敏感词/承诺类话术拦截；全链路日志便于追责

### 5.4 MCP / 工具草案（C0～C1）

| Tool | 作用 |
|------|------|
| `cs_detect_platform` | 识别当前是否客服页及站点 |
| `cs_list_threads` | 会话列表摘要 |
| `cs_read_thread` | 当前/指定会话消息（结构化） |
| `cs_analyze_intent` | 动机分析（可本地规则+LLM） |
| `cs_draft_reply` | 生成草稿并可选填入输入框 |
| `cs_send_reply` | 点击发送（默认走 `request_approval`） |

侧栏 UI：会话摘要卡片 + 动机徽章 + 草稿编辑 +「填入」「发送(需确认)」「开始托管」。

### 5.5 验收（C1）

- 打开约定客服页，模拟客户消息后 10s 内侧栏出现动机 + 草稿  
- 「填入」后输入框可见正确文本；「发送」弹出审批且可拒绝  
- Pause 后停止一切自动轮询

### 5.6 工时粗估

- C0：5～8 人日（含 1 个站点适配）  
- C1：再 +3～5 人日  
- C2：另开专项（策略引擎 + 审计）

## 6. 需求 D · 网页信息自动分析（1688 搜品 / 竞品）

### 6.1 场景

用户说：「帮我在 1688 找 XX 品类，锁定 5 个竞品，对比价格/起订量/复购话术」。

### 6.2 为何难（说清楚预期）

- 列表/详情 DOM 常变、登录态、反爬与验证码  
- 「竞品」定义主观（同类目 vs 同款图搜）  
- 需要 **浏览闭环 + 结构化抽取 + 报告**，不是单次 `page_text`

### 6.3 分层目标

| 阶段 | 名称 | 能力 |
|------|------|------|
| D0 | 通读摘要 | 任意页：`page_text` / snapshot → LLM 按用户问题出要点（已有底座） |
| D1 | 任务型浏览 | Skill：打开 1688 → 搜索关键词 → 等待列表 → 抽取 N 条卡片字段 |
| D2 | 竞品卷宗 | 进入详情页补字段；输出表格（标题/价/起订/店铺/链接/截图） |
| D3 | 持续监控 | 定时打开、diff 价格（更后） |

**本期建议 D0 通用化 + D1 对 1688 MVP**；D2 跟进。

### 6.4 实现要点

- Skill：`alibaba-1688-search`（navigate → wait_for → analyze/列表脚本 → 结构化 JSON）  
- 抽取优先 **页面脚本固定 schema**，LLM 只做「用户需求 → 搜索词 / 筛选条件 / 报告润色」  
- 输出落盘：`%APPDATA%/sparo/research/<stamp>.json` + 侧栏可预览  
- 遇登录墙 / 滑块：`pause` + 明确提示人处理，不硬刚反爬

### 6.5 验收（D1）

- 指令：「1688 搜索 不锈钢保温杯 只要包邮前 5 条」→ 返回 ≥3 条含标题、价格、链接的结构化结果  
- 失败时有可读原因（未登录 / 选择器失效 / 超时）

### 6.6 工时粗估

- D0 包装：1～2 人日  
- D1 MVP：5～10 人日（含选择器脆弱性缓冲）  
- D2：再 +5～8 人日

## 7. 与现有架构的关系

```text
┌─────────────────────────────────────────────┐
│  Hermes / OpenClaw / 侧栏 DeepSeek（脑）      │
└──────────────────┬──────────────────────────┘
                   │ MCP
┌──────────────────▼──────────────────────────┐
│ Sparo 原语层                                 │
│  navigate/snapshot/fill/click/…              │
│  analyze_page / execute_primitives           │
│  xhs_* / skills                              │
│  【新】download_image / context-menu         │
│  【新】cs_* 客服原语                          │
│  【新】research_* / 1688 skill               │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│ 共享 Chromium 窗 + Pause / Approval          │
└─────────────────────────────────────────────┘
```

不把「客服大脑」或「竞品分析大脑」绑死在浏览器进程里：Sparo 提供 **稳定读写与动作**；复杂推理优先外部 Agent，侧栏 LLM 作轻量内置。

## 8. 合规与产品红线

1. **自动客服发送**默认关闭；开启须明示「托管中」状态  
2. **禁止**教唆绕过平台风控 / 验证码破解；只做人机协同过墙  
3. 客服与情报日志本地可关；默认不上传第三方（除用户配置的 LLM API）  
4. 价格/承诺类话术必须可配置「禁答列表」

## 10. 已拍板决策（2026-08-11）

| # | 决策 |
|---|------|
| 1 | **客服**：不绑死单一 IM；**任意在 Sparo 打开的页面**只要有聊天输入框即可做「读会话 → 动机 → 草稿」；发送半自动（人确认） |

| 4 | **Hermes**：可改系统提示，并塞入 Sparo Playbook |
| 5 | **开工顺序**：A 图片下载 → B 填表 Skill/Playbook → C 客服半自动（全站）→ D 全站情报分析 |
