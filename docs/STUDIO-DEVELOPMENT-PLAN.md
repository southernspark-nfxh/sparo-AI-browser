# Sparo 媒体工作台 · 开发方案

> 版本：v1.0  
> 日期：2026-11-12  
> 状态：待评审，评审通过前不改工作台代码  
> 目标读者：产品设计、UI、前端、主进程与发布链路开发者、QA

## 0. 文档关系与一页结论

### 0.1 文档关系

- `MEDIA-STUDIO-PRODUCT.md`：产品边界、指标口径、平台红线与既有对象定义的权威来源。
- `TASKBOOK-MEDIA-STUDIO.md`：P0a–P3 的历史分期与验收记录；不得借本方案回头扩大旧阶段验收。
- `STUDIO-DESIGN.md`：前期设计调研与备选方向。本方案选定唯一视觉方向后，以本方案为后续 UI 实施依据。
- 本方案：P0a–P3 已有能力之上的下一轮工作台改版，覆盖美术 UI、页面、任务模型、技术接入、分期与验收。

如内容冲突：平台安全与指标口径服从产品书；旧阶段是否完成服从任务书；后续界面与交互以本方案为准。

### 0.2 一页结论

媒体工作台不是稿件表单和数据卡片的集合，而是一个以**账号资产、发布任务、异常处理**为主线的本地专业工作台。

本轮确定五项核心决策：

1. **视觉方向**：浅色内容区 + 石墨色侧栏，细边框、克制留白、无渐变、无毛玻璃。
2. **信息架构**：工作台 / 发稿 / 数据 / 评论 / 账号，共五个一级导航。
3. **发布模型**：一篇草稿可产生多次发布；一次发布包含多个平台任务；每个平台独立记录、续跑和回执。
4. **技术路线**：本地页面 + 现有 IPC + 现有八步发布引擎 + 真浏览器；不引入远程 UI、WebSocket、React 或新 npm 依赖。
5. **人工边界**：写稿不要求登录；发布前只校验所选平台；发布由人确认；评论只填平台回复框，由人发送。

### 0.3 本轮不解决什么

- 不做云端存稿、服务器代发、账号托管和远程工作台。
- 不做跨环境批量矩阵分发。一个草稿和一次发布只属于一个账号环境。
- 不做定时、一键错峰、自动缩标题、富文本编辑器重构。
- 不做导出报表、自定义透视、私信、自动点赞、自动关注、批量回复。
- 不扩展新平台，不把视频上传改为平台 API 分片直传。

## 1. 产品目标与使用原则

### 1.1 目标

用户打开工作台后，应能快速回答：

1. 当前操作的是哪个账号环境？
2. 哪些账号或任务需要我处理？
3. 稿件还缺什么，哪些平台可以发布？
4. 每个平台执行到哪一步，失败原因是什么？
5. 数据是否完整、来自哪里、截至什么时间？
6. 哪条评论待处理，如何安全地填入平台回复框？

### 1.2 使用原则

- **写稿与登录解耦**：未登录也能新建、编辑、插图和自动保存。
- **选中才校验**：只检查本次选择的平台，未选择的平台不阻断发布。
- **异常局部化**：一个平台掉线或失败，不影响其他平台已有结果。
- **历史不可覆盖**：再次发布新建任务；重试增加尝试记录，不抹掉旧回执。
- **提交后先核验**：结果未知的提交不得直接重试，避免重复发布。
- **所有数字有出处**：来源、采集时间和完整度不可省略。

## 2. 已有基础与必须保留的能力

### 2.1 直接复用

- 独立标签页 `sparo://studio`，侧栏只保留「媒体工作台」入口。
- `window.sparkStudio` IPC 桥，不新增 WebSocket。
- `platforms/*.json` 平台规则表与离线 `--plan`。
- 四个平台适配器。
- 八步发布链路：

```text
openBlank
→ fillTitle
→ fillBody
→ insertImages
→ setCover
→ setOptions
→ publishOrSchedule
→ verify
```

- `--from` 断点续跑，包括 `--from setCover` 自测。
- 本机草稿自动保存、JSONL 发布台账、SQLite 数据快照。
- 数据在平台标签页上下文发 GET；评论回复只填已打开且定位明确的回复框。
- 多账号环境通过 `webPreferences.partition` 隔离 Cookie、localStorage、IndexedDB 与缓存。

### 2.2 不重写、不搬家

- 不把发布步骤搬进渲染页面。
- 不为了“架构整齐”把现有执行脚本全部挪进主进程。
- 不把发布任务和台账搬进 SQLite。
- 不修改 `docs/listings/`，不修改包版本，不推远程。
- 不改八步引擎来配合视觉稿；UI 状态只做现有步骤的映射。

## 3. 美术 UI：简洁专业编辑控制台

### 3.1 风格定义

风格名称：**Studio Neutral / 克制编辑控制台**。

关键词：专业、安静、清楚、可信、高效。

视觉识别不依赖渐变和插画，而依赖四件事：

1. 石墨色导航与浅色工作区形成稳定骨架。
2. 标题、正文、辅助信息、数字有明确层级。
3. 卡片用细边框分区，不用厚重阴影堆叠。
4. 状态色只表达状态，不给平台涂满品牌色块。

本期只做这一套浅色主题。石墨色侧栏是固定布局，不代表另做暗色模式；全局暗色模式不在本轮范围内。

### 3.2 色彩 Token

| Token | 色值 | 用途 |
|---|---|---|
| `--bg` | `#F7F8FA` | 页面背景 |
| `--surface` | `#FFFFFF` | 卡片、表格、输入区 |
| `--surface-subtle` | `#F1F3F5` | 表头、只读区、轻分组 |
| `--sidebar` | `#17191D` | 左侧导航 |
| `--sidebar-hover` | `#23262C` | 导航悬停 |
| `--sidebar-active` | `#2B2F38` | 导航选中 |
| `--text` | `#1D2129` | 主文字与数字 |
| `--text-secondary` | `#4E5969` | 正文辅助、说明 |
| `--text-muted` | `#667085` | 时间、来源、占位；白底对比度不低于 4.5:1 |
| `--border` | `#E5E6EB` | 卡片、表格、输入边框 |
| `--border-strong` | `#C9CDD4` | 悬停与强分隔 |
| `--accent` | `#4F5ED7` | 主按钮、链接、当前焦点 |
| `--accent-soft` | `#EEF0FF` | 轻选中背景 |
| `--success` | `#18864B` | 成功、正常 |
| `--warning` | `#B54708` | 部分数据、需要注意 |
| `--danger` | `#C9352B` | 失败、登录失效 |
| `--info` | `#3563E9` | 执行中、提示 |

规则：

- 数字默认使用 `--text`，不用品牌色染数字。
- 成功、警告、失败同时配文字或图标，不只用颜色区分。
- 平台标识用中性底 + 平台简称，不使用大面积平台色。
- 正文文字与背景对比度至少 4.5:1。

### 3.3 字体与数字

不下载字体、不增加字体依赖，使用系统字体栈：

```css
font-family: Inter, "SF Pro Text", "Segoe UI", "PingFang SC",
  "Microsoft YaHei", system-ui, sans-serif;
```

| 用途 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面标题 | 20 / 28 | 600 |
| 编辑标题输入 | 20 / 30 | 600 |
| KPI 主值 | 32 / 38 | 600 |
| 区块标题 | 15 / 22 | 600 |
| 正文与表格 | 14 / 22 | 400 |
| 按钮与表单 | 14 / 20 | 500 |
| 标签 | 12 / 16 | 500 |
| 来源与脚注 | 11 / 16 | 400 |

数字统一 `font-variant-numeric: tabular-nums`；表格数字右对齐，文本左对齐。

### 3.4 间距、圆角、边框与阴影

- 间距基准：4px；使用 4 / 8 / 12 / 16 / 24 / 32 / 48。
- 输入框与按钮圆角：6px。
- 卡片圆角：10px。
- 弹窗与抽屉圆角：14px。
- 卡片默认：1px `--border`，无阴影。
- 浮层允许阴影：`0 12px 32px rgba(16, 24, 40, 0.12)`。
- 焦点环：`0 0 0 3px rgba(79, 94, 215, 0.18)`，不能只靠浏览器默认细线。

### 3.5 图标与动效

- 使用本地内联 SVG，线性图标，16px 与 20px 两档，统一 1.75px 描边。
- 不引入图标 npm 包，不引用第三方图片 URL。
- 图标按钮必须有 `aria-label` 和 `title`。
- 普通悬停与展开动画 120–160ms，`ease-out`。
- 不做数字翻滚、粒子、闪烁、巨幅渐变和循环动效。
- 尊重 `prefers-reduced-motion`；骨架屏可使用静态灰块，不强加闪烁。

### 3.6 禁止的视觉做法

- 不做数据大屏风、霓虹色、玻璃拟态、渐变 hero。
- 不用厚阴影区分每一张卡。
- 不把调试 JSON、原始错误堆栈直接展示给用户。
- 不做无功能装饰按钮、假趋势图、假百分比和假在线状态。
- 不用 emoji 代替统一图标和状态组件。

## 4. 信息架构与全局布局

### 4.1 一级导航

```text
工作台
发稿
数据
评论
账号
```

- **工作台**：待处理事项、账号异常、数据摘要、最新评论。
- **发稿**：草稿编辑、平台差异、预检、发布记录。
- **数据**：账号与内容数据、趋势、排行、异常。
- **评论**：评论收件箱与回复草稿。
- **账号**：当前环境的平台账号、登录态与重新登录入口。

素材不做一级，进入发稿页；设置不做一级，保留右上入口；发布记录不做一级，放入发稿页二级视图，并提供右上常驻任务入口。

### 4.2 全局骨架

```text
┌ 顶栏 56px ────────────────────────────────────────────────────┐
│ 媒体工作台  环境：默认 ▾              [发布任务 2]  [新建稿件] │
├ 侧栏 232px ─┬ 内容区 max 1440px / padding 32px ───────────────┤
│ 工作台      │ 页面标题 + 说明 + 页面主操作                     │
│ 发稿        │ 页面内容                                         │
│ 数据        │ 页脚：数据截至 / 最近刷新 / 错误说明             │
│ 评论        │                                                  │
│ 账号        │                                                  │
└─────────────┴──────────────────────────────────────────────────┘
```

- 内容区使用 12 栏栅格，栏间距 24px。
- 窗口小于 1100px：侧栏收为 64px 图标轨，仍保留可访问名称。
- 窗口小于 1100px：发稿页改为单栏，平台卡位于编辑区之后。
- 窗口小于 900px：KPI 两列；评论页改为列表与详情逐级进入。
- 页面最小支持宽度 800px，不出现整页横向滚动；宽表允许自身横向滚动。

### 4.3 环境上下文

顶栏环境选择器是工作台全局上下文：

- 草稿、发布任务、数据、评论和账号状态都带 `envId`。
- 新建草稿绑定当前环境；旧草稿只有能明确证明属于默认环境时才迁移为 `default`，其余标「未关联」，不清空内容、不擅自绑定账号。
- 切换环境只切换查看与操作上下文，不在同一标签里切换登录态。
- 不提供「全部环境一起发布」；跨环境聚合查看也不属于本轮。
- `envId` 必须贯穿草稿、预检、发布批次、平台任务、尝试、八步执行、结果核验、数据采集和评论回复；任何一步缺失时都停止，不回退到默认环境。
- 指标表继续沿用产品书既定主键，不擅自加列改键；采集记录必须能通过 `accountId` 明确关联环境与平台账号，无法关联时暂停写入，防止串号。
- 旧草稿和旧评论缓存只有在能明确归属时才迁移到对应环境；无法确定归属时标「未关联」，不得擅自归入当前非默认环境。

## 5. 页面与交互详案

### 5.1 工作台

目标：先处理异常，再看经营数据。

```text
工作台                                      [新建稿件]
当前环境：默认 · 数据截至 11-12 10:30

┌ 需要处理 ───────────────────────────────────────────────────┐
│ 百家号登录失效                         [重新登录]             │
│ 头条号《标题 A》停在封面                 [查看任务]           │
└──────────────────────────────────────────────────────────────┘

┌ 待发任务 ──┐ ┌ 失败任务 ──┐ ┌ 昨日阅读 ──┐ ┌ 本月收益 ────┐
│ 2          │ │ 1          │ │ 2,622      │ │ ¥3.69        │
│ 查看发布记录│ │ 需要处理   │ │ 相加，非去重│ │ 账面相加     │
└────────────┘ └────────────┘ └────────────┘ └──────────────┘

┌ 最近发布（8 栏）───────────────┐ ┌ 最新评论（4 栏）──────────┐
│ 标题 / 平台 / 阶段 / 更新时间  │ │ 平台 / 作者 / 摘要 / 时间  │
└────────────────────────────────┘ └────────────────────────────┘
```

规则：

- 「需要处理」只列需要人介入的事项，不把所有日志堆到首页。
- 首页数据来自已有快照；快照不存在时显示空态，不虚构趋势。
- 待办数字可点击，进入已筛选的对应页面。
- 阅读合计标「相加，非去重」；收益标「账面相加，非到账」。
- 任一平台 `partial`，聚合卡不显示涨跌百分比。

### 5.2 发稿：编辑视图

```text
发稿 / 编辑                    已自动保存 10:28      [发布记录]

┌ 共性内容（8 栏）──────────────────────┬ 发布平台（4 栏）─────────┐

│ │                                  │ ├──────────────────────────┤

│ ┌──────────────────────────────────┐ │ [ ] 搜狐号   未选择      │
│ │                                  │ │                          │
│ │                                  │ │ 展开平台后只显示：       │
│ │                                  │ │ 平台标题 / 封面模式      │
│ │                                  │ │ 分类 / 原创 / 其他差异项 │
│ └──────────────────────────────────┘ │                          │
│ 正文图片  [选择图片] [拖入此处]        │                          │
│ 封面      [选择封面] [预览]           │                          │

│ [保存] [预检]                                  [检查并发布 →]    │
└─────────────────────────────────────────────────────────────────┘
```

交互规则：

- 共性内容只填一次；平台差异只出现在对应平台卡。
- 卡片头直接显示完整度与第一个缺项；同时只展开一张卡。
- 越界只标红并说明，不自动缩短。
- 未登录不禁用编辑器，也不弹出阻断式登录框。
- 自动保存沿用现有能力；保存失败要显示「未保存」并保留当前输入。
- 正文继续使用 Markdown；本期不引入富文本编辑器。
- 图片选择通过本地文件能力完成，显示缩略图、文件名、移除与排序；不再要求用户手填本地路径。
- 底部动作栏在编辑容器内 sticky，不遮挡正文和平台选项。
- 未做任何预检时，主按钮为「检查并发布」；不能直接绕过预检。

### 5.3 发布预检

使用居中大弹窗，宽 720px，最大高度为视口的 80%；内容滚动，底部操作固定。

```text
发布前检查
本次使用环境：默认；只检查已选择的平台。

[正常] 头条号
标题 24/30 · 封面已选 · 必勾项已配置 · 登录正常

[需处理] 百家号
缺封面（必填）                         [去设置]
登录态未核验                           [重新核验]

[跳过] 大鱼号
未选择，不参与本次发布

当前可发布 1 个平台；需处理的平台默认跳过。
[返回修改]                         [确认发布 1 个平台]
```

规则：

- 预检包括内容规则、平台选项、环境与所选账号登录态。
- 登录缺失只阻断对应平台，不清空草稿，不阻断其他平台。
- 登录态无法判定时写「未核验」，不能伪造「正常」。
- 警告平台默认跳过，用户可返回修改；不能靠一次点击强行绕过必填缺项。
- 确认单不出现定时、时间建议或一键错峰。
- R3 只验到现有确认单，不真实执行、不创建生产发布批次；R4 只用旧台账与测试夹具搭建任务视图；R5 同步接入真实任务创建与八步执行，避免出现「已排队但无人执行」的假任务。

### 5.4 发稿：发布记录与任务中心

发布记录是发稿页的二级视图；右上「发布任务」打开 420px 右侧抽屉，展示进行中和最近任务。抽屉不是唯一入口，完整历史仍在发布记录页。

```text
《标题 A》· 环境：默认 · 2026-11-12 10:30 确认

头条号    处理图片与封面    insertImages    [查看详情]
百家号    已发布            已核验回执       [查看回执]
大鱼号    发布失败          COVER_NOT_PICKED [从封面续跑]
搜狐号    结果待核验        提交后页面跳转   [核验结果]
```

规则：

- 一次确认形成一个发布批次，每个平台一个独立任务。
- 展示用户可理解的阶段，同时保留原始步骤名用于诊断。
- 失败必须包含 `errorCode`、人话说明、发生步骤和建议动作。
- 「重试」只作用于当前平台；已成功平台不再执行。
- 提交前失败可按允许步骤续跑；提交后结果未知只提供「核验结果」。
- 再次发布同一稿件创建新批次，不覆盖旧批次与旧回执。
- 后台执行不抢焦点；需要人在平台页确认时才切到对应平台页。
- 任务持久化，离开页面、切换导航或重启后仍可查看。

- 总览卡只放阅读、净增粉丝、收益、异常，不放待回评论。
- 只有一天数据时显示「暂无趋势」，不能伪造平线或涨跌。
- 内容榜必须是表格，不出现 `JSON.stringify`。
- 收益以分存、以元显示；缺失指标显示 `—`，真实 0 显示 `0`。
- 刷新失败保留旧值，并显示「未获取到新数据，仍显示 10:30 的结果」。
- 手动刷新沿用 5 分钟冷却；采集串行，不新增后台常驻轮询。

## 6. 核心对象与任务状态

### 6.1 最小对象模型

不推翻产品书已有 `PublishJob`，只增加一个发布批次概念，避免另造一套平行模型。

| 对象 | 关键字段 | 说明 |
|---|---|---|
| `Draft` | `id / envId / revision / title / body / platforms / updatedAt` | 一篇可长期编辑的稿件 |
| `PublishRun` | `runId / draftId / draftRevision / snapshotHash / envId / precheckId / confirmationId / confirmedAt` | 用户一次确认形成的发布批次 |
| `PublishJob` | `jobId / runId / draftId / envId / platform / stage / currentStep / submitState` | 某平台在该批次中的任务 |
| `PublishAttempt` | `attemptId / jobId / envId / snapshotHash / fromStep / startedAt / endedAt / error` | 一次执行或续跑记录 |
| `Receipt` | `jobId / runId / envId / platform / articleId / url / verifiedAt / summary` | 核验后的平台回执 |

- `PublishRun`、`PublishJob` 与尝试记录继续落 JSONL。
- 扩展后的 `ledger.mjs` 是发布事件 JSONL 的**唯一写入入口**：主进程工作台服务与执行脚本都必须调用它，不得各自 `appendFile`；渲染层只读查询结果，不获得写文件能力。
- 新事件统一携带 `eventId / eventType / occurredAt / envId`，并按事件类型携带 `runId / jobId / attemptId`。写入入口串行追加并按 `eventId` 去重，同一事件重放返回已记录结果；页面状态由事件投影生成，不另维护一份可独立修改的任务底账。
- 旧台账只有 `draftId + platform` 时仍能读取；新记录补 `runId`，旧记录只读展示，不回填虚假批次、环境或尝试。
- 预检返回 `precheckId + draftRevision + snapshotHash + 所选平台 + envId`；确认时必须全部匹配，稿件、平台选择或环境变化后原预检失效，必须重新预检。
- 确认时保存不可变稿件快照；执行读取该快照，不读取仍在编辑的 `draft.json`，后续改稿不改变已确认任务。
- `confirmationId` 由主进程做幂等约束：双击、重复 IPC 或页面重发同一确认只返回同一 `runId`。按钮禁用只是交互反馈，不能代替主进程幂等。
- 再次发布创建新 `runId` 和新平台任务；重试沿用 `jobId`、新增 `attemptId`。

### 6.2 用户状态与八步映射

| 用户可见状态 | 对应步骤或条件 | 允许动作 |
|---|---|---|
| 等待确认 | 尚未形成有效确认 | 返回编辑、确认 |
| 排队中 | 等待执行 | 查看 |
| 打开发布页 | `openBlank` | 查看 |
| 填写内容 | `fillTitle / fillBody` | 查看 |
| 处理图片与封面 | `insertImages / setCover` | 查看 |
| 设置平台选项 | `setOptions` | 查看 |
| 提交中 | `publishOrSchedule` 且已获人确认 | 查看 |
| 核验结果 | `verify` | 查看 |
| 已发布 | 回读或列表核验通过 | 查看回执 |
| 发布失败 | 提交前明确失败 | 从允许步骤续跑 |
| 需要人工 | 登录、验证码、短信、必补项 | 去处理 |
| 结果待核验 | 提交后跳转、超时或无回执 | 核验结果，禁止直接重试 |

状态显示必须来自执行记录，不由前端定时器假装推进。

### 6.3 续跑与重试边界

- 头条重试不重建或修改百家任务。
- `--from` 只能使用现有引擎允许的断点；续跑前核对标题与 `snapshotHash`，防止串稿。
- 已成功任务没有「重试」按钮。
- 调用 `publishOrSchedule` 前必须先持久化 `submitState=submitting`、`attemptId`、`envId` 与 `snapshotHash`。进程在提交中或提交后崩溃，重启一律转为「结果待核验」，不得按提交前失败自动续跑。
- 结果未知任务必须先核验，核验失败再转人工，不自动重发。
- 重试不覆盖上一次错误；保留每次尝试的时间、步骤与错误。
- 保持逐平台 review、串行 commit、同平台多篇串行，并继续执行 `perDay` 与 `minGapMinutes`；工作台不能绕过发布节奏。
- 任何自动重试仅限明确安全、未提交的本地准备步骤；本轮默认不新增自动重试。

## 7. 技术接入方案

### 7.1 进程与执行关系

```text
studio.html / studio.ts
  └─ window.sparkStudio（contextBridge IPC）
       └─ 主进程工作台服务
            ├─ 草稿与本地文件
            ├─ 发布批次、任务与台账
            ├─ 账号环境状态
            ├─ 数据快照查询
            └─ 调用现有发布 / 采集 / 评论执行层
                  └─ Sparo 标签页与平台页面
```

- UI 只表达意图，不直接拼平台请求、不伪造签名、不持平台 Cookie。
- 现有八步和适配器保持独立；主进程负责命令、状态持久化和事件转发。
- 不引入远程 UI，不要求联网才能打开本地工作台。

### 7.2 IPC 设计原则

保留现有 `load / create / save / precheck / confirm / refresh / reply`。按实际实现最小补充：

| 能力 | 建议 IPC 语义 |
|---|---|
| 账号状态 | 查询当前环境账号、核验所选平台、打开登录页 |
| 发布记录 | 查询批次与平台任务、打开对应平台页 |
| 续跑 | 从明确允许步骤重试单个平台任务 |
| 结果核验 | 只执行 verify / 列表回读，不重新提交 |
| 本地图片 | 选择文件、读取草稿内缩略图、移除与排序 |
| 状态更新 | 主进程推送任务变化；页面卸载后停止监听 |

具体名称可按现有代码风格确定，但不另建 WebSocket，不暴露通用 `executeJavaScript` 给工作台页面。

### 7.3 存储

| 数据 | 位置 |
|---|---|
| 草稿 | `%APPDATA%\sparo-store\drafts\<id>\` |
| 已确认稿件快照 | `%APPDATA%\sparo-store\publish-snapshots\<runId>.json`，写入后不可修改 |
| 发布批次、任务、尝试、台账 | JSONL，沿用现有发布台账体系，只能经 `ledger.mjs` 写入 |
| 指标快照 | `%APPDATA%\sparo-store\metrics.sqlite` |
| 评论缓存 | 现有本地评论缓存，记录必须带 `envId`；无法归属的旧记录标「未关联」 |
| UI 偏好 | 仅保存侧栏折叠、筛选等无害偏好，不保存 token |

任何缺失数据不得写成 0；任务失败不得写成成功；本地填框不得写成评论已回复。已确认快照与编辑中草稿分开存放，执行层只能按 `runId + snapshotHash` 读取对应快照。旧草稿、任务和评论只有在归属明确时才迁移；无法确定环境的数据不参与非默认环境的展示、采集或执行。

### 7.4 前端实现约束

- 延续原生 HTML / CSS / JavaScript 或 TypeScript，不引入 React、Tailwind、ECharts 或新依赖。
- CSS 使用 `@layer reset, tokens, base, layout, components, utilities`。
- 使用 CSS 自定义属性、容器查询、`color-mix()`、`@media (prefers-reduced-motion)`。
- KPI 栅格使用容器查询，不能只按屏幕宽度判断。
- 状态用 `data-state`、平台用 `data-platform`，JS 不逐处写内联颜色。
- 所有异步区域具备加载、空、真实 0、缺失、错误五种状态。
- 不为了视觉效果新增一套 mock 数据生产路径；验收使用真实本地数据或明确的测试夹具。

## 8. 统一组件规范

### 8.1 KPI 卡

结构固定：标签 → 数值 → 单位 → 对比 → 来源与截至时间。

- 一张卡最多三个可见数值。
- 对比必须写清窗口；无比较条件显示 `—` 和原因。
- 箭头表示涨跌，颜色表示好坏，两者不得混用。
- 缺失与真实 0 使用不同组件状态。

### 8.2 状态标签

| 状态 | 界面文字 | 视觉与操作 |
|---|---|---|
| `ok` | 正常 / 完整 | 成功色小点，无额外表单 |
| `partial` | 部分数据 | 警告色小点，可查看缺项 |
| `stale` | 未更新 | 灰色，提供刷新 |
| `missing` | 未获取 | 灰色，提供重试 |
| `unsupported` | 平台未提供 | 浅灰，无无效按钮 |
| `login_missing` | 登录态缺失 | 失败色，提供重新登录 |
| `error` | 请求失败 | 失败色，保留旧值并重试 |
| `unknown` | 未核验 / 结果待核验 | 中性色，提供核验 |

### 8.3 表格

- 表头 44px，sticky；行高 44px；单元格左右 padding 16px。
- 默认 6–7 列，其他列进详情，不做全字段宽表。
- 分隔只用行线与 hover 底色，不同时使用斑马纹。
- 空表显示原因与下一步，不只显示「暂无数据」。

### 8.4 按钮与危险动作

- 主按钮每屏最多一个；次要动作使用描边或文字按钮。
- 发布确认写清平台数量；重试写清平台与起始步骤。
- 禁用按钮必须能解释原因；不让用户点完才知道缺什么。
- 所有按钮均有默认、hover、active、focus、disabled、loading 状态。

### 8.5 页面反馈

- 保存：显示「保存中 / 已自动保存 / 保存失败」，不用频繁 toast。
- 发布：进入任务中心，不用 toast 代替任务结果。
- 数据错误：保留旧值，页内提示，不清空整页。
- 评论填框：显示目标平台与读回结果，不显示「已回复」。

## 9. 分期开发计划

以下 R1–R6 是新一轮改版，不改写 P0a–P3 的历史结论。每阶段完成后自测、提交一个独立 commit，不推远程；每阶段均运行 `npm run typecheck` 与 `npm run test`。

### R1 · 视觉基础与导航骨架

改动：

- 建立 Token、CSS layer、字体、按钮、表单、卡片、状态标签与焦点规范。
- 完成石墨侧栏、56px 顶栏、环境选择器、五个一级导航。
- 旧功能暂时原样迁入新导航，不新增发布能力。

验收：

- 1440 / 1280 / 1024 / 800 四档宽度无整页横向滚动。
- 侧栏折叠后所有入口仍可访问，键盘焦点清晰。
- 页面没有渐变、毛玻璃、调试 JSON 和无功能按钮。

### R2 · 工作台与数据页

改动：

- 实现 KPI、待处理事项、最近发布、最新评论摘要。
- 数据页完整实现总览卡、趋势、内容榜、平台对比、收益拆分、异常六块视图；平台对比与收益拆分可组合为页签。
- 接入五种异步状态和统一指标可用性。

验收：

- 六块视图均有真实内容或明确空态，不以平台明细代替平台对比与收益拆分。
- 真实 0 显示 0，缺失显示 `—`。
- `stale / missing / unsupported / login_missing` 文案与操作不同。
- 内容榜无 `JSON.stringify`；单天数据不伪造趋势。
- 接口失败保留旧快照。

### R3 · 发稿、账号与预检

改动：

- 完成共性编辑区、平台卡、底部动作栏和本地图片选择预览。
- 新增当前环境账号页与登录状态核验。
- 预检加入所选平台账号检查，未登录不阻断编辑。

验收：

- 全程未登录也能写稿并自动保存。
- 只选一个平台时不检查其他平台是否登录。
- 平台卡完整度、预检缺项与规则表一致。
- 账号页不读取、展示或落盘 token。
- 本阶段只验到现有确认行为，不真实发布。

### R4 · 发布批次与持久任务中心

改动：

- 扩展 `ledger.mjs` 为唯一发布事件写入口，定义 `PublishRun / PublishJob / PublishAttempt` 事件与只读投影，但本阶段不把真实确认按钮接入新任务创建。
- 完成发布记录页、右上任务抽屉、用户状态映射与失败详情；真实数据只读旧 JSONL，新模型仅用明确标注的测试夹具验收。
- 兼容读取旧记录，不覆盖历史、不生成没有执行器的生产「排队中」任务。

验收：

- 测试夹具中，同一 `draftId` 的两次确认形成两个不同批次，每个平台任务独立。
- 测试夹具中，头条失败不改变百家成功回执，重试新增尝试记录，已成功平台无重试按钮。
- 提交后未知状态只有核验动作，没有直接重试。
- 旧台账可正常投影，缺失的新字段显示「历史记录」，不伪造批次或环境。
- 切换导航和重启后任务仍可见；真实确认按钮仍只到 R3 的确认单，不产生新生产任务。

### R5 · 真实发布接入与安全续跑

改动：

- 在同一阶段接入确认幂等、不可变快照、生产任务创建与现有八步执行；确认成功后任务立即进入真实执行器，不存在只入队不交付的中间版本。
- 主进程按 `confirmationId` 去重；调用 `publishOrSchedule` 前落 `submitting` 事件，启动时恢复并投影任务状态。
- 需要人确认时切换到对应平台页；其余后台动作不抢焦点。
- 接入单平台 `--from` 续跑与结果核验，完整传递 `envId / runId / jobId / attemptId / snapshotHash`。

验收：

- 双击确认、重复 IPC、刷新后重发同一 `confirmationId` 均只生成一个 `runId` 和一组平台任务。
- 修改稿件、平台选择或环境后，旧预检不能确认；执行内容始终等于确认时的 `snapshotHash`。
- 分别在 `publishOrSchedule` 前、提交中、提交后模拟进程崩溃：提交前按允许断点恢复，提交中与提交后均为「结果待核验」，不自动重发。
- 在非默认 `envId` 环境实测一个平台，核对打开标签、八步执行、回执与台账全部属于该环境；缺失环境时停止，不回退默认环境。
- 先在开发形态核验头条、百家；未通过的平台标为未开放，不伪装可发。
- 由人在安装包里真实发布头条、百家各一次并保存回执。
- 四平台全部宣称为可用前，大鱼、搜狐也必须分别完成真实验收。
- 头条停在封面时可从封面续跑，百家不重复执行；同平台多篇保持串行，逐平台 review、串行 commit、`perDay` 与 `minGapMinutes` 均有底账证据。
- 结果未知时不产生重复发布。

### R6 · 评论布局、恢复与安装包收尾

改动：

- 评论改为三栏收件箱，小窗口改为逐级详情。
- 完成草稿恢复、保存失败提示、所有空态与错误态。
- 清理旧样式与调试输出，完成安装包 QA。

验收：

- 只显示评论探针已通的平台；未通平台不展示伪造的空列表。
- 头条、百家只填回复框，无发送与「我已发送」按钮；大鱼、搜狐只读。
- 同一时间只操作一个平台评论页；填入并读回后切到对应平台页，由人发送；回复频率限制和下一次 GET 判定不变。
- 工作台刷新或异常重开不丢已自动保存的稿件。
- 安装包包含 `out/renderer/studio.html`，安装形态实际点通五个页面。

## 10. 测试与验收

### 10.1 自动化测试

至少覆盖：

- 预检只校验所选平台；未登录可编辑但不能发布对应平台。
- 旧草稿仅在归属明确时迁移环境，无法归属时保持「未关联」且不丢旧字段。
- 一篇稿多批次、一批次多平台任务、单平台独立续跑。
- 同一 `confirmationId` 双击、重复 IPC 和崩溃后重放只创建一个批次；预检版本、平台选择或环境变化必须使确认失效。
- `publishOrSchedule` 前、中、后崩溃的恢复状态正确；提交中与提交后只能先核验，不能直接重试。
- `envId` 从草稿、预检贯穿到八步、核验、数据采集和评论填框；任何缺失都停止而非回退默认环境。
- 发布 JSONL 只有 `ledger.mjs` 一个写入口；相同 `eventId` 重放不重复追加，主进程与执行脚本不能形成双底账。
- 成功任务禁止重试，未知提交禁止直接重试。
- 八步到用户状态的映射，无前端假推进。
- `undefined / null / unsupported / missing` 不变成 0。
- `partial` 聚合不出现涨跌百分比。
- 评论只读平台禁用回复；20 秒与每小时 30 条限制不被 UI 绕过。
- 现有离线 `--plan`、`--from setCover` 与相关发布自测继续通过。

### 10.2 页面自测清单

- 1440 / 1280 / 1024 / 800 四档宽度。
- 浏览器 200% 缩放，数字不截断，按钮仍可点击。
- 键盘 Tab 覆盖导航、表单、平台卡、表格操作、弹窗与抽屉。
- 加载、空、真实 0、缺失、错误、登录失效逐项查看。
- 长标题、长评论、长错误说明不撑破布局。
- 环境切换后草稿、任务、数据和账号不串环境。
- 工作台无价格、套餐、付费入口，无 token 和原始堆栈。
- 控制台无报错；每个新增按钮都实际点击验证下一步。

### 10.3 真机与安装包

- 不用单测绿代替真实页面验收。
- 开发窗通过不等于安装包通过。
- 重新打包前运行受影响场景；安装包至少复测 G1、G2、G3。
- 媒体工作台额外验收：新建稿、预检、真实发布、单平台续跑、数据刷新、评论填框。
- 真实文章与真实评论发送只由人执行，自动化测试不得代发。

## 11. 安全与产品红线

1. 发布请求由平台页面发起；不伪造 `Acs-Token`、`tt-anti-token` 或其他签名。
2. 不抓 token、不持久化 Cookie、不在日志打印登录态。
3. 数据只发 GET，并在对应平台标签页上下文执行。
4. 遇验证码、滑块、短信立即停，转人工，不绕过。
5. 工作台没有评论发送按钮；发布必须经人确认。
6. 填表、发帖、采集不抢焦点；需要人操作时才切到平台页。
7. 不做模拟指纹、代理换 IP、自建签名服务、API 分片直传。
8. 不做跨环境批量发布，不把多账号能力变成矩阵轰炸工具。
9. 客户端不出现价格、套餐和付费入口。
10. 不用「看起来完成」替代回执、读回和底账。

## 12. 完成定义

只有同时满足以下条件，才能称本轮改版完成：

- 五个一级页面均已在运行中的 Sparo 里实际点通。
- 视觉符合本方案的浅色专业风，四档宽度与键盘操作通过。
- 账号、草稿、发布批次、平台任务、回执之间关系清楚，历史不覆盖。
- 头条、百家真实发布和单平台续跑有底账证据；宣称支持的其他平台也有各自证据。
- 数据缺失不变成 0，评论填框不变成已回复，任务未知不变成失败或成功。
- `npm run typecheck`、`npm run test` 通过，受影响黄金场景和安装包复测通过。
- 无远程 UI、无新依赖、无 token 落盘、无自动发送、无未登记的新提前结束判断。

最终交付不是一张漂亮截图，而是**简洁可信的界面、可恢复的任务、能复核的底账，以及安装包里真实可用的闭环**。
