# 媒体工作台 · 产品书

> 状态：v2 讨论稿（2026-11-11）。范围：头条号、百家号、大鱼号、搜狐号四平台。
> 一句话：**Sparo 里调出来的一张传媒工作台——写稿、分发、看数、回评论，在一个地方做完。**
> 定位对齐：Sparo 是「会动手的 AI 浏览器，发送前你确认」，不是云端 SaaS，也不是代运营后台。

---

## 0. 一页结论

- 产品不是一个「发稿页」，而是**一个工作台**；编辑与分发只是工作台里的第一个模块。
- 工作台一共三块真需求：**写与发**、**看数据**、**回互动**。
- **发布链路**大约八成：统一稿件入口、四个平台适配器、八步发布与断点续跑、批量定时、台账。**数据和互动是零**——P2 不是给现成数据套一层皮。
- 数据模块是新增的主干，不是附属。它决定这个工作台是「一次性工具」还是「每天都会打开的地方」。
- 封号风险低但不为零。红线三条：多号矩阵铺量、绕过风控、全自动无人值守。
- 最大隐性成本是平台改版后的适配维护，所以一切走规则表 + 断言，不写死 if-else。

## 1. 产品定位与边界

### 1.1 它是什么

一个常驻在本机的媒体工作台，从 Sparo 侧栏或首页入口调出。所有数据落在本机，账号是用户自己的，登录态是用户自己登的。

### 1.2 它不是什么

- 不是云端 SaaS：不存稿、不存 Cookie、不代登录。
- 不是 MCN 后台：不托管他人账号，不做多号矩阵。
- 不是数据抓取器：只读用户自己后台的数据，不爬公开页，不做竞品监控。

## 2. 问题

### 2.1 发的问题

一篇文章发四个平台，实际发生的是：

1. 打开四个后台，四套编辑器，四次传图、四次选封面。
2. 每套后台的规矩不一样，而且这些规矩现在藏在脚本里，用户看不见、也改不了。
3. 发完不知道哪家成功、哪家漏勾、哪家卡在审核。

现有代码里已有这些规矩，只是散落在适配器注释中：

| 平台 | 必须做的事 |
|---|---|
| 头条 | 封面是硬校验；「投放广告赚收益」必勾且要回读为已选；首发若已选则不动；赞赏、微头条、作品声明需人工补 |
| 百家 | 封面必须选「单图」radio，否则服务端 `cover_layout=none`，发布报 `errno:20040083`；只能点刚上传那张缩略图；「采用AI生成内容」不勾 |
| 大鱼 | 封面只能从正文选，正文必须已有 3 张**不同**的图，封面走「三图」 |
| 搜狐 | 封面 1 张；创作声明必须是「无需声明」；找不到定时入口就停手，不改点发布 |

这些知识是资产，但现在只对开发者可见。

### 2.2 看数的问题

比「发」更耗人的是「看」：

1. 四个后台、四套数据页，指标名字都不一样：展现量、推荐量、曝光量、阅读量、播放量。
2. 收益分散：广告分成、活动奖励、补贴，各自在不同菜单，结算周期也不同。
3. 单篇与账号两个维度要来回切，想看「这篇在四个平台一共多少阅读」得自己算。
4. 评论分散在四个后台，回复要一个个进。
5. 数据大多是 T+1，当天看到的数不等于当天表现，容易被误读。

所以工作台的第一价值不是「省点击」，是**把四套口径合成一张能看的表**，并且标明来源和时间。

## 3. 市场调研

### 3.1 四类玩家

| 产品 | 形态 | 技术路线 | 数据与互动 | 公开报价 |
|---|---|---|---|---|
| 融媒宝 | Windows 本地客户端 | 官方 API / app_token 优先；不开放的平台用「协议 + JS 脚本」模拟网页；宣称稿件本地分发、不上服务器 | 有平台数据统计、评论管理与关键词自动回复、1000+ 账号管理 | 46–188 元/月，258–1298 元/年 |
| 蚁小二 | 客户端 + 云 | 官方 API 授权 + 浏览器 RPA + 指纹浏览器 + App 云发布 | 有矩阵数据统计、多账号管理 | 订阅制 |
| 易媒助手 | 本地客户端 | 客户端加密，账号本地托管，强调平台只检测内容不检测 IP | 有数据与多平台管理 | 订阅制 |
| cspub（开源） | 命令行 | 每平台一套鉴权；图片按平台转存；能直发就直发，发不了就开浏览器 | 无数据与互动 | 免费 |

共同点很清楚：**发布只是入口，数据与账号管理才是留存**。融媒宝把「同时管理 1000+ 账号」「一键回复评论」当卖点，就是这个道理。

### 3.2 他们共同的四件套

1. **鉴权**：有官方接口走官方接口；没有就用登录态 Cookie + 页面内 token。
2. **图片**：下载原图 → 传进平台自己的图床 → 替换正文地址。没有捷径。
3. **差异适配**：每平台一个适配器，负责字段映射、必填默认值、封面规格、限额。
4. **回采与回执**：发布后回查列表页确认成功；数据从后台自己的数据页取，按日快照。

cspub 的实测最能说明「差异」有多硬：头条对任何非头条域名的图整篇拒绝（`7115 图片uri非法`）；知乎会剥掉站外图；百家号直调接口缺 CSRF 必 500；CSDN 每天限 1 篇。

### 3.3 可学与不可学

**学**：规则表驱动、图片逐平台转存、回执台账、数据按日快照、失败可续跑、订阅制商业化。

**不学**：账号托管、多号矩阵、批量铺量、50+ 平台堆数量、自动点赞互关、无审核自动回复。

## 5. 工作台形态

### 5.1 入口与布局

入口：**独立标签页 `sparo://studio`**，不经过任何平台。侧栏只留一行入口与当期状态（P1 仅显示待发篇数，P3 起才显示待回），点了跳进工作台；那一行不是工作台本身。

不做侧栏抽屉：侧栏默认 340px，装不下八个模块、编辑区和确认单；发布提交与选封面时平台页必须在前台（后台标签 `innerHeight` 为 0），抽屉会一直盖住要给人看的那一页。

P1 线框只出现四项导航：

```
┌──────────────────────────────────────────────────────┐
│ 账号：头条✓ 百家✓ 大鱼✓ 搜狐✓                        │
├─────────┬────────────────────────────────────────────┤
│ 总览     │                                            │
│ 稿件     │              主区域                        │
│ 分发     │                                            │
│ 台账     │                                            │
└─────────┴────────────────────────────────────────────┘
```

P2 才加「数据」导航、日期与刷新；P3 才加「互动」。素材与账号不单独占一级。第 5.2 节是完整模块地图，不代表一次上齐。

### 5.2 八个模块

| 模块 | 干什么 | 依赖 |
|---|---|---|
| 总览 | 当期该做什么：待发、异常、数据涨跌 | 其它模块汇总 |
| 稿件 | 写稿、草稿箱、从模板新建 | 本地草稿 |
| 分发 | 勾平台、预检、确认单、任务状态 | 四适配器 |
| 数据 | 账号与单篇指标、趋势、收益、平台对比 | 各平台数据接口 |
| 互动 | 聚合评论、筛选、回复草稿 | 各平台评论页 |
| 素材 | 图片库、封面、常用尾图 | 本地文件 |
| 账号 | 登录态健康度、过期提醒、重登入口 | 各平台后台 |
| 台账 | 每篇发到哪、回执、失败原因 | ledger |

> 这八个模块是地图，不是一期全上：P1 只有稿件、分发、台账 + 瘦总览（待发、失败、登录过期）；P2 加数据；P3 加互动。账号健康折进总览的异常条，有重登流程之前不单独占一级；素材不单独占一级，稿件图片区引用现有素材库。

### 5.3 总览页

数据总览第一屏只回答四个问题：

```
本周总阅读 12,480（四平台相加，非去重）   净增粉丝 +128
本月账面收益 ¥286.40（相加，非到账）
异常：大鱼登录已过期（2 小时前）           [去处理]
```

> 涨跌百分比只在四平台数据全部 `full` 时显示；任一平台 `partial` 就只给绝对值。净增粉丝用有符号数（+32 / -5）。P1 的瘦总览只有三行：待发、失败、登录过期；P2 总览卡不放待回评论，待回到 P3 随互动页出现。

完整形态下是三条曲线（阅读、粉丝、收益）和一张「本周内容榜」。数据缺哪个平台，就在卡片角上标灰点，点开说明原因，不静默丢数。

### 5.4 编辑模块

左边写稿，右边勾平台。

- 左：标题、正文（Markdown 或粘贴富文本）、图片区、封面、摘要、话题。
- 右：平台卡片，默认按上次选择记忆。
- 底：一个「预检」，一个「发布」。发布前必须先过预检。

勾一个平台，卡片立刻展开它会对这篇稿做什么：

| 显示项 | 例子 |
|---|---|
| 标题是否越界 | 头条 5–30 字，超了只标红，不自动缩短 |
| 封面会被怎么处理 | 大鱼：正文不同图不足 3 张，无法选三图封面 |
| 图片会被怎么转 | 头条：全部转存头条 CDN；搜狐：1 张封面 |
| 会默认勾什么 | 头条：投放广告赚收益；百家：不勾 AI 声明；搜狐：无需声明 |
| 需要人工补什么 | 头条：赞赏 / 微头条 / 作品声明 |
| 预计节奏 | 该平台单日限额、与上一次发布的间隔 |

### 5.5 发布前确认单

点「发布」不直接发，先出一张确认单，逐平台一行。P1 只做立即发布，确认单不出现定时或时间：

```
头条   ✅ 预检通过   封面1张  广告已勾  AI声明未勾   立即
百家   ✅ 预检通过   封面单图  AI声明未勾            立即
大鱼   ⚠️ 缺图       正文只有2张不同图，无法选三图封面   已跳过
搜狐   ✅ 预检通过   封面1张   无需声明              立即
```

人点一次「确认发布」，才允许进入后续平台写入与发布流程。这一屏就是产品跟「无人值守工具」的分界线。Cursor 的 P1 验收停在确认单，不执行 stage / review / commit。

## 6. 数据模块

### 6.1 取数原则

1. **只从用户自己的后台取。** 在已登录的标签页里，用页面上下文请求该平台自己的数据接口，和发布同一条路子。
2. **不估算、不推算。** 平台给多少就显示多少；缺失就标缺失，绝不按阅读量反推收益。
3. **只读不写。** 数据采集全是 GET，不触发任何状态变更。
4. **低频。** 缺才拉，不重复打；手动刷新有冷却。不做后台高频轮询。

### 6.2 统一指标模型

无论哪个平台，落到同一张表：

| 字段 | 含义 |
|---|---|
| `platform` / `accountId` | 来源 |
| `date` | 数据日期（平台口径，不是采集时间） |
| `impressions` | 展现 / 推荐 / 曝光 |
| `reads` | 阅读 / 播放 |
| `likes` / `comments` / `shares` / `collects` | 互动四项 |
| `follows` | 新增粉丝 |
| `revenue` | 收益，**分存、元显示**，拆 `ad` / `activity` / `subsidy` |
| `capturedAt` | 采集时间 |
| `completeness` | `full` / `partial` / `missing` / `unsupported`（平台不提供该指标，与取失败分开） |

单篇数据用同一套字段，多一个 `articleId` 和 `title`。

跨平台合计一律标注「相加，非去重」，不能写成「总人数」；净增粉丝用有符号数。

### 6.3 口径对照（待实测校准）

| 统一字段 | 头条 | 百家 | 大鱼 | 搜狐 |
|---|---|---|---|---|
| impressions | 展现量 | 推荐量 | 曝光量 | 推荐量 |
| reads | 阅读量 | 阅读量 | 阅读量 | 阅读量 |
| likes | 点赞 | 点赞 | 点赞 | 点赞 |
| comments | 评论 | 评论 | 评论 | 评论 |
| shares | 转发 | 分享 | 分享 | 分享 |
| collects | 收藏 | 收藏 | 收藏 | 收藏 |
| follows | 涨粉 | 涨粉 | 涨粉 | 涨粉 |
| revenue | 广告分成 | 广告 / 活动 | 分成 | 通常无 |

> 这张表必须靠 P0 的探针实测确认，不能照抄。字段名、接口路径、是否 T+1、是否有分页上限，逐项登记。

### 6.4 延迟与口径提醒

- 绝大多数指标 T+1；当天看到的是昨天的数。
- 收益通常更慢，可能 T+2 或按月结算，页面上必须标「截至 X 月 X 日」。
- 四个平台的「阅读」定义不同（点开、停留、播放），**跨平台加总只能叫「总曝光/总阅读」，不能叫「总人数」**。
- 搜狐通常没有收益字段，落 `unsupported`，**不能落成 0**。
- 本月收益只加有收益字段的平台，卡片写「账面相加，非到账」。
- 每张卡片右下角固定显示：来源平台 + 数据日期 + 采集时间。任一平台 `partial` 时，该聚合卡不显示涨跌百分比。

### 6.5 展示

| 视图 | 内容 |
|---|---|
| 总览卡 | 近 7 天阅读、净增粉丝、本月收益、异常 |
| 趋势 | 阅读 / 粉丝 / 收益三条线，可切 7 / 30 天，可单平台对比 |
| 内容榜 | 按单篇阅读排序，显示它在各平台的表现与合计 |
| 平台对比 | 同一天四个平台的阅读与互动，横向柱状 |
| 收益拆分 | 按平台、按类型（广告 / 活动 / 补贴） |
| 异常 | 登录过期、接口变更、数据缺失 |

待回评论不放进 P2 总览卡，到 P3 随互动页一起出现。

### 6.6 刷新策略

| 时机 | 动作 |
|---|---|
| 打开工作台 | **先画上次快照**，不阻塞；昨天的快照缺哪个平台才补拉 |
| 补拉 | 后台串行，一次一个平台，不并发打四家 |
| 手动刷新 | 同一平台 5 分钟冷却 |
| 后台常驻 | 不做，避免无意义请求和风控误判 |

视图只读快照，不直接读网络。打开工作台与「每日首次启动」合成一条逻辑：缺才拉，有就用，不当场连打四家。

## 7. 互动模块

### 7.1 能力

- 聚合四个平台的评论列表（P0b 探针已通的平台先显示），按平台 / 内容 / 时间 / 是否已回筛选。
- **回复入口只开头条与百家**；大鱼、搜狐的回复按钮标「只读，回复未开」。
- 每条评论右侧「回复」：把内容填进**平台页面的回复框**，由人在平台页上点发送。**工作台没有发送按钮。**
- 常用回复短语，本地保存，一键填入平台回复框。

### 7.2 红线

- 只填草稿，不自动发送；工作台不设发送按钮，不在工作台内代提交回复。
- 不做自动点赞、自动关注、互关互赞。
- 不做无审核的批量回复。
- 同一时间只操作一个平台的评论页，不并发。

### 7.3 风险说明

评论回复是**写操作**，风控等级高于读数据。回复频率独立写死，不复用发布的 `minGapMinutes`：单条至少间隔 20 秒，每平台每小时不超过 30 条，遇验证码立即停。是否发送成功只认下一次 GET 能看到这条回复，不提供「我已发送」按钮。私信暂不做，等这一块跑稳再评估。

## 8. 对象模型

### 8.1 草稿 Draft

落盘在 `%APPDATA%\sparo-store\drafts\<id>\`，目录结构兼容现有稿件格式，便于直接跑老脚本。

| 字段 | 说明 |
|---|---|
| `id` | 草稿 ID |
| `title` / `summary` | 标题、摘要 |
| `body` | Markdown 正文 |
| `images[]` | 正文配图，按出现顺序 |
| `cover` | 封面图 |
| `topics[]` | 话题 / 标签 |
| `primaryPlatform` | 首发平台；错峰与「头条首发已选则不动」都靠它 |
| `platforms{}` | 每平台启用状态与覆盖项（留空走默认） |
| `schedule{}` | 每平台独立定时 |
| `createdAt` / `updatedAt` | 时间戳 |

### 8.2 平台规则表 PlatformProfile

## 9. 架构

### 9.1 三层

```
工作台外壳（sparo://studio）
   ├─ 编辑与分发 → 三段式发布
   ├─ 数据 → 采集器 → 归一化 → 本地快照 → 视图
   └─ 互动 → 评论读取 → 回复草稿
```

### 9.2 发布链路

沿用 [三段式设计](./SOCIAL-PUBLISH-PIPELINE-DESIGN.md)：

```
填稿 stage  →  回读 review  →  发布 commit
脚本/接口       逐项断言         页面/风控 + 人确认
```

| 场景 | 做法 |
|---|---|
| 跨平台同稿 | 各平台各开一个后台标签，stage 可并行 |
| commit | 排队串行，确认单上点一次，逐平台发 |
| 同平台多篇 | 串行，中间留间隔 |
| 同平台多标签 | 不做，单窗口只有活动标签有布局 |
| 需要人在平台页操作时（提交发布、点发送） | 工作台把前台让给平台页，做完再切回来 |

### 9.3 数据采集链路

```
打开工作台（昨天快照缺失，或今天的取数还没跑）
  → 检查该平台登录态（读一个已知接口，401 就标过期）
  → 在后台标签的页面上下文 fetch 数据接口（GET）
  → 原始回包落 raw，映射成统一指标
  → 写本地快照（按平台 + 日期）
  → 视图读快照，不直接读网络
```

补拉串行，一次一个平台；已有快照先画出来，不等人。

好处：视图永远有数可看；接口挂了显示上次快照并标「数据截至」。

### 9.4 存储

指标进 SQLite（`%APPDATA%\sparo-store\metrics.sqlite`），发布任务和台账继续 JSONL。

### 9.5 失败降级

| 情况 | 动作 |
|---|---|
| 登录态过期 | 账号模块标红，其他平台照常；不重试 |
| 数据接口 4xx/5xx | 记错误码，显示上次快照 + 采集时间 |
| 接口字段变了 | 该平台标 `partial`，不静默当成 0 |
| 填稿接口失败 | 退回 UI 填稿路径 |
| 回读不符 | 停在该平台，列差异，不发布 |
| 无发布回执 | 切列表页按标题搜；5 分钟无进展，说人话关单 |
| 遇验证码 / 滑块 / 短信 | 立即停，转人工，**不绕过** |

### 9.6 代码落点

| 文件 | 分期与改动 |
|---|---|
| `adapters/*.mjs` | P0a 改读 `PlatformProfile`；P2 加 `collect()`，P3 加 `readComments()` / `draftReply()` |
| `engine.mjs` | P0a 保留现有八步与 `--from` 续跑；三段式另开一段，不在 P0a 收敛 |
| `publish.mjs` | P0a 增加 `--platforms a,b,c` 与不连浏览器的离线 `--plan` |

## 11. 关键流程

### 11.1 一稿多发

1. 写稿 → 勾平台 → 预检。
2. 预检逐平台算差异：缺图、超字数、封面不可用，当场标出。
3. 人补完 → 出确认单 → 点确认。
4. 并行 stage → 逐平台 review → 串行 commit。
5. 状态台刷新，每平台一行结果，失败给下一步建议。

### 11.2 每日数据回采

1. 打开工作台先读快照；昨天快照缺哪个平台，才补拉哪个。
2. 补拉串行，一次一个平台；能取的取昨日数据，写快照。
3. 取不到的标红，给出「去重新登录」。
4. 总览显示「数据截至」。

### 11.3 评论处理

1. 互动页聚合评论，默认只看未回复；只显示探针已通的平台。
2. 点回复 → 内容填进平台回复框 → **工作台切到平台页，由人点发送**。
3. 工作台没有发送按钮，不代提交，也没有「我已发送」按钮。只有下一次 GET 能看到该回复才标为已回复；填写失败保留内容，不丢。
4. 大鱼、搜狐只读：能看列表，不能回；按钮标「只读，回复未开」。

### 11.4 定时与错峰

- P1 不做定时、不做一键错峰，确认单不出现时间。
- 后续开放时，每平台一个时间；「一键错峰」只是把四个时间填上建议值（相隔 20–40 分钟，带抖动），另段验收，不做统一日历。
- 定时只跑 stage + 设置平台侧定时，不跑 commit；设完可关标签。
- 首发平台单独标记，其余错峰，降低同质化判定。

### 11.5 断点续跑

保留 `--from`：任一步失败，从该步续跑；续跑前先核对标题，防止串稿。

## 12. 风险与红线

### 12.1 封号风险结论

**低，但不为零。** 平台主要查内容来源、账号行为、是否绕过风控，不是「你发得快」。

当前做法：单账号、本人登录、本人设备、本人网络；请求由平台页面自己发，真 token；一篇一篇、有人确认、不存 token、不切 IP、不接管登录。从平台视角看，与人工点鼠标没有区别。

**数据采集是只读，风险比发布更低**，但同样要控频率：每天一次，手动刷新有冷却。

### 12.2 三条红线

1. **多账号矩阵 + 同稿铺量。**《互联网用户公众账号信息服务管理规定》第十八条点名禁止。
2. **绕过风控。** 伪造签名、自动过验证码、代理换 IP、指纹伪装。
3. **全自动无人值守。** 开了就不管，内容不审、评论自动回、敏感词不查。

### 12.3 降权比封号更常见

同稿同题同日发多平台，会被判非首发或重复，结果是限流而不是封号。规避：选一个平台首发、其余错峰、标题与摘要各改一版、正文开头差异化。

### 12.4 政策背景（2026）

| 时间 | 事件 | 影响 |
|---|---|---|
| 2026-03-27 | 微信公众平台新增「非真人自动化创作行为」规范 | 公众号后续接入需单独评估，不做纯自动发布 |
| 2026-03 | 小红书 AI 托管账号治理公告，纯 AI 账号直接封 | 同上，先不接 |
| 2026-05-29 公布 / 09-01 施行 | 五部门《互联网信息内容多渠道分发服务管理规定》 | 管的是 MCN / 代运营机构（需登记、签入驻协议、页面展示机构名）。我们做工具、用户发自己的号，不落入；一旦做账号托管就落入 |

### 12.5 工程约束

- 不把风控 token 存盘、不写日志。
- 不在 Node 侧直发提交，发布必须由页面发起。
- 不用 `dispatchEvent` 绕过 Sparo 的发布闸门。
- 遇验证码立即停，交给人。
- 每平台保留单日限额与最小间隔，不做毫秒级连发。
- 数据只存指标，不存原始 Cookie 与账号信息。

## 14. 不做清单

- 账号托管、代登录、代持 Cookie。
- 多账号矩阵批量分发。
- 50+ 平台堆数量。
- 服务器端代发、云端存稿。
- 破解签名、模拟指纹、代理换 IP。
- 无人值守的定时轰炸。
- 自动点赞、自动关注、互关互赞、无审核批量回复。
- 工作台内直接提交回复（没有发送按钮）。
- 竞品监控、公开页爬取。
