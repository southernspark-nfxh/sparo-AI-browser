# 最小化之后窗口仍会自己回到前台

> 2026-10-27 最小化批量测试。只登记，不改代码。
> 严重度：高。人正在用这台电脑时，Sparo 会盖住当前窗口。

## 现象

开发版 pid `34388` 启动后即最小化。任务进行中，前台多次变成 Sparo（`fg-change sparo=True`）：

- 15:10:59 S2 复制博主（后台阅读）
- 15:12:06、15:12:12 S2 关单之后
- 15:13:01、15:13:21、15:14:47 S3 写微博草稿，反复拉回，不是一次
- 15:18:45 S6 查天气
- 15:26:00 S7 查酒店和高铁
- 15:31:22 S10 打开对比报告
- 15:33:37 S12 填表

15:01:54 是启动时 `presentWindow` 的第一次 `focus()`，单独算启动，不算任务中抢焦。

15:19 前后还出现过：窗口已经最小化，但前台进程仍是 Sparo。最小化不等于不占键盘焦点。

## 和现有口径的关系

`AGENTS.md`：后台调研最小化时继续跑，完成只闪任务栏，出报告只切标签，不把窗口弹回来。

`browser.ts` 的 `restoreForCoPresence` 只打算在填表 / 回复 / 发帖确认时拉回一次。S6、S7、S10、S2 不在这条路上，仍然拉回了。S3 拉回了三次，超过「一次」。

焦点日志在测试机 `%LOCALAPPDATA%\Temp\sparo-qa\focus-log.txt`。底账使命 id 见 `docs/QA-20261027-BATCH-COMMON-SCENARIOS.md` 末尾总表。
