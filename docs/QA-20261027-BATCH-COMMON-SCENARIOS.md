## 执行规程

1. 每条句子发完后，先记下侧栏最后一句话（人话层面过不过），再查底账：
   - `missions.jsonl` 按 mission id 过滤：open 的 raw 是否就是这句（防吞句/改写）；turn 序列有没有真实 findings；close 的 reason 是什么。
   - 凡 close=done 的，对照该条的「必须看到」逐项核对交付物；凡 close=incomplete 的，缺口提示是否说人话、是否属实。
2. 每条结果记录：过 / 不过（附底账摘录）。**不过的条目不现场修**，登记成新 BUG 单（沿用 `docs/BUG-20261027-*.md` 命名），全部测完后按严重度排序。
3. 12 条全测完出一张总表：过 X / 不过 Y，每个不过的对应哪张 BUG 单、是否已在登记册。
4. 开发版全过后 `npm run dist`，安装包复测 S1/S2/S4/S6/S7 五条（★ 标记），记录安装包构建时间与 commit 号。
