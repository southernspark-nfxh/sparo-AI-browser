# 发版规程：提交 / 推送 / 打包，三段各上一把锁

> 起因：多个窗口并行改 Sparo，出现过「活干完了没提交」「提交了没推送」「打包出来的安装包不知道对应哪一版源码」。根因不是缺推送环节，而是三段都没有**强制动作**和**交付标记**。
> 适用：所有在主工作区（`D:/download/sparo上架应用商店版`）和 worktree（如 `D:/download/sparo-multi-window`）干活的窗口。

## 第一段：提交（每干完一件事就提交）

1. 一轮活只提交**自己白名单内的文件**（每份任务书 §0 都写了白名单）。
2. **禁用 `git add -A` / `git add .`**，逐文件 add。工作区里有别人的未提交改动时，整目录 add 会把别人的半成品绑进你的提交。
3. 提交信息格式：`<类型>(<模块>): <一句话>`，末尾带任务书编号，例：`feat(dxm): 判重接口解析纯函数 (R11-PartA)`。
4. **禁用 `git stash` / `reset` / `checkout -- .` / `clean`**（多写入方工作区里这几条会静默毁别人的活）。

## 第二段：推送（每轮收工就推，不是「全做完了」才推）

1. 收工三件事：`git status` 确认干净 → `git commit` → `git push origin master`。
2. 汇报里必须写一句：**「已推送 origin/master，HEAD xxxx」**。没有这句话，视为这轮没交付。
3. 推送的用途说清楚：**防丢 + 让别人能对齐**。它**不防两个窗口抢同一个文件**——那个靠文件白名单和频繁提交。
4. 推送前若远端有别人的新提交，先 `git fetch` 看清再合并；不许直接 `push --force`。

## 第三段：打包（单一出口 + 版本封板）

打包必须能回答一个问题：**这个安装包是哪一个提交打出来的。**所以：

1. **封板**：确定出货时，发版窗口做三件事——改 `package.json` 版本号 + 写 `CHANGELOG.md` 对应段落 + `git tag vX.Y.Z`，然后 `git push origin vX.Y.Z`。
2. **打包只认 tag**：从 tag 所在的干净工作树执行 `npm run dist`。
   前置三条硬检查，缺一条不许打：
   - 工作区干净（`git status --short` 无输出）
   - 与远端一致（`git status -sb` 不出现 `ahead` / `behind`）
   - tag 存在且指向当前 HEAD（`git describe --tags --exact-match`）
3. **产物带版本名**：`release/Sparo-Setup-<版本>.exe`。旧包不覆盖、不删除，目录里躺着几个包就是几个版本，一眼能分。
4. **一个出口**：任何窗口都可以提交和推送，但**打包只由发版窗口做**。其他窗口要新包就开口要，不许自己打——三个同名安装包躺在同一个目录里，谁也说不清哪个是准的。
5. **包里装什么要写明**：默认只打 `master`。要把 `feat/multi-window` 这类未合并分支带进包，必须事先说明并单独标版本，不许默认带。
6. 打完在汇报里写清：版本号 / tag / 对应提交 / 安装包路径 / 跑了哪些验收。

## 角色

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| 发版窗口（当前：总负责窗口） | 封板、打 tag、打包、写发版记录、真机验收 | 不替别的窗口提交代码 |
| 其他开发窗口 | 提交 + 推送 + 报 HEAD | 不打包、不改版本号、不动 CHANGELOG 的已发版本段落 |

## 四条硬补充（2026-11-09 19:20 立，起因见 `REVIEW-MULTIWINDOW-0.4.1-2026-11-09.md`）

1. **四项权限收口**：版本号（`package.json`）、`CHANGELOG.md`、`git tag`、打包，只有发版窗口能动。开发窗口一律不改，等发版窗口统一处理。
2. **红一个都不打**：全量测试必须绿才能打包。偶发红必须单独复跑并留原始输出归档，结论要写清"既有问题"还是"本次回归"；口头解释不算。
3. **必须做基线对照**：出现红时，先在未改动的代码上跑同两个测试文件。基线绿 → 是自己改坏的，不许说"测试前提过时"。
4. **不许为测试改生产代码**：默认驳回。确有必要（例如测试需要注入点时），必须拆成单独提交、代码注释写明"测试工装用途"、在 `docs/DECISION-POINTS.md` 登记后再合，不许夹在功能提交里默默加。
