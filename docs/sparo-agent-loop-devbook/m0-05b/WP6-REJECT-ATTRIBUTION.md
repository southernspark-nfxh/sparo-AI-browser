### 实际送入的输入缺了什么

`G8-host-read` 的 case 写了 `embeddedIn=G2 桌面页 PageDown 无进展后改看移动页`，但 `buildVerifierInput` 只传 `raw`、`constraints`、`planSummary`、`deliverables`、`evidenceIndex`、候选和区间；`embeddedIn` 不在 Verifier 输入里。

`planSummary` 只写「连续 PageDown 后**应对照** settled-0 与 settled-1」，没有写已经发生的观察和换策略。两条 settled 证据也只有 `evidenceId / kind / artifactId`，没有把「settled-1 相对 settled-0 离线字符差 0」「工具正文没有『较上次』」「+0 后改看移动页，而不是再按 PageDown」写成证据索引记录。manifest 里有 `offlineCharDelta: 0` 和 `comparedTo`，但这些字段没有随 `evidenceIndex` 或 `rangeReads` 的元数据进入模型。

所以本轮不是「同输入结果不一致」：G2 与 G8 虽共用候选和三份时间线页，G8 的约束、计划和证据索引不同。主因也不是「候选不满足契约」：候选正文明确只复制三份冻结页，8／21／1 共 30 条，与预审边界一致。

### 第二轮理由与冻结材料的对账

- `notEvidence: true` 只禁止候选自证，不取消 `candidateDeliverable` 的交付身份。同一通道已被设施明确标为 `candidate-deliverable`。
- settled-0 与 settled-1 的 358 字正文和 sha256 都相同；对本 case 的无进展观察，这正是离线字符差 0 的可核对依据，不是必须再制造两份不同正文。
- 要求补冻结页以外的 10 月 29 日更晚微博，以及称候选只是「三页各 10 条」，分别越出冻结边界并违背实际的 8／21／1 分布，不能据此改判候选无效。

这些是第二轮 Verifier 理由中的错误，但复验已经发生且没有通过，所以不能记成「真误拒未完成复验」，也不能把 `observedClass` 当作已覆盖。
