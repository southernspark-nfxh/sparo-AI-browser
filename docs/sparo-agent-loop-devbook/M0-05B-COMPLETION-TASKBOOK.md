## 3. WP6：无模型调用的拒绝归因

本阶段不得调用模型，不得新增运行结果。

新增 `docs/sparo-agent-loop-devbook/m0-05b/WP6-REJECTION-TRIAGE.md`，逐个核对旧 case、候选文件、Artifact pin、验收输入、Verifier 原始反馈、补读区间和 Close Guard。

每条拒绝必须归入且只能归入一个主因：

| 主因 | 判定依据 | 下一步 |
|---|---|---|
| `candidate_deficient` | 候选自身缺交付、缺结论或含无依据断言 | 重做候选，不改 rubric |
| `input_gap` | 冻结证据不足以形成完整交付 | 回 WP7 补输入；补不到就保留缺口 |
| `case_assembly_defect` | 原句、交付契约、候选、Artifact 或宿主场景组装错误 | 新建修正 case，旧 case 保留 |
| `facility_defect` | 设施漏传冻结契约要求的输入、区间或结果 | 只修评估设施并升版本 |
| `verifier_reject` | 独立检查确认候选有效，Verifier 仍给出原始拒绝 | 可记真实拒绝；后续是否形成误拒后通过以原始第二轮结果为准 |
| `rubric_ambiguity` | 合同无法唯一判定候选是否有效 | 停止该 case，提交单独评审 |

### 必查病例

1. **G4-report-pass**
   - Verifier 实际看到的是画像结论，还是只有“写了一份报告”的元描述和标题列表。
   - 报告文件是否作为可定位交付 Artifact 冻结，是否有哈希、证据绑定和可读区间。
   - 报告是否真正完成“画像”，而非只列 10 条标题。
   - `reportOpened` 只证明 Guard 条件，不证明报告内容合格。

2. **G6-pass-or-false-reject 与 G6-false-reject-sample2**
   - 两次使用同一首诗但结果不同，必须并排记录两轮输入是否逐字一致、模型/prompt/rubric 是否一致、拒绝理由是什么。
   - 不得为了消除波动而改写旧结果，也不得直接称模型“有误”而不给合同依据。

3. **G8-pass-or-false-reject 与 G8-pass-sample2**
   - 当前 `raw=长采集滚动，不单列原句` 是元描述，不是宿主用户任务。
   - 当前观察记录是否被错误当成宿主任务的最终交付。
   - G8 应依附 G2、G4 或 R1 的真实原句、交付契约和报告要求，同时检查 +0 与换策略观察。

4. **G2、T1、R1 probe/gap**
   - 区分“能够做一次回放”与“足以形成完整交付”。A 门通过不等于后者已经满足。
   - 不得把缺证据的 partial note 改成有效候选。
