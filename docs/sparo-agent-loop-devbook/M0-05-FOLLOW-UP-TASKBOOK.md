## 0. 目标与下一步决策

### 目标

1. 修正 M0-05A 与 M0-05B 的覆盖分工，消除“只读网页采样必须产出取消、误拒、预算耗尽”等不可能完成的条件。
2. 补齐离线回放所需的输入 Artifact、页面状态和契约夹具，证明同一冻结版本的同一区间可重复读取。
3. 在输入覆盖通过后，用评估专用离线设施回放 Actor / Verifier，取得真实模型用量、验收结果和成本。
4. 形成 M1 门所需的可审计材料；样本或计量不足时继续保持 `[TBD]`，不得强行开门。

### 本阶段唯一要支持的决策

判断 **M0-05B 成本报告是否足以与 M0-04 拆分评估、M0-06 提审记录一起进入 M1 门审**。

本阶段不判断 v2 已可发布，不切换业务流量，不选择 A/B/C 上架方案。

## 6. WP3：搭建评估专用离线回放设施

A 门通过后才允许本工作包。

### 设施边界

- 评估代码只可放在独立评估目录，例如 `tools/eval/m0-05b/`，不得进入 `src/main` 或安装包运行链路。
- 评估输出放在 `docs/sparo-agent-loop-devbook/m0-05b/`；不写入生产 Mission journal。
- 回放只读取冻结 Artifact、契约夹具和模拟工具目录，不调用浏览器副作用。
- 可以使用真实模型调用生成候选交付和执行独立 Verifier；必须走已批准的独立模型代理，不新增供应商，不下发云端 Key。
- 每次运行记录 `evaluationMode=offline_replay`、模型版本、prompt 版本、rubric 版本、回放设施版本、Artifact 清单版本和价格版本。
- trace 字段沿用 M0-03；回放标识不得被写成生产 v2 已上线。

### Verifier 输入与输出

- 不接收 Actor 自由叙述。
- 默认只给原句、约束、计划摘要、交付契约、证据索引和候选产物摘要。
- 摘要不足时只读指定 Artifact 区间，记录每次补读的 `artifactId`、区间和长度。
- 输出持久化 `VerificationResult`，并保留 `verificationId`、`rubricVersion`、逐项交付状态、缺口和置信度。
- Close Guard 结果与 Verifier 结果分开记录；Guard 失败不得写 `mission.closed` 或 `close`。

## 7. WP4：冻结并执行结果场景矩阵

### 先写预期，再运行

每个 case 在运行前冻结：输入版本、候选交付类型、预期结构断言、允许工具、终止条件、通过/失败判定和成本归属。不得看到 Verifier 结果后修改预期。

### 覆盖要求

任务行至少包括：G1、G2、G4、G6、G8、T1、P1、R1。  
每个任务行至少覆盖以下结果类；G8 可嵌入 G2/G4/R1 的滚动段，但必须单独计算覆盖：

| 结果类 | 产生方式 | 禁止做法 |
|---|---|---|
| 通过 | 候选交付满足冻结契约，Verifier 与 Close Guard 均通过 | 用长文本、`covers` 或 Actor 自报代替验收 |
| 误拒后通过 | 对预先判定有效的候选，Verifier 实际发生误拒；随后按原 rubric 补读/复验并通过 | 手写“误拒”标签、修改 rubric 制造结果 |
| 连续拒绝 | 使用存在明确缺口的候选，按测试上限连续验收，最终 `verification_exhausted` | 把连续拒绝写成用户取消 |
| 预算耗尽 | 用明确标记的 `evalBudget` 控制终止，最终 `budget_exhausted` | 把测试预算填成 O-01 或生产预算 |
| 取消/运行失败 | 由控制器执行用户取消、运行时失败/回滚等固定场景，并记录准确原因 | 自动把异常显示成用户取消 |

整套样本还必须覆盖成本分子中的 `cancelled`、用户明确按现状结束的 `incomplete`、`runtime_rollback`，不能只验证公式而没有任何对应样本。

若误拒在有效候选上实际没有发生，该格保持未覆盖；不得为了开门反复改提示词直到出现想要的结果。应记录样本量和未覆盖原因，O-01 继续 `[TBD]`。

### 特殊成本归属

- G1 若按轻量生产路径回放，独立 Verifier 调用数为 0；离线独立 Verifier 只能作为对照实验，不能计入该 Mission 的生产成本。
- P1 只生成草稿，不调用发送工具。
- G6 的候选文档来自离线生成，不作为网页证据。
- 预算、取消、挂起和恢复只改变评估控制器状态，不写生产工作单。

## 8. WP5：形成 M0-05B 成本与质量报告

新增 `M0-05B-COST.md`，至少包含：

### 版本与样本

- 任务、case、结果类和样本量。
- 模型、prompt、rubric、回放设施、Artifact 清单、价格版本与价格日期。
- 真实样本、用户输入、契约夹具分别计数。

### 单次模型调用

- Actor / Verifier / 压缩 / 其他调用类型。
- 未缓存输入、缓存输入、输出 Token；实际 Artifact 补读量。
- 可得成本、缓存命中、墙钟时延。
- 失败调用有供应商用量则记录，没有则 `[TBD]`，不得记 0。

### 完整 Mission 与组合成本

- 每个 Mission 的全部模型调用、工具重试、验收重试、证据补读和总时延。
- 分任务类型、分结果的成本；P50、P95、最大值和样本量。
- 分子包含成功、失败（含 `incomplete`）、用户取消、运行时回滚，以及仍为 `blocked` 的 `budget_exhausted` / `verification_exhausted`。
- 同一 Mission 在冻结截止时只计一次；成功数为 0 时只报总成本和样本量，不做除法。

### 质量联动

- Verifier 误放率、误拒率、平均验收轮次。
- 轻量误判率、不可逆升级率及其成本。
- 任何缺失 Token、价格、Artifact 或结果类均明确标 `[TBD]` 及影响范围。

只有任务矩阵和结果类全部覆盖、关键计量完整时，才可提出 O-01 临时 Token 数供评审；不得由执行代理自行宣布成本门通过。
