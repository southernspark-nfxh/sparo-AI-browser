## 4. WP6：无模型拒绝归因

不调用模型。只读已有 case 和 trace，新增 `m0-05b/WP6-REJECT-ATTRIBUTION.md`。对每个检查点只允许标一种主因：`候选不满足契约`、`回放输入不完整`、`设施组装错误`、`同输入结果不一致`、`真误拒未完成复验`。证据不够就标 `[TBD]`，不得为了归类再跑一次。

### G4 报告输入

对照 `cases/G4-report-pass.json` 与 `runs/wp4/G4-report-pass.json`。

已有 trace 的两轮原始 `goalSatisfied` 都是 `false`。模型理由是：证据索引里只有移动页 `e-g4-mobile`，没有报告 artifact；候选摘要不是证据；区间元数据没有正文。Trace 里另有 `kind=report_opened` 的文件读取。

要核对的是：报告文件是否进入了 Verifier 的默认输入。默认输入按设施规则不携带区间正文。若报告只出现在 trace、没有进入证据索引或允许的区间记录，主因是设施组装，不是把这轮记成误拒后通过。上百条是偏好，已有理由没有把它当成硬失败，这个判断保持。

### G6 同诗不同结果

对照 `G6-pass-or-false-reject` 与 `G6-false-reject-sample2` 的 case 和两份 trace。两份候选都是 `candidates/g6-poem.txt`，哈希 `9a873e67fd05c8bf24b9d301ace021ec5a3fe5b7f7045beb423eca0cba76c9f3`。

第一份首轮原始 `goalSatisfied=true` 并关单。第二份两轮都是 `false`，理由是候选摘要不是证据，证据索引没有诗的正文或区间。

先对两份实际送入模型的 JSON 做差异，不要只看理由文本。输入一致则主因是同输入结果不一致，禁止第三次回放来刷出拒绝或通过。输入不一致则写明差异来自 case 还是设施，仍不回放。

### G8 宿主任务绑定
