# Sparo 技能广场 — 长期产品与开发方案

> 2026-09-09 原方案：先做免费分享，不做积分与付费。
> 2026-11-04 扩展为长期市场蓝图：免费技能与付费技能共存，但分阶段开放。
> **状态：研究设计稿，未开工。下一版本建议只做 P0 + P1，不直接开放付费和任意代码技能。**
> 本机格式：[SKILL-FORMAT.md](./SKILL-FORMAT.md)。云订阅：[CLOUD-SUBSCRIPTION.md](./CLOUD-SUBSCRIPTION.md)。

## 30 秒

技能广场不是官网上的几个下载链接，而是 Sparo 的**技能发行、交易与可信运行系统**。

- 基础浏览器继续免费，自备模型 API 永远可用。
- 创作者可以上传免费或付费技能；用户搜索、查看权限、购买或安装。
- 安装后的技能进入本机技能列表，由 `match_skill` / `run_skill` 调用。
- 平台统一负责审核、签名、分发、订单、购买权益、退款、结算和下架。
- 下载量与好评可以排序，但必须防刷，不能按原始数字直接排。
- 云端模型点数与技能购货款是两本账，不互通，不再造一套“技能积分”。

**下一版本推荐范围：** 技能格式 v2、权限仲裁、签名包、本机管理、免费技能上传/审核/安装、分类搜索、评分与举报。付费只做服务端接口预留，不露购买入口。

## 1. 产品定位与边界

### 1.1 一句话定位

**Sparo 免费做“会动手的浏览器底座”，创作者提供技能，平台通过技能交易与可信分发形成长期生态。**

### 1.2 技能与 Chrome 插件的区别

Chrome 插件主要扩展浏览器和页面；Sparo 技能是**可被模型调用的任务能力包**，可以包含意图说明、参数、站点、步骤、工具调用、异常处理和人工闸门。

因此，技能广场不能只复制插件商店的页面，还必须多管四件事：

1. 模型什么时候可以选这条技能。
2. 技能实际能调用哪些浏览器能力。
3. 技能在哪些网站、哪些账号场景下可以运行。
4. 技能出错、下架或退款后，本机权益和运行状态如何处理。

### 1.3 长期做什么、不做什么

| 做 | 不做 |
|---|---|
| 免费与付费技能共存 | 把基础浏览器改成付费才能用 |
| 创作者自主定价、平台统一交易 | 作者在详情页各贴一个私人收款码 |
| 签名技能包、权限声明、运行时仲裁 | 安装后任意读取 Cookie、密码和浏览历史 |
| 官方、认证、普通创作者清晰标识 | 让付费或下载量冒充“官方推荐” |
| 真实人民币订单与购买权益 | 技能积分与云端模型点数混用 |
| 免费先试、付费后验、分阶段开放 | 第一版同时开放 UGC、支付和任意代码执行 |
| 用户主动安装、主动购买、主动授权 | 模型或 MCP 代买、代装、代评价 |

## 2. 成熟平台机制与映射

资料核对日为 **2026-11-04**。下表只描述各平台当时公开机制，不把任何平台整套照搬。

| 平台 | 已核实的成熟做法 | Sparo 应借鉴 | 不应照搬 |
|---|---|---|---|
| Chrome Web Store | ZIP 上传、商品资料与隐私声明、提交审核、延迟发布；自动与人工审核并存，已上架内容也会复审；要求最小权限、明确付费与退款说明。[cite:1][cite:2][cite:3] | 统一上传入口、发布预览、最小权限、风险触发复审、警告/下架/申诉分级 | 只审安装包、不管安装后的真实浏览器动作 |
| VS Code Marketplace | 应用内浏览，列表展示发布者、下载量与星级；发布者 ID 与扩展 ID 共同确定身份；提供版本、平台包、安装趋势和评分报告。[cite:4][cite:5] | 应用内技能列表、发布者主页、稳定身份、版本管理、创作者数据面板 | 把高权限扩展直接信任模型执行；只按下载量判断质量 |
| Raycast Store | 按名称、关键词、类别搜索，只展示兼容当前系统的扩展；安装后立即进入命令体系；支持后台更新、版本历史、截图和配置说明。[cite:6][cite:7] | 兼容性过滤、安装后立即可用、更新记录、截图、配置引导、安装前后一致的体验 | 默认所有平台、所有 Sparo 版本都能运行同一技能 |
| Stripe Connect 市场模式 | 统一店面收款、创作者入驻、平台服务费、退款与争议、向卖家结算；平台需明确商户责任和负余额风险。[cite:8] | 订单、权益、退款、创作者结算采用同一交易账本 | 把支付理解成一次回调；忽略退款、拒付和结算对账 |
| Microsoft Store | 政策覆盖数字店面、可测试性、兼容性、隐私和评分操纵；具体上架版本仍需按提审时规则复核。[cite:9] | 渠道规则进入构建与验收，保留测试账号和审核材料 | 用页面隐藏技巧绕过商店规则 |
| GPT Store / 自定义 GPT | 官方资料表明其发布和商业机制在 2026 年已发生变化，不能作为稳定的付费市场范本。[cite:10] | 参考低门槛创建、分类发现和外部动作需授权的思路 | 把其早期商业化传闻当作 Sparo 收费依据 |

**归纳结论：** 上传、分类、评分、版本和交易都有成熟零件；Sparo 真正需要自建的是“**权限声明 → 运行时仲裁 → 人工确认 → 下架失效**”这条安全链。

## 3. 用户、创作者与平台角色

| 角色 | 核心目标 | 主要能力 |
|---|---|---|
| 普通用户 | 找到可信技能，安装后浏览器更会做事 | 搜索、筛选、看权限、安装、购买、启用、评分、举报、退款 |
| 创作者 | 低成本制作技能并获得用户与收入 | 创建、调试、上传、定价、查看数据、更新、回复评价、结算 |
| 官方运营 | 保证市场有内容、有质量、有秩序 | 精选、分类、审核、活动、违规处置、创作者扶持 |
| 安全审核 | 阻止恶意自动化与隐私泄露 | 静态检查、沙箱复现、权限复核、举报处理、撤销签名 |
| 支付与财务 | 保证每笔收入可核对、可退、可结算 | 订单、支付回调、退款、拒付、结算、税务与发票资料 |
| 渠道审核 | 保证安装包符合发行渠道政策 | 渠道差异、价格与付款界面检查、测试材料 |

## 4. 用户侧完整闭环

### 4.1 发现

技能广场同时提供：

- **Sparo 应用内广场**：主要使用场景，可搜索、筛选、安装和管理。
- **官网广场**：用于公开传播、搜索收录和分享详情页；登录后可购买，安装时唤起或指引打开 Sparo。
- **侧栏克制推荐**：用户明确说“有没有技能可以做……”时才推荐；不得在正常任务中反复插广告。

首页不堆几十个分类，首屏只保留：

1. 搜索框。
2. 官方精选。
3. 常用分类。
4. 免费 / 付费筛选。
5. 热门、好评、新上架、最近更新入口。

### 4.2 技能详情页

安装或购买前必须看清：

- 技能名称、一句用途、适用场景和不适用场景。
- 作者、官方/认证标识、版本、更新时间与更新记录。
- 免费或实际售价、购买后包含什么、后续升级规则。
- 声明站点、声明动作、风险等级和隐私说明。
- 参数示例，例如“输入商品名，输出三家比价报告”。
- 截图或演示，但演示不得伪造执行结果。
- 安装量、评分、评价数、兼容性、举报入口。
- 已知缺口、支持方式、退款规则。

**权限说明要写成用户能懂的话。** 例如不要只写 `execute_primitives`，而要写“会在指定网页填写表单，但不会替你点击提交”。

### 4.3 免费安装

```text
点安装
  → 检查 Sparo 版本、系统与工具协议兼容性
  → 展示站点与动作权限
  → 用户确认
  → 下载签名包并校验哈希
  → 写入本机社区技能区
  → 安装成功回执
  → 出现在「已安装技能」和 match_skill 可选集合
```

默认安装后启用；涉及高风险权限的技能可以先安装为“待授权”，用户逐项确认后才启用。

### 4.4 付费购买

```text
点购买
  → 确认作者、技能、版本、价格、升级与退款规则
  → 使用 Sparo 账号登录
  → 平台统一收银台付款
  → 服务端确认真实订单
  → 生成 entitlement（购买权益）
  → 客户端拉取权益
  → 按免费安装同一条签名分发链安装
```

**付款成功不等于安装成功。** 订单、权益、包下载、安装回执必须是四个独立状态，任何一步失败都能继续或恢复，不能重复扣款。

### 4.5 安装后管理

「我的技能」至少支持：

- 启用 / 停用。
- 查看与修改可撤回的授权。
- 更新、查看更新内容、安装历史版本。
- 卸载、清除该技能自己的本机数据。
- 恢复已购买技能。
- 评价、修改评价、举报、申请退款。
- 查看来源、签名状态、当前版本和兼容性。

官方技能、社区技能和本机开发技能分区保存，禁止社区包覆盖官方同名包。

### 4.6 下架、退款与撤销的区别

| 事件 | 新用户 | 已安装且已购买用户 |
|---|---|---|
| 作者停止销售 / 普通下架 | 不再展示购买入口 | 保留最后一个安全版本的下载与使用权 |
| 技能不兼容新版本 | 不再向不兼容用户展示 | 标为不可用，允许回退 Sparo 或等待兼容版 |
| 退款成功 | — | 权益撤销，联网同步后停用付费技能 |
| 恶意或严重违规撤销 | 立即下架 | 通过撤销清单禁用；不能只把网页隐藏 |

普通下架与恶意撤销绝不能混用，避免作者不维护就把老用户已购技能远程清空。

## 5. 创作者侧完整闭环

### 5.1 两条创作路径

**路径 A：整理本机技能，适合普通创作者。**

```text
本机已有技能 / 经验
  → 人点「整理为技能」
  → 补齐标题、用途、参数、站点、已知缺口
  → 预览将公开的每一步
  → 自动检测并剥掉密码、验证码、邮箱、Token、个人链接
  → 在本机样例页测试
  → 上传免费技能
```

原始 `lessons.json` 永远不自动上传；没有人的“分享/发布”动作，数据只留本机。

**路径 B：开发者工具，适合专业创作者。**

提供模板、校验器、模拟页面、测试样例、打包器和调试日志。创作者先在本机开发模式运行，再上传签名前的发布包。

第一版只接受声明式 JSON 与受支持模板，不接受任意 Node.js、Electron 或远程脚本。

### 5.2 上传步骤

1. 登录并完成创作者身份与收款资料验证；免费发布可以先只做账号验证。
2. 创建技能，系统分配不可变的 `publisher_id + skill_id`。
3. 上传包，填写分类、说明、截图、隐私、支持方式和兼容性。
4. 自动校验格式、权限、域名、敏感内容和包安全。
5. 在隔离样例环境复现核心流程，保留测试证据。
6. 作者查看公开预览，确认没有隐私后提交审核。
7. 审核通过后发布；作者可选择立即发布或稍后手动发布。
8. 查看安装、评分、失败举报与收入数据，提交后续版本。

### 5.3 更新规则

- 技能 ID 不变，版本使用 SemVer。
- 修复包、功能包、权限变化包分开审核。
- 新增域名、外部写动作、文件上传或网络请求，必须重新审核并请用户重新授权。
- 安全修复永远免费，不得借安全补丁强制老用户二次购买。
- 作者不能单方面删除所有历史包；平台至少保留审核证据和最后一个安全版本。
- 自动更新只适用于权限未扩大且兼容的版本；重大版本由用户主动选择。

### 5.4 创作者后台

- 发布状态、驳回原因、审核证据和申诉入口。
- 安装趋势、成功安装数、评分分布、版本分布。
- 举报、退款、兼容性问题和作者回复。
- 付费后展示订单总额、退款、平台服务费、税费与预计结算净额。
- 不展示用户姓名、邮箱、网页正文、任务内容或浏览历史。

## 6. 分类、搜索、排序与评价

### 6.1 分类体系

第一版使用固定一级分类，标签作为补充，避免创作者自创几千个空分类。

| 一级分类 | 示例 |
|---|---|
| 电商运营 | 店小秘、商品采集、比价、客服草稿 |
| 内容创作与发布 | 小红书、公众号、素材整理、跨站贴图 |
| 办公效率 | 飞书、表单、邮件草稿、网页笔记 |
| 信息调研 | 多站检索、对比、报告、文献整理 |
| 出行与生活 | 酒店、机票、火车、天气、路线 |
| 网页工具 | 翻译、打印、截图、下载、整页整理 |
| 开发与数据 | 开发者工具、结构化提取、API 辅助 |
| 其他 | 有真实功能但不属于以上类别 |

每条技能至少一个一级分类，可另有站点、场景、免费/付费、官方/认证、风险等级、兼容版本等筛选。

### 6.2 搜索

搜索索引包含标题、别名、用途、作者、分类、站点和示例口令；权限文本只用于筛选，不让作者堆无关热词抢占结果。

搜索排序先看相关性与兼容性，再看质量。付费身份、作者缴费和广告不得暗中提升自然排名。

### 6.3 排序口径

| 排序 | 推荐口径 | 防刷要求 |
|---|---|---|
| 综合推荐 | 相关性、兼容性、编辑精选、评分置信度、近期有效安装、维护状态 | 不公开固定权重，异常流量先隔离 |
| 下载最多 | 去重后的成功安装数；可分总量与近期榜 | 同一账号反复装卸不重复计数，失败下载不计 |
| 好评最多 | 已验证安装/购买评价数量与贝叶斯调整分共同排序 | 作者不能评自己，退款与作弊订单不计 |
| 新上架 | 首次审核通过时间 | 改标题、重传同包不能重新当新品 |
| 最近更新 | 新版本审核通过时间 | 只改描述不冒充功能更新 |

评分不能直接用“5 星但有 1 条评价”压过“4.8 星且有大量评价”。采用贝叶斯平均：

\[
S = \frac{v}{v+m}R + \frac{m}{v+m}C
\]

其中 `R` 是技能平均分，`v` 是有效评价数，`C` 是同类别整体平均分，`m` 是根据真实评价分布设定的置信门槛。页面同时展示原始均分和评价数，不把调整分伪装成用户均分。

### 6.4 评价与反作弊

- 只有成功安装过的账号能评价；付费技能标注“已购”。
- 一个账号对一条技能只保留一条当前评价，可修改并保留编辑记录。
- 作者可公开回复一次，不能删除差评；用户和作者都可举报违规内容。
- 自买自评、集中刷号、退款订单、激励好评、异常设备群进入风控复核。
- 不用单一 IP 或单一设备字段直接判作弊，避免误伤共享网络。
- 精选、热门、好评、官方认证是四种不同标识，不互相替代。

## 7. 免费与付费商业设计

### 7.1 免费技能

- 创作者选择免费，所有兼容用户可安装。
- 免费技能也必须走同一套签名、权限和审核链。
- 允许作者提供自愿支持链接，但不得在技能内诱导用户绕开平台购买“解锁码”。
- 官方可以设精选、基础必备和新人合集，先解决冷启动。

### 7.2 付费技能

第一阶段只支持**一次性购买**，不急着做订阅。

推荐权益规则：

- 购买者本人登录的自己的多台设备可恢复使用，不做逐台重复收费。
- 包含所购大版本内的功能更新与全部安全修复。
- 新大版本可以另行定价，但旧的安全版本继续可用。
- 持续消耗作者服务器或第三方 API 的技能，必须把额外费用单独讲清；后续再评估订阅，不把成本藏进 Sparo 模型点数。

作者可以设 1 元、2 元、5 元这类低价，但正式开放前必须按真实支付报价核算手续费、退款与结算成本。必要时提供购物车或技能合集摊薄单笔成本，不能用虚假高下载量弥补低价经济模型。

### 7.3 平台收入

平台从真实交易中收取公开的服务费，创作者后台展示完整计算过程。抽成比例不在客户端或技能包中写死，付费内测前根据支付通道、退款、审核和结算成本单独拍板并公布。

平台服务费不能只写成“抽成”，它对应真实责任：

- 商店分发与签名。
- 审核、复审、举报和安全撤销。
- 收银、订单、权益、退款与争议。
- 创作者入驻、结算与对账。
- 客服和渠道合规。

### 7.4 两本账永远分开

| 账本 | 买什么 | 是否互通 |
|---|---|---|
| 云端模型点数 | 模型任务消耗 | 与技能购货款不互通 |
| 技能订单 | 创作者技能的使用权益 | 不能用模型点数抵扣 |

客户端不保存云端模型真 Key，不保存银行卡数据，不在技能包内写价格。价格与权益以服务端记录为准。

## 8. 支付、权益、退款与结算

### 8.1 统一交易账本

核心实体：

- `Skill`：长期稳定的技能身份与详情。
- `Release`：某一次版本、权限、兼容性与审核结果。
- `Package`：签名包、哈希、存储位置和撤销状态。
- `Order`：用户、技能、金额、支付状态和渠道。
- `Entitlement`：用户实际拥有哪个技能的何种使用权益。
- `Refund / Dispute`：退款、拒付与责任状态。
- `Payout`：创作者可结算金额、已结算金额和调整项。
- `Review / Report`：评价、举报与处置记录。
- `AuditEvent`：审核、改价、下架、撤销、人工改账的完整审计。

支付回调必须幂等，乱序回调不能覆盖较新的订单状态。客户端显示“已购买”只能来自服务端权益，不接受本地布尔值或模型口述。

### 8.2 收银台

- 使用支付服务商托管或受控收银页面，Sparo 不直接接触卡号。
- Agent 不得代用户确认支付，支付、登录和验证码仍走人工闸门。
- 非微软渠道可以按现行规则在 Sparo 窗口或官网付款。
- `STORE_CHANNEL=msft` 继续隐藏价格与付款界面；是否展示已购权益、如何恢复购买，提审前按当时政策复核，不擅自改变现有渠道口径。

### 8.3 退款

统一退款政策至少覆盖：重复购买、未到账、描述严重不符、声明环境下不可运行、恶意或违规下架。

- 平台统一受理，创作者可提交说明，但不能各自写一套霸王条款。
- 退款成功后撤销权益并处理创作者结算冲回。
- 已结算后发生退款或拒付，需要明确的负余额与后续抵扣规则。
- 审核证据只使用订单、版本、兼容性和脱敏运行结果，不上传用户网页正文来“证明不能退”。

### 8.4 创作者结算

付费开放前必须完成：创作者实名与收款验证、结算周期、起结金额、退款准备、拒付处理、税务与发票流程、异常冻结和申诉。

支付服务商可替换，订单与权益账本不能被某一家服务商绑死。Stripe Connect 的市场模式可作架构参考，不代表最终选定该供应商。[cite:8]

## 9. 技能包格式 v2

现有 `declared_domains`、`declared_actions`、`human_gates`、`params`、`steps`、`fallbacks`、`knownGaps` 保留并升级，不推倒重来。

| 字段组 | v2 需要表达的内容 |
|---|---|
| 身份 | `publisher_id`、不可变 `skill_id`、显示名、作者、来源 |
| 版本 | SemVer、`min_sparo_version`、工具协议版本、支持系统、更新说明 |
| 展示 | 分类、标签、别名、用途、示例、截图、已知缺口 |

| 执行 | 参数、步骤、回退、人工闸门、预期交付物 |
| 合规 | 隐私链接、支持链接、第三方服务与素材权利声明 |
| 分发 | 包哈希、签名、发布时间、审核编号、撤销状态 |

价格、折扣、购买权益和创作者结算资料保存在服务端，不放进可编辑技能 JSON。

`human_gates` 不是作者可以省略的提示文字，而是系统级底线。作者声明得再少，运行时的支付、登录、验证码、不可恢复删除等闸门仍然存在。

## 10. 权限模型与运行时仲裁

### 10.1 风险分级

| 等级 | 能力示例 | 默认策略 |
|---|---|---|
| R0 公共读取 | 打开声明站点、读取页面、等待 | 安装时展示，运行时限制域名 |
| R1 本地产出 | 生成报告、保存截图、下载图片 | 展示保存位置与数量限制，不上传 |
| R2 网页草稿 | 填表、写回复、注入标题正文 | 必须读回或回执；未授权发送时只留草稿 |
| R3 外部写操作 | 发布、发送、上传、删除、改设置 | 沿用 `execMode` 与 `request_confirm`，技能无权放宽 |
| R4 禁止自动化 | 支付、登录凭据、验证码、Cookie/密码提取 | 技能不得执行，立即暂停交给人或拒绝 |

自动执行模式下，发布/发送按现行用户授权规则处理；支付与不可恢复删除仍需独立确认。技能包、模型或外部 MCP 都不能本地代答确认。

### 10.2 每次调用都校验

```text
模型选择技能
  → 运行时检查技能已安装、已启用、未撤销且兼容
  → 检查当前步骤是否在声明动作内
  → 检查最终 URL 是否在声明域名内（含重定向后的 URL）
  → 检查文件、上传、网络和外部写权限
  → 需要人工闸门时暂停
  → 执行并留下脱敏审计记录
```

不是安装时检查一次就永久放行。模型不能通过改参数、短链、跳转或另一段提示绕过权限。

### 10.3 特殊红线

- 技能指令属于不可信输入，不能覆盖系统提示和人工闸门。
- 不读取浏览器 Cookie 仓库、密码库和其他技能私有目录。
- 不自动上传本机经验、任务正文、账号信息或素材库。
- 不通过隐藏远程配置把已审核步骤替换成新步骤。
- 不在后台做监控式采集，不自动定时截屏。
- `set_file` 只能使用用户明确提供的文件路径，上传目标也必须在声明域名内。
- 模型和 MCP 不得代买、代装、代授权、代评分。

### 10.4 任意代码技能后置

未来若确需 JavaScript 技能，必须单独立项：隔离 Worker、无 Node/Electron 权限、无 Cookie、受限网络、超时与内存限制、签名与源码审核。不能把“开放平台”理解成直接把 Electron 主进程交给第三方。

## 11. 总体技术架构

```text
官网 / Sparo 技能广场 / 创作者后台
                 │
                 ▼
       技能市场服务（独立 /skills 路由）
       ├─ 目录、搜索、分类、详情
       ├─ 上传、包存储、签名、版本、兼容性
       ├─ 审核、举报、撤销、申诉
       ├─ 订单、权益、退款、结算
       └─ 安装回执、评分与风控
                 │
                 ▼
 Sparo 客户端技能中心
       ├─ 已安装仓库与购买权益缓存
       ├─ 签名/哈希验证与更新器
       ├─ 兼容性检查与权限管理
       └─ 撤销清单同步
                 │
                 ▼
 match_skill / run_skill → 权限仲裁 → 现有浏览器工具与人工闸门
```

### 11.1 客户端落盘建议

社区技能与官方包隔离，按发布者、技能和版本保存；本机开发技能另有明确标识。安装过程先写临时目录，验签通过后原子切换，失败不得留下半包覆盖旧版本。

客户端可缓存权益以支持断网启动；断网时不得因无法联系服务器就立刻收回已购技能。恶意撤销使用带签名的撤销清单，联网后优先同步。

### 11.2 服务端边界

服务可继续挂在独立 `sparo-pay` 旁的 `/skills` 路由，但技能权益必须独立于云端模型配额。支付密钥、签名私钥和创作者收款资料只在服务端，客户端仓库不放密钥。

### 11.3 数据最小化

默认只收集目录、订单、安装回执、评价和审核所需数据。技能成功率、失败原因等运行指标若需要采集，应使用单独、明确、可关闭的匿名同意，不带页面正文、账号、URL 参数或任务内容。

## 12. 审核、复审与安全处置

### 12.1 审核流水线

| 阶段 | 检查内容 |
|---|---|
| 包检查 | 格式、大小、路径穿越、哈希、签名、恶意压缩包、隐藏文件 |
| 静态检查 | 域名、动作、敏感字段、远程代码、混淆、隐私与权限一致性 |
| 动态检查 | 样例页执行、最终跳转域名、权限外调用、重复填写、假完成 |
| 内容检查 | 功能真实、描述一致、截图脱敏、无灌水、无侵权与误导 |
| 人工复核 | 新创作者、高风险权限、外部写、付费首发、重大代码或权限变化 |
| 上架后复审 | 举报、异常退款、异常评分、权限变化、定期抽检 |

Chrome 的“新开发者、危险权限、重大变化需要更仔细审查”和上架后复审机制可作为直接参考。[cite:2]

### 12.2 处置分级

- **驳回修改**：尚未公开，不影响老版本。
- **警告限期整改**：轻微问题，保留申诉和整改记录。
- **停止新安装**：兼容性或质量存疑，老用户暂不扩大影响。
- **普通下架**：停止销售，已购用户保留最后安全版本。
- **安全撤销**：恶意或严重风险，本机同步后禁用。
- **创作者冻结**：重复恶意发布、支付欺诈或刷榜，保留申诉通道。

所有人工改状态、改价、改权益和改结算都必须有审计日志，不能只改数据库一行。

## 13. 分阶段路线图

不用日期倒排，使用验收门推进；上一道门没过，不开下一阶段。

**前置闸门：** 现行安装包人测与 G1/G2/G3 验收未完成前，不开 P1 社区；P0 只做线下底座，不改线上环境，不把未验收能力塞进安装包。

### P0 — 技能底座

**范围：** 格式 v2、权限模型、签名与哈希、本机技能管理、兼容性、撤销清单、开发校验器、官方种子技能迁移。

**不做：** 公开上传、支付、任意代码。

**出口：** 现有官方技能全部经过权限仲裁；未声明域名、篡改包、越权动作、重定向绕行均有测试；G1/G2/G3 不受破坏。

### P1 — 免费技能封闭内测

**范围：** 邀请创作者、免费上传、人工审核、应用内与官网列表、分类搜索、安装/停用/更新/卸载、评分、举报。

**不做：** 付费、作者结算、公开注册即发。

**出口：** 一台机器发布、另一台安装并运行；无隐私自动上传；恶意样本被拒；普通下架和安全撤销行为正确。

### P2 — 免费技能开放

**范围：** 创作者注册、风险分级审核、完整搜索排序、作者后台、版本历史、申诉、反刷量与反刷评。

**出口：** 自评、反复装卸、集中刷号、重传冒充新品不能操纵榜单；权限扩大必须重新授权；审核与处置可追踪。

### P3 — 付费技能封闭内测

**范围：** 邀请高质量创作者、真实货币、一次性购买、统一权益、退款、结算、对账、渠道适配。

**出口：** 重复/乱序回调不重复发货；重装可恢复；退款会撤销；普通下架不伤害老买家；恶意撤销可禁用；微软渠道无价格与付款界面。

### P4 — 付费技能开放

**范围：** 开放创作者结算、合集与购物车、活动、推荐、完整风控和财务运营。

**出口：** 真实订单全链路对账；退款、拒付、负余额、税务与发票流程完成演练；低价技能的成本模型经过真实支付报价核验。

### P5 — 高级生态

**范围候选：** 沙箱代码技能、持续服务型订阅、团队/企业私有技能广场、组织统一授权和审计。

每一项独立评审，不因 P4 完成而自动开工。

## 14. 各阶段验收矩阵

### 14.1 包与运行安全

- 未签名、哈希不符、包路径穿越、超大压缩包、隐藏远程脚本全部拒绝。
- `evil-ctrip.com`、`ctrip.com.evil.com`、裸 IP、短链与重定向不能绕过声明域名。
- 技能提示词要求忽略系统规则时，人工闸门仍有效。
- 未声明的点击、上传、网络请求不能执行。
- 停用、卸载、撤销后，`match_skill` 不再把该技能当成可用能力。
- 权限扩大版不会被静默自动更新。

### 14.2 社区与榜单

- 同一账号反复装卸只形成规定的去重安装口径。
- 未安装、作者自评、退款与作弊订单不进入有效评分。
- 修改描述不会刷新“新上架”。
- 作者不能删除差评，平台处置有理由与申诉记录。
- 社区包不能覆盖官方包，本机原始经验不会自动公开。

### 14.3 交易与权益

- 成功、失败、取消、重复回调、乱序回调、断网恢复都有唯一正确终态。
- 支付成功但安装失败时可继续安装，不再次扣款。
- 换机与重装可恢复已购技能。
- 退款、普通下架、安全撤销三种结果严格不同。
- 创作者结算与订单、退款、拒付能够逐笔对账。
- `msft` 构建扫描不到价格、购买按钮和付款页。

### 14.4 回归要求

权限仲裁触及任务执行链时，不能只看单测绿；按 [QA-GOLDEN-SCENARIOS.md](./QA-GOLDEN-SCENARIOS.md) 复测受影响场景，安装包至少复测 G1、G2、G3。涉及本地提前判断或绕行的规则，先登记 [DECISION-POINTS.md](./DECISION-POINTS.md)。

## 15. 市场健康指标

不把下载量当唯一北极星。分五组看：

| 维度 | 指标 |
|---|---|
| 发现与安装 | 搜索到详情转化、详情到安装转化、安装成功率、兼容性失败率 |
| 技能质量 | 有效评价分布、卸载、举报、版本更新、用户主动反馈的任务成功/失败 |
| 创作者生态 | 审核通过与驳回原因、持续维护作者、收入分布、退款与争议 |
| 平台商业 | 交易额、平台服务费、退款、拒付、结算差额、单一作者/技能收入集中度 |
| 安全 | 越权拦截、恶意包拦截、撤销覆盖、重复违规作者 |

运行成功指标若依赖匿名客户端事件，必须注明采集同意与样本偏差，不能用服务端下载量冒充“任务成功”。

## 16. 主要风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 冷启动没有好技能 | 广场空、用户来一次就走 | 官方种子 + 邀请创作者 + 垂直分类精选，先于公开 UGC |
| 低价付费覆盖不了成本 | 作者与平台都留不住 | 真实费率核算、合集/购物车、公开结算口径，不盲目承诺比例 |
| 刷下载与刷好评 | 好技能被埋没 | 成功安装去重、验证评价、贝叶斯评分、异常流量隔离 |
| 恶意技能窃取账号 | 用户损失与平台信任崩溃 | 声明式优先、最小权限、运行时仲裁、签名撤销、禁止 Cookie/密码 |
| 网站改版导致技能失效 | 差评与退款增加 | 兼容性标识、样例回归、版本回退、作者维护状态、停止新安装 |
| 作者下架伤害老买家 | 已购权益失效 | 普通下架保留最后安全版本，只有安全风险才远程禁用 |
| 支付与模型点数混淆 | 客诉与账目混乱 | 两本账、真实货币、权益独立、界面分开 |
| 渠道审核失败 | 安装包无法发布 | 渠道构建隔离、提审前复核政策、价格与付款界面自动扫描 |
| 审核成本随 UGC 爆炸 | 上架慢、漏审 | 风险分级、自动测试、官方/认证作者记录、抽检与举报复审 |
| 创作者抄包与侵权 | 原创者流失 | 发布者身份、包相似与来源证据、投诉申诉、重复违规处置 |

4. 分类、搜索、安装量与评分去重口径。
5. 审核、举报、普通下架、安全撤销和申诉。
6. 订单/权益的数据模型预留，但不开支付入口。

### 明确推迟

1. 付费公开上架与作者分成。
2. 技能订阅、技能积分、与云端点数互通。
3. 任意 JavaScript / Node.js 技能。
4. 个性化广告排名、作者买量。
5. 团队私有市场与组织管理。

**最终建议：先把“别人愿意上传、用户敢安装、安装后真能跑”做成，再开付费。付费不是第二阶段的第一天功能，而是免费生态通过质量门后的独立商业阶段。**

---

## 18. 研究限制

- 本方案使用公开官方资料，没有对这些平台进行真实创作者付款、退款或结算实测。
- 支付通道费率、国内创作者结算、税务与发票需要供应商正式报价和法务/财务核验，因此本文不虚构抽成比例与成本数字。
- Microsoft Store 规则会变化，`msft` 渠道在付费内测前必须重新核对提审时有效条款，不以本文代替平台审核结论。
- 排序权重与贝叶斯门槛需要真实数据分布后校准，不能预先编造“最佳权重”。
