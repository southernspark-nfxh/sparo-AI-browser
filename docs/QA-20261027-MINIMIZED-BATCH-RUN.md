## 0. 总原则

- 用户正在用这台电脑。**全程不得抢占前台焦点**：Sparo 窗口启动后即最小化，之后所有操作不得把它拉回前台、不得向其他窗口发送任何键鼠。
- 驱动方式：**只用 Computer Use（UIA）的元素级动作**——`set_value` / `type_text` / `press_key` / `click` 全部带 `element_id`，通过 `get_app_state(pid)` 拿树后按元素 ID 操作。
- **坐标动作（x/y click）全程禁用**。2026-10-27 上午实测教训：坐标点击落在当时的焦点窗口（Cursor），一句 URL 被打进了用户的 Cursor 聊天框。坐标点击只作用于前台窗口，与最小化要求根本冲突。
- 观察方式：`get_app_state(pid, disableScreenshot:false)` 对非前台窗口同样能拿到截图和 UI 树（已实证）。截图只用于核对 Sparo 自己，不要求窗口在前台。
- 如果元素级动作在最小化状态下个别不生效（某些控件要求可见），允许把 Sparo 恢复为**非激活的正常窗口**（不 maximize、不抢焦的操作优先），仍禁止坐标点击；每次恢复/最小化记入执行日志。

## 1. 环境准备

1. `npm run start` 起开发版（当前源码，含五笔修复）。等侧栏出现、首页加载完。
2. 确认登录态：微博、携程/12306 所需登录沿用 `%APPDATA%\sparo-store` 的既有 profile；若微博未登录，停下来请用户登一次（这是唯一允许的登录人工介入），登录后继续。
3. 拿到 Sparo 进程 pid（`list_apps` 里找 `node_modules\electron\dist\electron.exe` 那一项，**不是** `D:\Program Files\Sparo\Sparo.exe`）。
4. 把窗口最小化，之后全程用 pid + element_id 驱动。
5. 侧栏输入框定位法：UI 树里找 `edit "说要做什么…"` 占位文本的元素 ID（每次操作前重新取树，ID 会变，不许缓存复用上一次的）。

## 2. 逐条执行规程（对批次书 S1-S12 逐条）

每条按以下节拍：

1. 发句前：记录当前时间、前台进程 pid（证据：不是 Sparo）。
2. 元素级把句子打进侧栏输入框并回车。
3. 等待期间用 `get_app_state` 轮询侧栏尾部（间隔 ≥15 秒，不打断任务）；**单条最长挂账 10 分钟**，超时无终态记 blocked 并摘录最后状态，继续下一条。
4. 关单后核底账：`Get-Content "$env:APPDATA\sparo-store\missions.jsonl"` 按 mission id 过滤——
   - open 的 `raw` 是否就是这句原句（防吞句/防改写）；
   - turn 序列 findings 是否非空、cap 是否都有手（不许出现「这一步没有对应的手」）；
   - close 的 reason（done / incomplete / stall 关单的人话提示）；
   - 对照批次书该行的「必须看到 / 不许看到」逐项打勾。
5. 记录：过 / 不过（附底账摘录）/ blocked（原因）。**不过的条目不现场修**，另开 `docs/BUG-20261027-*.md` 登记。
