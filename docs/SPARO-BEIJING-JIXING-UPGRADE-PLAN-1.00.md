# SPARO 浏览器·北京吉星升级方案（1.00 版本）

- 方案版本：1.00
- 方案性质：产品形态基线
- 适用产品：SPARO 浏览器
- 制定日期：2026-11-18
- 当前状态：已定方向，作为后续产品修改与开发任务书的上位依据

> **核心定义：一个指挥室 + 多个页面工作间；一个页面同一时刻只能有一个任务、一个执行 Agent。**

---

## 0. 文档地位与版本规则

### 0.1 方案地位

本方案承接此前 0.x 阶段的产品探索，正式确定 SPARO 浏览器 1.00 阶段的产品形态。

本方案确定后，后续产品修改、界面调整、开发任务书和验收标准，均应以本方案为依据，不得在实现过程中擅自改变已经确定的核心原则。

### 0.2 版本边界

- 1.00 之后的所有 1.x 版本，均沿用本方案定义的产品形态。
- 1.x 版本可以完善交互、性能、稳定性和功能覆盖，但不得改变本方案的核心结构。
- 如果未来需要改变“指挥室 + 页面工作间”的总体形态，或改变“一页一任务一 Agent”等核心原则，必须升级为 2.00 方案，不得在 1.x 中静默变更。

### 0.3 方案版本与安装包版本的关系

本文件的“1.00”是**产品方案版本**，不是安装包版本号，也不要求将安装包版本回退或覆盖为 1.0.0。

安装包继续按照现有发布规则递增版本；每次打包递增 patch，不复用旧版本号覆盖旧安装包。

### 0.4 与旧设计稿的关系

此前多 Agent 设计稿中，与本方案不一致的内容，以本方案为准，尤其包括：

1. 颜色不再用于区分不同 Agent，而是统一用于表达任务状态；Agent 身份通过名称展示。
2. 会话隔离不再只按 Agent 区分，而是进一步落实到页面和任务；同一 Agent 的多个页面任务也不得混用对话。
3. 页面不允许被其他 Agent 或其他任务抢占；新任务默认新开独立页面，复用空闲页是例外。

本方案是产品形态基线，不代表相关功能已经上线。具体实施仍需依据现行代码另出开发任务书，并单独完成测试与验收。

## 1. 升级背景

此前的产品思路，是希望通过一个聊天框管理所有网页。

但聊天框是单线、串行的，网页任务却是多线、并行的。页面一多，就会出现：

- 不同页面的上下文混在同一条历史里；
- 用户需要反复解释“我说的是哪个页面”；
- Agent 容易误判当前操作目标；
- 各页面的执行过程互相刷屏；
- 用户难以一眼看出哪些页面在工作、哪些卡住、哪些等待自己处理；
- 多 Agent 同时工作时，可能争抢同一个页面，互相覆盖操作。

因此，1.00 不再继续强化“一个聊天框包管所有页面”，而是升级浏览器本身的产品结构。

---

## 2. 总体产品形态

SPARO 浏览器 1.00 由两类视图组成：

### 2.1 指挥室

用于查看整个浏览器的实时情况，并统一下达命令。

### 2.2 页面工作间

每个网页都是一个独立工作单元，拥有自己的任务状态、执行 Agent 和专属聊天。

### 2.3 两级聊天入口

- **总指挥聊天**：管所有页面、跨页面任务和全局异常。
- **页面专属聊天**：只管当前页面和当前页面上的任务。

聊天入口仍然采用右侧侧栏，不把聊天输入框嵌入网站正文，避免遮挡网页或破坏网站布局。

---

## 3. 指挥室：全局总览与统一指挥

### 3.1 固定主标签

指挥室是一个固定主标签，始终作为全局入口存在。

指挥室的主区域不再打开普通网页，而是显示整个浏览器的实时总览。右侧保留总指挥聊天侧栏。

### 3.2 全页面实时总览

总览按照“页面”组织，而不是按照 Agent 组织。因为同一个 Agent 可能同时在多个页面执行不同任务。

每个页面条目至少显示：

- 页面名称或网站名称；
- 当前执行 Agent；无 Agent 时明确显示无；
- 当前任务状态；
- 当前正在执行的步骤；
- 最近更新时间；
- 完成、异常、等待人工等结果提示。

示例：

| 页面 | 执行者 | 状态 | 当前动作 |
|---|---|---|---|
| 店小秘商品 A | Cursor | 进行中 | 正在编辑商品，准备上品 |
| 店小秘商品 B | Cursor | 进行中 | 正在编辑另一个商品 |
| 百度 | 无 | 静止 | 当前没有任务 |
| 百家号 | Trae | 进行中 | 正在上品 |
| 头条号 | Trae | 进行中 | 正在上品 |
| 微博 | Trae | 进行中 | 正在浏览并搜集信息 |
| 知乎 | Trae | 等待人工 | 答案已编辑，等待确认发布 |

### 3.3 状态更新不刷聊天

“正在填标题”“正在上传封面”“正在读取页面”等过程，只更新总览中的当前动作，不逐条刷进总指挥聊天。

总指挥聊天只接收：

- 任务完成及结果摘要；
- 任务异常或卡住；
- 需要人工参与；
- 跨页面任务的整体进度；
- 必须交由用户决定的事项。

### 3.4 点击条目进入真实页面

点击总览中的页面条目时：

1. 激活原来已经存在的页面标签，不复制新窗口；
2. 展示该网页的真实现场；
3. 同时切换到该页面的专属聊天；
4. 保留该任务原有记录和上下文。

指挥室只是所有真实页面的实时投影，不是另外创建的一批假窗口。

### 3.5 总指挥能力

用户可以在指挥室中：

- 向一个或多个页面派发任务；
- 打开新页面；
- 切换到指定页面；
- 停止或继续任务；
- 关闭页面；
- 处理异常和人工请求；
- 查看跨页面任务的整体结果。

关闭页面不等于自动删除任务记录。关闭仍在执行或等待处理的页面前，必须先明确停止任务，避免后台任务失去页面后仍继续运行。

## 4. 页面工作间：一个网页一套独立工作上下文

每个页面工作间由三部分组成：

1. 真实网页；
2. 页面任务状态区；
3. 页面专属聊天侧栏。

### 4.1 页面状态区

页面右侧聊天侧栏的顶部，持续显示当前任务状态，而不是只把状态写成一条聊天消息。

至少显示：

- 当前 Agent；
- 当前任务；
- 当前状态；
- 正在执行到哪一步；
- 最近更新时间；
- 等待人工的具体原因；
- 完成后的结果汇报。

页面状态、标签头状态和指挥室总览状态必须同步，不能一处显示完成、另一处仍显示执行中。

### 4.2 页面专属聊天

页面专属聊天只处理当前页面，例如：

- 修改当前商品的标题；
- 更换当前稿件的封面；
- 继续当前页面未完成的任务；
- 查看当前 Agent 的完整执行记录；
- 处理当前页面提出的问题。

切换到哪个页面标签，右侧就恢复哪个页面的专属聊天，不把所有页面的历史混在一起。

### 4.3 会话隔离粒度

会话必须按页面和任务隔离，不能只按 Agent 名称隔离。

即使同一个 Trae 或 Cursor 同时执行多个任务，每个页面也必须有自己独立的任务上下文和对话记录。

### 4.4 手动打开的页面

用户手动打开网页时，也自动形成页面工作间和页面会话，但初始状态为灰色静止：

- 无 Agent 连接；
- 无任务执行；
- 不伪造工作进度；
- 不占用其他 Agent 的页面。

---

## 5. 第一红线：一页一任务一 Agent

这是 1.00 最重要的页面使用原则，优先级高于操作便利性。

### 5.1 页面独占

同一个页面在同一时刻：

- 只能绑定一个任务；
- 只能由一个 Agent 执行；
- 不能同时运行第二个任务；
- 不能接入第二个 Agent；
- 不允许通过排队、复用或切换的方式让多个任务交叉操作同一页面。

### 5.2 新任务默认新开页面

任何 Agent 收到新任务时，默认创建并绑定一个独立的新页面。

这条规则适用于 Cursor、Trae 以及其他所有接入 SPARO 的 Agent，也适用于同一个 Agent 连续接收的多个新任务。

继续执行当前已有任务，不属于新任务，仍在原页面进行，不应无故另开页面。仅未结束任务的原目标续跑留在原页；验收后提出修改、追加商品、更换平台等新需求，默认作为新任务开新页，不得借“续跑”把新目标塞回已完成的页面。

### 5.3 忙碌页面禁止抢占

只要页面存在以下任一情况，其他 Agent 和其他新任务就不得占用：

- 已连接 Agent；
- 正在执行任务；
- 暂停但尚未结束的任务；
- 卡住或异常、等待处理；
- 等待人工扫码、付款、验证码或确认；
- 已绑定但尚未释放的任务页面。

不得因为页面暂时没有点击、看起来没有变化，就认定它空闲。

### 5.4 只有明确空闲的页面才能复用

复用页面是例外，必须同时满足：

- 没有连接任何 Agent；
- 没有执行中的任务；
- 没有暂停、异常或等待人工的未结束任务；
- 原任务已结束并解除页面绑定；
- 页面明确显示为可使用的空闲状态。

仅显示灰色并不必然代表可以复用；灰色表示“不再运行”，是否可以复用还必须检查 Agent 和任务绑定关系。

待验收页面不得被其他 Agent 自动抢占。

### 5.5 绑定与释放

任务开始时，建立“页面—任务—Agent”的独占绑定。

任务完成后不得立即释放绑定。页面保持绑定，转为灰色并显示“已完成·待验收”，直到用户验收或明确关闭任务后才解除绑定。

任务被主动停止时，保留停止结果和绑定，直到用户明确结束任务；任务异常或卡住时同样保留绑定和现场，由原 Agent 在原页面续跑或处理。只有任务被明确结束并释放绑定后，页面才可能重新成为可复用的空闲页。

### 5.6 跨页面任务

一个总任务需要操作多个平台时，应拆成多个独立子任务：

- 每个子任务使用自己的页面；
- 每个页面只由一个 Agent 执行；
- 各页面可以并行；
- 指挥室汇总整体进度，但不把多个子任务塞回同一页面。

### 5.7 标准场景

用户在 Cursor 窗口 A 中说：“去店小秘编辑商品 A，准备上品。”

系统打开店小秘页面 A，绑定窗口 A 的任务。

用户又在 Cursor 窗口 B 中说：“去店小秘编辑商品 B，准备上品。”

系统必须再打开店小秘页面 B，绑定窗口 B 的任务。

两个任务可以同时进行，但不得争抢、覆盖或串联同一个网页。

## 6. 四色任务状态

颜色统一表达任务状态，不表达 Agent 身份。Agent 是谁，直接显示名称。

四色状态必须同步出现在：

- 指挥室页面条目；
- 对应网页的标签头（Tab）；
- 页面侧栏顶部状态区。

| 颜色 | 状态 | 含义 | 页面行为 |
|---|---|---|---|
| 绿色 | 进行中 | Agent 正在工作 | 持续更新当前步骤，页面被独占 |
| 红色 | 卡住或异常 | 执行失败、无法继续、需要诊断或处理 | 停止盲目推进，保留现场并上报 |
| 黄色 | 等待人工 | 需要人参与后才能继续 | 在安全的当前步骤暂停，等待人处理 |
| 灰色 | 不再运行 | 静止、停止、无 Agent、任务已结束 | 不执行动作；是否可复用另看绑定关系 |

### 6.1 绿色：正在工作

表示 Agent 正在该页面执行任务。

绿色不是完成，也不代表可以验收。页面显示绿色时，其他 Agent 不得占用。

### 6.2 红色：卡住或出问题

表示任务遇到异常、卡住、失败或无法自行恢复的情况。

页面应保留现场，并在页面聊天和指挥室中说明：

- 卡在哪一步；
- 已尝试过什么；
- 需要重试、换一种方法，还是由用户处理。

### 6.3 黄色：邀请人类参与

表示任务本身未必失败，但必须由人完成某个动作后才能继续，例如：

- 扫码登录；
- 输入验证码；
- 付款；
- 确认发布；
- 回答 Agent 无法决定的问题；
- 其他需要人工授权或判断的事项。

黄色状态下，Agent 不得绕过人工要求继续执行高风险动作。

人类操作页面时，Agent 暂停操作，避免人与 Agent 同时点击同一页面。人处理完后，由原 Agent 在原页面继续原任务，不另开新页面。

### 6.4 灰色：不再运行

表示页面当前没有正在运行的动作，包括静止、停止、无 Agent 或任务已结束。

灰色只是运行状态，不自动等于“允许其他 Agent 接管”。接管仍须满足第 5.4 条。

### 6.5 状态优先级

- 出现红色或黄色时，不得继续显示为绿色正常运行。
- 页面停止运行后转为灰色，同时保留完成、异常或停止的结果文案。
- 完成不是第五种运行颜色；完成通过结果汇报、待验收标识和闪烁提醒表达。

## 7. 工作进度同步

Agent 工作到哪一步，必须同步到两个位置：

1. 当前页面侧栏顶部状态区；
2. 指挥室对应的页面条目。

例如：

- 正在读取商品信息；
- 正在编辑标题；
- 正在上传图片；
- 正在填写正文；
- 正在检查发布结果。

状态文案描述当前真实动作，不使用没有实际进展的空泛“正在努力”。

进度更新只改变状态区和总览，不持续刷总指挥聊天。

---

## 8. 人工介入与恢复

当任务需要人工参与时，系统必须同时做到：

1. 页面状态变为黄色；
2. 页面侧栏明确说明需要人做什么；
3. 指挥室对应条目变为黄色；
4. 总指挥聊天出现一条集中的人工请求；
5. 任务停在安全步骤，不继续执行后续动作。

用户点击该请求后，进入对应真实页面和页面聊天。

人工完成后，Agent 在同一页面继续任务，并恢复绿色进行中；如果无法继续，则转为红色并说明原因，不能假装已经完成。

---

## 9. 完成汇报与验收提醒

每个页面完成任务后，都必须形成结果汇报，不能只停止运行而不发声。

### 9.1 页面内结果汇报

在该页面的专属聊天和状态区中显示结果卡片，至少包括：

- 任务是否完成；
- 完成了什么；
- 当前结果位于哪个页面；
- 关键产出或操作结果；
- 是否存在未完成项；
- 是否需要用户验收或进行下一步操作。

结果必须真实。只打开页面、只填了部分内容、只上传但未核验，不得汇报为全部完成。

### 9.2 指挥室结果汇报

指挥室对应页面条目同步显示：

- 已完成；
- 待验收；
- 简短结果摘要。

跨页面总任务可以由指挥室再汇总一次整体结果，但每个页面的独立汇报仍需保留。

### 9.3 双位置闪烁提醒

任务完成时，同时触发：

1. 指挥室内对应页面条目的闪烁或高亮提醒；
2. 对应真实网页标签头（Tab）的闪烁或高亮提醒。

提醒不能一闪而过，应持续到用户点击查看或确认已知悉。

点击任一提醒后：

- 同时停止指挥室条目和真实标签头两处提醒；
- 激活对应真实页面；
- 打开该页面专属聊天；
- 展示结果汇报，供用户验收。

如果用户已经位于该页面，查看结果卡片即视为已知悉，两处提醒同时停止，不再强制重复切页。

### 9.4 不抢前台

完成提醒只用于让用户知道“可以来验收了”。

不得因为任务完成就擅自抢前台、切换用户正在查看的页面或打断用户当前操作。

---

## 10. 完整页面生命周期

标准流程如下：

1. Agent 收到新任务；
2. 默认新开独立页面，或复用系统明确判定为空闲的页面；
3. 建立“页面—任务—Agent”独占绑定；
4. 页面转为绿色进行中；
5. 执行步骤实时同步到页面状态区和指挥室；
6. 需要人工时转为黄色，处理后恢复原任务；
7. 卡住或异常时转为红色，保留现场并上报；
8. 任务完成后停止运行，显示完成结果和待验收标识；
9. 指挥室条目与真实标签头同时闪烁提醒；
10. 用户查看并验收；
11. 任务关闭并解除绑定；
12. 页面按用户选择保留、关闭，或在明确空闲后供后续任务复用。

## 11. 信息与操作边界

### 11.1 总指挥聊天负责

- 跨页面、跨平台任务；
- 新建任务和分派页面；
- 查看全局结果；
- 处理集中上报的异常与人工请求；
- 打开、切换、停止、继续和关闭页面任务。

### 11.2 页面专属聊天负责

- 当前页面的具体操作；
- 当前任务的细节调整；
- 当前页面的执行记录；
- 当前页面的结果汇报；
- 当前页面需要人工处理的问题。

### 11.3 禁止信息混流

- 不把多个页面的完整执行过程塞进总指挥聊天；
- 不把同一 Agent 的不同页面任务合并成一条对话；
- 不让一个页面的指令默认作用于其他页面；
- 不让一个 Agent 通过未指定页面的方式误操作用户当前页。

## 12. 1.00 验收红线

后续实现至少必须通过以下场景，才能认为符合本方案：

1. **双任务开页**：两个 Agent 分别接到同网站任务，系统生成两个独立页面。
2. **同 Agent 多任务**：同一 Agent 接到两个新任务，也不得把两个任务混进同一页面。
3. **忙碌页防抢占**：绿色、红色、黄色以及未释放绑定的页面，均不能被其他任务占用。
4. **空闲页复用**：只有无 Agent、无未结束任务且已解除绑定的页面才允许复用。
5. **页面独占**：同一页面同一时刻始终只有一个任务、一个执行 Agent。
6. **状态同步**：页面侧栏、标签头和指挥室中的 Agent、步骤、颜色与结果一致。
7. **绿色运行**：执行过程中显示绿色，并持续反映真实当前步骤。
8. **红色异常**：卡住或失败时显示红色，说明原因，不假报完成。
9. **黄色人工**：扫码、付款、验证码、确认发布等场景显示黄色，人工处理后能回到原任务继续。
10. **灰色停止**：不再运行时显示灰色，且灰色不被直接等同于可抢占。
11. **完成汇报**：每个任务完成后，本页有结果卡片，指挥室有完成摘要。
12. **双位置提醒**：完成时，指挥室条目与真实标签头均发出持续闪烁或高亮提醒。
13. **点击验收**：点击提醒能进入原页面、原任务和原页面聊天，而不是新开页面。
14. **不抢前台**：完成提醒不打断用户当前操作。
15. **会话隔离**：切换页面时只显示本页会话，同一 Agent 的不同页面也不串话。
16. **过程不刷屏**：普通步骤只更新状态，不持续刷总指挥聊天。

## 13. 后续修改纪律

1. 后续任务书必须写明对应本方案的章节，不得凭实现方便改变页面独占原则。
2. 不得在 1.x 中恢复“多个 Agent 共用忙碌页面”或“一个页面并行多个任务”。
3. 不得把颜色重新改成 Agent 身份色；状态色与 Agent 名称必须分离。
4. 不得用全局聊天记录代替页面状态总览。
5. 不得只完成任务而不提供结果汇报和验收提醒。
6. 不得通过抢前台、强制切页代替后台提醒。
7. 如果新需求与本方案冲突，先停下并升级方案版本；涉及产品形态变化时进入 2.00，不得直接改代码绕过。
