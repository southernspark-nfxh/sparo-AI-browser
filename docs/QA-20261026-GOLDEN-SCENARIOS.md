## 3. 设计层与执行层的错误清单（复盘结论，QA 任务的靶子）

### 设计层

1. **脑手分离红线只有文档、没有强制。** 「决策点显式登记」写了，但代码里有多少个会提前终止/旁路任务流的本地判断，没有清单、没有登记册。`openSiteIsTheJob` 就是存量漏网者——**地里还有多少只地鼠，没人知道**。这是「修不完」的结构性原因。
2. **「完成」的定义曾经太松**（已修），但「早退」的入口太多：namedSiteIsOpen、userDidNotAskToRead、loginRedirectNote、stall≥3、siteGate ask/navigate、repeatStop……每条旁路都是独立写的，新修的清点只罩住了被发现的那几条。

### 执行层

3. **验收标准是单测绿，不是场景通。** 单测断言函数行为，不断言「用户那句原话在当前页状态下跑完全程」。三天的三个病，单测一个都逮不住——它们全是「真实中文句子 × 真实页面状态 × 真实时序」的组合。
4. **安装包长期滞后 HEAD。** 10-24 事故包是 10-22 打的；修没修，用户测的是旧包，双方都拿到错误信号。**打包后复测必须从「可选项」变成「必选项」。**
5. **修在下游、病在上游。** 先修关单清点（出口），再修收摊拦截（中途），今天才摸到入口抢答——顺序是跟着爆炸点走的，不是跟着数据流方向走的。沿着「理解 → 计划 → 循环 → 收尾」从上游到下游清一遍，比等爆炸高效。

## 4. 任务内容（四项，按序执行）

### T1 黄金场景集（黄金 = 用户真实说过、真实失败过）

建立 `docs/QA-GOLDEN-SCENARIOS.md`，首批 8 条，每条带**证据级验收标准**——不看侧栏感觉，看 `%APPDATA%\sparo-store\` 底账：

| # | 场景（原句级别） | 前置状态 | 验收证据（missions.jsonl / chat-memory / reports） |
|---|---|---|---|
| G1 | 打开微博 | 任意 | 单步 navigate，close(done)，侧栏「已打开 weibo.com。」 |
| G2 | 当前我打开的这个博主 最近三天的微博 帮我复制下来 做成一个文档 | 已停在某博主 u/ 页 | ≥1 条真实 step turn；首步是 read_page；不零执行；关单前必交付齐或 incomplete 带缺口人话 |
| G3 | 把最近 3 天微博逐条复制下来（阅读页刚产出之后说） | 上一条助手消息带阅读页 | 开新工作单进 missions.jsonl，**不进改写捷径** |
| G4 | 研究博主 XXX 画像，最好上百条 | 任意 | 全句只有一张有效单；采集步有真实滚动/翻页 turn；报告注明样本量 |
| G5 | （waiting_human 挂起后回）打开 / 好 / 继续 | 任务挂起中 | 恢复原任务续跑，不新开单、不销毁 |
| G6 | 帮我写一首诗 / 纯创作句 | 任意 | 提议卡正常出现，不被 isLegalCap 吞 |
| G7 | 打开百度，搜今天北京天气 | 任意 | 不早退，后半句执行，有检索 turn |
| G8 | 长采集滚动翻页 | 无限滚动页 | page_text 带「较上次 +N 字」；+0 换策略，不连按同一键 |

每条场景的判定写成可照抄的核对语句（查哪个文件、grep 什么字段、期望值是什么），让任何 AI/人拿着就能验。

### T2 决策点登记册（地鼠地图）

建立 `docs/DECISION-POINTS.md`：把主循环与路由层所有**能让任务提前终止、绕过脑区、或改变走向的本地判断**全部列出，逐项登记：

- 位置（文件:行）、触发条件、能否提前结束任务、当前依据（正则/启发式/模型产物）、处置结论（删 / 降级为带过期的 fallback / 保留并写明理由 / 交还模型）；
- 首批必含：openSiteIsTheJob、userDidNotAskToRead、namedSiteIsOpen 三处调用点、loginRedirectNote、stall≥3 收摊、siteGate ask/navigate、repeatStop、mission 二次执行守卫、阅读页改写捷径门岗、routeUserGoal；
- 登记册落盘后，新增任何同类判断必须先登记再合码（写进 AGENTS.md 或 CONTRIBUTING 约定）。

### T3 修复-场景映射 + 打包前回归纪律

写进 `docs/PRODUCT-TASKBOOK.md` 或独立小节：

- 每个触及脑区/路由/关单的 commit，提交信息或任务书里标注「影响黄金场景 G?」；
- 重打包前，受影响场景必须在 `npm run start` 下过一遍；**打包后安装包必过 G1+G2+G3 三条**（覆盖开站、采集、改写边界）；
- 单测可自动化的部分（如 G2 的「不零执行」可断言循环入口判定）进 `npm test`；不可自动化的留人工清单，不许用单测绿冒充场景通。

### T4 全链路一次走查（上游→下游）

按「理解 → 计划 → 循环入口 → 循环体 → 收尾 → 关单」顺序，对照决策点登记册逐段走查一遍现行代码，回答：每一段还有哪些「文档红线已禁止但代码仍在做」的判断。产出走查记录，发现的新洞只登记、另开任务书，不在本单修。
