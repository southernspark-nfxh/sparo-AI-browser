## 修复项（三个洞 + 一条规范落地）

### F1 计划落盘前校验「手」的合法性，非法步骤打回，不许进循环

- 位置：脑区计划/handbook 接纳处（mergePlan / 计划校验层），不是执行层。
- 规则：每一步的 `cap` 必须在当前合法手清单内（navigate/read_page/act/fill_form/run_skill/search 等现行集合）；不在清单内的 cap（如 `search_read`、`train_search` 若也无手）→ **整步拒收，打回脑区重出计划或降级为已有手**，并记日志。
- 注意单 C 里 `train_search` 是 ok=True 的（有手，查的是 12306 页面）；`search_read` 才是无手的。先把「哪些 cap 有手」的清单以代码为准列出来（问现行代码，不问文档），校验逻辑只信这份清单。
- 同一步以**同一失败原因**重复时禁止原样重试（单 A 连撞三次同一句话就是这种行为）；失败必须换打法或换步。

### F2 目标已达成立即关单，禁止完成后漫游

- 单 B 的病：发布已成功（交付物齐了），循环仍继续派生新步（search_read → 读无关百度页）。
- 修法：每步结束后若必交付已齐（过现行清点闸口），**直接关单**，不再让模型派生新步；模型想继续必须过「还有什么没交付」校验，答不出就关。
- 这条与既有「synthesize 三层拦截」是同一闸口的另一半：那边拦「没干完就收」，这边拦「干完了还不收」。

### F3 无进展挂死必须有说法

- 触发面：循环 N 分钟（建议 5 分钟）无任何新 finding、且没有 waiting_human 挂起记录 → 必须主动动作：换策略重试一次（如 12306 超时→换携程火车票/结果页 URL 直达），仍无进展则关单并在侧栏说人话（「12306 查询超时，没拿到车次价格，已试过的入口：…」）。
- 不许出现单 C 这种「50 分钟零进展零消息」。
- 修完后单 C 的原句必须能跑出个结果（哪怕是「12306 超时，改用携程查到…」的部分交付 + incomplete 也行），不许静默挂着。

### F4 发布权限规范落地（对应 §0）

- 发布技能/发布按钮逻辑支持两种模式：默认只填草稿；当句含明确自动发指令时才点发送。
- 判断「当句是否授权自动发」由模型在理解层判定（deliverable/指令槽），本地不拿正则抢答；本地只做底线兜底（支付、登录、验证码永远不许自动点）。
- `docs/PUBLISHING.md` 同步更新口径。

### F5（附带，小）妙招失效自清理

- 单 A/G2 实测中，沉淀妙招「微博博主三天内微博复制-2e45b3」第 1 步找「王海林0516」失败——博主实际姓**汪**。妙招记错了关键文本。
- 修法：妙招执行因「找不到其记录的关键文本」失败时，把该妙招标记降权/作废并记经验，下次同场景不再优先撞它。现系统已能自纠绕过（G2 实证），这条只是防止反复撞同一个坏妙招。
