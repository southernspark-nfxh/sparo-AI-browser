## 0. 背景：验收发现了什么

打包版（release\win-unpacked，10:43 包）验收结论：

- ① 门岗直放 ✅、② 出卡机制 ✅（但触发面窄，见下）、④ 微博三笔回归 ✅（一单、报告页、侧栏干净）。
- ③ 沉淀 ❌ 未验成（唯一 new 单撞网易云登录墙早收，distill 无产出）。
- **阻断发现**：纯创作类新任务永远出不了卡。

根因链（全部坐实，非猜测）：

1. 提示词（understand.ts:248）允许模型 plan 用 `synthesize`；`isLegalCap`（loop.ts:665-667）明确拒收 synthesize（P0 之前的预存规则，be06dec 引入）。
2. 纯创作新任务（密室谜题、顺口溜、浇水表）模型 100% 判 `coverage:"new"` + `plan:[{cap:"synthesize"}]`——API 直探 3/3 复现。
3. `analyzeGoal`（loop.ts:481-496）把 coverage 分支放在 `mergePlan(...).length > 0` 之后 → mergePlan 丢光 synthesize → 落到 496 行 `return merged` → **不出卡、coverage 不落盘、静默直跑**。
4. 次要：plan 为空数组时 coverage 同样不落盘（taskbook P2 §245 明说属设计内，不动）。

证据：`qa-screenshots/accept-packed/`（3-propose-card2.png 卡面、6-weibo-report.png 微博报告页、`_probe*.ps1` API 探测脚本与 `_prompt.txt`）。

## 1. 修法（唯一改动点）

`src/main/agent/loop.ts` `analyzeGoal`：把 `heard.coverage === "new"` 的判定**前移到 mergePlan 之前**——

- 条件改为：`heard.plan?.length > 0 && heard.coverage === "new"` → 直接 `sealWorkOrder({...merged, coverage:"new", needsConfirm:true, approach: 编号步骤})`，handbook 用 `mergePlan` 结果，**为空则回退 `compileHands`**（执行兜底，卡片文案不受影响——approach 本来就只用 heard.plan 编号）。
- `coverage:"covered"` 分支维持原样（mergePlan 非空才置 covered）。
- `isLegalCap` **不改**：synthesize 依旧不当手（它是终止信号）。在 mergePlan 头顶注释补一句「出卡不依赖本函数结果，纯 synthesize plan 也会出卡」。
- 渲染层一行不改；verifyContracts 不动；禁止本地关键词预判「是不是新任务」（P2 §29 红线沿用）。
