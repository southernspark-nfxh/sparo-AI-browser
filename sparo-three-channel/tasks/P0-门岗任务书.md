## 0. 干什么

在侧栏用户原话进入大脑（工作单 / understand / 云端计费）之前，加一层本地「门岗」：

- 用户原话 normalize 后，与 `%APPDATA%\sparo-store\skill-triggers.json` 里登记的触发语做**完整原话精确匹配**。
- 命中 → 直接回放对应技能，不调模型、不扣云端点数，侧栏只留一句「按惯例：<技能名>」。
- 未中 → 原样放行，现有流程一个字不变。
- 配套：登记（用户点「记住」才写）、连败摘除、设置页管理。

**P0 明确不做**：不动大脑通道（understand/reasoner/kernel 一行不改）；不动 `matchSkills`/`resolveSkill`/`runSkill` 内部；不做参数化触发语（已拍板方案A，逐字原话）；不做四件套沉淀（P2）。

**与设计稿的四处务实差异（保留，前三处已同步回设计稿）**：

1. 设计稿「大脑提议 + 用户沉默确认」→ P0 改为用户显式点「记住」才登记（P0 不动大脑，显式点击更保守）。
2. 设计稿「是否一步到位由大脑判定」→ P0 用本地白名单顶着（§2.5），**已登记，过期 2027-01-23**，P2 大脑接管后删除。
3. 设计稿 2.2「失败当轮转交大脑续跑」→ P0 做不到（不动脑），降级为**失败只记账**：`fails>=2` 停用后**不再零 LLM 直放**；原话若仍是「运行妙招」句式，下一句走窄路（`runSkillTool` 正常路径，配了模型会带一次 LLM 摘要），不进工作单。**当轮转脑留给 P2**。
4. **「运行妙招 …」窄路**：侧栏这句话在现有路径上不会稳定走进 `executeHand`——`loop.ts` 550 行的本地计划步 `covers` 是 `form`，句子被收成交付物 `answer`，`nextThought` 两边都对不上，直接合成，不调 `executeHand`；没配模型时卡片一定不出，配了模型要押 reasoner 碰巧输出 `run_skill`。所以门岗未命中、让路守卫通过之后，加一条窄路（判定见 §2.3）。**只为这句式开一条确定性登记入口，不改 kernel**；其他未命中原话仍原样进大脑。

数据结构也从设计稿的「按技能 id 做 key」改为**扁平 `triggers[]` 数组**（按 id 删/停更直接）。

## 1. 红线（违反就退回重做）

1. 门岗只做 normalize 后**完整原话精确匹配**。禁止关键词、子串、模糊、语义匹配。normalize 只做四件事：去首尾空白、合并连续空白为单空格、全角字母数字标点转半角、去句末标点（`。！？!?.`）。禁止再加别的。
2. 多步骤技能永不进门岗查表。只有过 §2.5 白名单的技能可登记触发语。
3. 禁止自动登记。触发语只能来自用户显式点「记住」按钮。
4. **门岗让路规则**（见 §2.3）：有未关工作单、暂停中、带引用、带图、后台车道时，门岗零副作用直接放行。产品规则「有未关的单就续跑」高于门岗。
5. 门岗回放**直接调 `runSkill`，禁止调 `runSkillTool`**：`runSkillTool`（browser.ts 4469 行）在有 readings 且配了模型时会调 `deepseek.completePlain`（4479–4496 行），回放必须零 LLM 请求。
6. 命中不得触碰云端计费：early return 必须在任何 `beginCloudTaskIfNeeded` / `assertAndStartTask` 之前。
7. 商店版约束不动：不露价格/支付 UI，触发语不出本机。
8. 只改 §3 列出的文件。`docs/listings/` 不许碰。
9. 完成后：`npm test` 全绿 + `npm run typecheck` 退出码 0，再 `npm run start` 手动过 §6 QA 清单，全绿才交。
10. 一个 commit，只 `git add` §5 列出的文件，禁止 `git add -A` / `git add .`。

## 2. 行为规格

### 2.1 数据文件

`%APPDATA%\sparo-store\skill-triggers.json`（注意不是原版 `%APPDATA%\sparo`），扁平数组：

```json
{
  "triggers": [
    {
      "id": "8位hex",
      "skillId": "taught-xxx",
      "text": "normalize 后的完整原话",
      "addedAt": "ISO",
      "runs": 0,
      "fails": 0,
      "enabled": true,
      "lastUsedAt": "ISO 或缺省"
    }
  ]
}
```

- id 用 `randomBytes(4).toString("hex")`（8 位；**别照抄 lessons 的 6，那是 12 位**）。
- 同一 normalize 文本只留一条（重复登记去重）。
- normalize 后是空串：不登记、不命中。
- 文件读写放 `src/main/triggers/store.ts`：load/save/upsert/delete/toggle/`recordOutcome`（见 2.6），模式参考 `src/main/learning/store.ts`。
- 坏 JSON 文件不炸，返回空。

### 2.2 gate.ts（纯函数，不碰文件、不碰浏览器）

`src/main/triggers/gate.ts` 只放纯函数：

- `normalizeUtterance(text: string): string`
- `matchTrigger(triggers: Trigger[], text: string): Trigger | null` —— 入参是**已加载的数组**（`matchTrigger(configDir, text)` 这种签名与「纯函数」冲突，禁止）
- `isOneShotSkill(skill: SkillProbe): boolean`（规则见 2.5）—— `SkillProbe` 是 gate.ts 里自定的本地宽类型，与 2.5 的类型注意一致

### 2.3 门岗 hook 点与让路

`src/main/browser.ts` `dispatchChatJob`（6007 行）。位置：**helpAsk 判定块结束（6032 行）之后、cleanQuotes 分支（6034 行）之前**——早于本函数第一次 `beginCloudTaskIfNeeded`（6036 行），不扣点。

进入查表前，先过让路守卫，任一不满足即零副作用放行：

- `cleanQuotes.length === 0`（带引用的句子让路）
- `jobImages.length === 0`（带图让路）
- `!this.paused`（暂停中让路）
- 前台无未关工作单（`this.activeMission` 为空或已 done/取消）；当前 scope 有未关 mission（`this.taskStore()?.mission`）也让路——「有未关的单就续跑」优先
- 非后台车道：`this.taskStore()?.lane !== "background"`（`enqueueBackground` 最终也进本函数）

守卫过后才 `matchTrigger`：

1. 命中且技能当时仍过白名单（命中时**再查一次** `isOneShotSkill`，不满足当未命中放行）。
2. chatLog 推 assistant 消息：「按惯例：<技能 title>」。**只此一句**，读页摘录不进侧栏。
3. `await runSkill(this, this.configDir(), { id: skillId })`（runner.ts 970 行，直接调，不走 `runSkillTool`）。
4. `recordOutcome`（store.ts）：ok → `runs+1`、`fails=0`、`lastUsedAt`；非 ok → `fails+1`，`fails>=2` 时 `enabled=false`，chatLog 追加「这句原话连着没跑成，已停用这个惯例，可在设置里恢复」。失败时把失败原因一句写进侧栏。
5. early return（转成 ToolResult 返回），不再进入后续流程。

**门岗未命中后的「运行妙招」窄路**（接在同一位置，守卫已通过、查表未中时）：

```ts
// 判定直接内联 stub.ts 88–90 的两条正则（含英文 run skill），不要调 parseLocalIntent
const m =
  text.match(/(?:运行|执行|打|用|按)\s*妙招\s*[「"']?(.+?)[」"']?\s*$/i) ||
  text.match(/run\s*skill\s+(.+)$/i);
if (m) {
  const query = m[1].trim().replace(/^["'「」]+|["'「」]+$/g, "");
  // executeHand({ type: "run_skill", query }, text, [], "chat", tabId) 并 return
}
```

**为什么不能调 `parseLocalIntent`**：它 81 行先走 `routeUserGoal → parseMission`，88 行正则排在后面——「运行妙招 比价」会被 mission.ts 567 行收成 compare_shop（type 是 mission），「运行妙招 天气穿衣建议」被 308 行收成 weather，都到不了 run_skill；而「发小红书」（stub.ts 98–104）和 routeUserGoal 里带技能的发布 type 也是 run_skill，调它会把发布一并截走。内联正则只截「运行妙招」句式，窄路既不缺也不宽。stub.ts 不动，两条正则在 browser.ts 门岗处保持一致即可（书外风险：stub.ts 改了句式要同步这里）。

照 6090–6110 行 `directReader` 的先例写执行段：chatLog 推 `hand.reply` → pushSidebarState → return ToolResult（含 catch 分支照抄）。这样登记路径确定可达，且第一轮跑完不留未关工作单，后续 QA 句不会被让路守卫接走。

### 2.4 登记（用户显式点「记住」）

**唯一登记挂载点：`executeHand` 的 `run_skill` 分支（browser.ts 4925–4929 行）**。三个调用点里只有这里手里有 `userAsk`；MCP 路径与 4414 行工具分发**不传原话、不弹卡**。

该分支改为：先接 `const r = await this.runSkillTool(...)` 拿完整结果（现有 `.message` 赋值保留），`r.ok` 且技能过白名单、且 `normalizeUtterance(userAsk)` 未登记、且 chatLog 末尾没有同文本的未点卡片时，推一条 assistant 消息带 `pendingTrigger: { skillId, text: normalizeUtterance(userAsk) }`。

**skillId 必须取 `r.data.skillId`**（runner.ts 1097 行返回，`runSkillTool` 4498 行原样透传 `r`）：「运行妙招 QA门岗演示」的 `action.id` 是空的、`action.query` 是「QA门岗演示」（标题不是文件名），用它们回放 `getSkill` 对不上 `qa-gate-demo.json`。

侧栏把 `pendingTrigger` 渲染成卡片「按惯例记住『原话（截 28 字）』？[ 记住 ]」，样式照 2974 行附近的 cortex 卡片画。「记住」按钮走 IPC `spark:remember-trigger`（**不要走 `sparkShell.chat()`**）。主进程写入前**再 normalize 一次、再查一次 one-shot**、按 normalize 文本去重。不点不写，无任何默认动作。

注意：自然语言的天气/出行句走 `parseMission`/工作单，不经过本分支，P0 不会出卡——这是预期行为，QA 用例见 §6。

### 2.5 one-shot 白名单（本地规则 · 已登记 · 过期 2027-01-23）

`isOneShotSkill(skill)` 全真才放行：

1. `skill.steps.length <= 3`
2. 每步动作（`step.tool || step.action`，与 runner.ts 487 行 `stepTool` 同口径）∈ `{ "navigate", "wait_for", "page_text" }`
3. `skill.steps` 序列化后不含 `{{`（带槽模板排除）
4. `skill.params` 无 `"required": true` 项（必传参数排除）

第 3、4 条堵住漏洞：`life-thailand-trip`（`query` required）、`life-rent-compare`（出差/比价，设计稿要求永远走大脑）与 `life-translate-page`（`{{url}}`）、`life-express-track`（`{{noEnc}}`）原来会混进来。回放不带 params，带槽技能空槽跑必坏。

**类型注意**：入参用本地宽类型（结构化读取 `tool` / `args` / `params` / `steps`），**不要 import `src/main/skills/store.ts` 的 `Skill` 类型硬套**——那个类型没有 `params` 字段、步骤字段是 `action` 不是 `tool`，且 store.ts 不在本任务书改动清单里。

### 2.6 摘除（recordOutcome，store.ts）

见 2.3 第 4 步。摘除不删除记录，只 `enabled=false`，设置页可恢复（恢复时 `fails` 清零）或删除。注意：登录墙**不会**让 `runSkill` 返回 `ok:false`（runner 不读 `human_gates`，读到登录页正文仍算成功）——失败语义只覆盖执行级失败（如断网 navigate 失败）。

### 2.7 设置页

`src/renderer/shell.html`「学到的经验」区块（设置「经验」面板 2021 行附近）下方加「记住的原话」列表：每行 text、技能名、runs/fails、停用/恢复开关、删除按钮。空态一句提示。渲染函数照 `renderLessons`（2594 行）写 `renderTriggers`；数据并进 `getSidebarPayload` 返回值（加 `triggers` 字段，参考现有 `lessons` 链路，3128 行附近），随 `pushSidebarState` 下发（3149 行附近渲染）。

## 6. QA 自测清单（npm run start 手动过）

准备：放 QA 专用 fixture 技能，**文件名写死 `%APPDATA%\sparo-store\skills\qa-gate-demo.json`**（`getSkill` 按 id 找文件名）；`source` 保持 `"taught"`，`seedBundledSkills` 才不会覆盖它。种子技能全部过不了收紧后的白名单，属预期：

```json
{
  "id": "qa-gate-demo", "title": "QA门岗演示", "intent": "QA 门岗用", "source": "taught",
  "createdAt": "2026-10-23T00:00:00.000Z", "updatedAt": "2026-10-23T00:00:00.000Z",
  "steps": [
    { "tool": "navigate", "args": { "url": "https://www.baidu.com" } },
    { "tool": "page_text" }
  ],
  "stepCount": 2, "stats": { "success": 0, "fail": 0 }, "enabled": true
}
```

1. **登记**：侧栏发「运行妙招 QA门岗演示」（窄路正则确定性进 run_skill）→ 跑完出「记住」卡 → 点「记住」→ 设置页可见。注意第一轮走的是 `runSkillTool`，fixture 含 `page_text`，**配了模型时会有一次 LLM 摘要**——预期行为，零 LLM 只在第 2 条验收。第一轮跑完不留未关工作单（窄路直接 return）。发自然天气句「今天北京天气怎么样」→ 走工作单、**不出卡**（预期）。
2. **直放（必须联网）**：再发一字不差的「运行妙招 QA门岗演示」→ 直接回放。**零 LLM 的证据**：侧栏只有「按惯例：QA门岗演示」一句，没有读页摘录、没有模型摘要，云端余额不变。断网留给第 5 条，这里不要断网（fixture 第一步是打开百度，断网 navigate 必失败）。
3. **让路**：改一个字（如「运行妙招 QA门岗演示2」）→ 门岗未中、走窄路，提示找不到该妙招，**不进大脑**（「运行妙招 X」句式从此确定归 run_skill，这是窄路的预期代价）；有未关工作单时发命中原话 → 续跑优先、不被门岗截走；暂停中发命中原话 → 不被截走。
4. **未登记**：发没登记过的话 → 行为与改动前完全一致。
5. **连败摘除**：断网回放两次（navigate 失败，ok:false，均出现「按惯例」+失败句）→ 设置页该条显示已停用。联网后第三次发同句：**不再零 LLM 直放**——这句仍匹配窄路正则，走 `runSkillTool` 正常路径，侧栏出现「正在按妙招「QA门岗演示」执行…」而**不是**「按惯例」，不进工作单、不当轮转脑（P2 才恢复）。设置页点恢复（fails 清零）后再发 → 恢复「按惯例」直放。**不要用登录墙当失败用例**（runner 不读 human_gates，登录页正文算成功）。
6. **删除**：设置页删除一条触发语 → 立即不命中。
7. **白名单反例**：「运行妙招 比价」（`life-compare-shop`，9 步）跑完**不出卡**；「运行妙招 天气穿衣建议」（`life-weather-wear`，有 required 参数 city）跑完**不出卡**。这两条经窄路确实进了 `run_skill`，不出卡的原因是被白名单挡住——出不出卡要对着技能日志确认是白名单拦截。
8. 主进程改动需重启生效（不热更），自测用开发窗。
