## 0. 干什么

两件事：

1. **`run_skill` 移除模糊直跑**：`runSkill`（runner.ts 970 行）现在用 `resolveSkill`（298–324 行）按 query 模糊猜技能直接跑——「发小红书」「比价」这种自然语言 query 都能碰运气跑起来。P1 改为**只接受 id 或已登记触发语**；对不上就返回候选清单（`suggestions`），不执行。本地模糊打分（`matchSkills`）降级为纯候选提示，原样保留给查询工具用，一行不改。
2. **妙招候选进大脑上下文**：大脑选技能时得看得见候选清单，才能用 id 拍板。chat 大脑已有（browser.ts 7667–7670 注入 `skills: catalog`），P1 把同一份候选补进 kernel 的 reasoner 和 understand 提示词，并把工具描述/MCP 提示改成实话（run_skill 只认 id）。

**P1 明确不做**：不动 `matchSkills` 打分逻辑；不动门岗查表与登记/摘除（P0 已验收）；不做四件套沉淀（P2）；不动 `resolveSkill`（它只剩 `get_skill` 只读查询在用）；不动 understand 输出 schema（不加新字段，只加一段提示词文本）。

## 1. 红线（违反就退回重做）

1. `runSkill` 的解析只有两条路：`getSkill(id)` 精确命中，或 key 命中 `skill-triggers.json` 里 `enabled` 触发语的 normalize 文本。**禁止**在严格解析里加标题匹配、别名匹配、子串匹配等任何第三条路（设计稿 §4「只接受 id 或已登记触发语」）。
2. `matchSkills`（runner.ts 225–296）一行不改。它只服务：`match_skill` 工具、`get_skill` 失败候选、`run_skill` 失败候选、窄路的 `namedSkillId`。
3. 触发语查询复用 `src/main/triggers/gate.ts` 的 `normalizeUtterance` 和 `src/main/triggers/store.ts` 的加载函数，禁止新造一份 normalize。
4. **脑区与非脑区不混提交**（设计稿 §6），本期两个 commit，划分见 §5。`src/main/agent/**` = 脑区。
5. 模糊打分永不进无意识通道：门岗回放（browser.ts 6117 `replayHabit` 直调 `runSkill({ id })`）行为不变；strict 化后它走 id 命中，不受影响，不许顺手改它。
6. 找不到时的返回结构不变：`{ ok: false, message: "未找到妙招「key」", data: { suggestions } }`（runner.ts 986–991 现状），只换解析函数，下游（窄路 6190、MCP）不受影响。
7. 只改 §3 列出的文件。`docs/listings/` 不许碰。不动 package.json 版本号。
8. 完成后：`npm test` 全绿 + `npm run typecheck` 退出码 0，再 `npm run start` 手动过 §6 QA 清单，截图当天归档 `qa-screenshots/p1-candidates/`（文件名带步骤号），全绿才交。

## 2. 行为规格

### 2.1 严格解析（runner.ts）

新增并导出：

```ts
export function resolveSkillStrict(configDir: string, key: string): Skill | null
```

解析顺序：

1. `getSkill(configDir, key)`（按 id 找文件名）命中 → 返回。
2. 加载 `skill-triggers.json`，找 `enabled !== false` 且 `normalizeUtterance(trigger.text) === normalizeUtterance(key)` 的条目 → `getSkill(configDir, trigger.skillId)`；技能文件已被删则当未命中。
3. 否则返回 `null`。

`runSkill`（970 行）把 984 行的 `resolveSkill` 换成 `resolveSkillStrict`，其余不动（未命中仍走 986–991 返回候选）。

注意 import 方向：runner.ts 新增 `import { normalizeUtterance } from "../triggers/gate.js"` 和 triggers store 的加载函数。triggers/gate.ts、triggers/store.ts 不 import skills/*，无循环依赖。

### 2.2 窄路改传 id（browser.ts 596–6210）

P0 窄路现在把用户原话当 query 直接传给 `run_skill`（6196 行），strict 化后「比价」「QA门岗演示」这类别名/标题会跑不动。改造：

- `namedSkillQuery`（610–614）改为 `namedSkillId(configDir, query): string | null`：`getSkill(query)` 命中返回其 id；否则取 `matchSkills(configDir, query, 1)[0]`，`reason` 含 `exact` 或 `alias:` 时返回该候选 id，否则返回 `null`。判定口径与 P0 一致，只是从 boolean 改成带回 id。
- 窄路（6187–6210）：`const skillId = namedSkillId(this.configDir(), named)`；为 null 时走现有「未找到妙招」分支（6190–6193）不变；命中时 `executeHand({ type: "run_skill", id: skillId, query: named }, text, [], "chat", tabId)`（id 用于执行，query 留给侧栏文案和摘要）。
- `executeHand` 的 run_skill 分支（4994–5001）：4995 行 label 改为 `action.query || action.id`（侧栏显示用户原话「比价」，不是 `life-compare-shop`）。`runSkillTool` 4554 行摘要提示里的 `input.query || input.id` 顺序已对，不动。

### 2.3 工作单执行兜底（browser.ts 5802 附近）

候选进 reasoner 后（2.5），模型会选 `cap=run_skill` 并把妙招 id 写进 `step.query`，但这种 step 没有 `action`（reasoner.ts 458–461 只在 `compileHands` 有 run_skill 手时才能补 action）。现状 5802 行 `if (step.action)` 不满足就静默跳过。在 5802 之前加一个分支：

```ts
if (step.cap === "run_skill" && !step.action && step.query) {
  const hand = await this.executeHand({ type: "run_skill", id: step.query, query: step.query }, goal.raw, [], goal.kind, tabId);
  // 与 5803 分支相同的观察/记录处理
}
```

`step.query` 不是合法 id 时 strict 解析返回「未找到妙招 + 候选」，失败语义安全，不会误跑。

## 4. 单元测试（tests/skill-strict.test.ts 必写）

只测 runner 纯逻辑，浏览器用空对象 stub；跑技能一律 `dryRun: true`（runner.ts 998–1013 在 dryRun 时不动浏览器）。模式照 `tests/triggers.test.ts`（tmpdir 隔离 configDir，技能 JSON 手写进 tmpdir/skills/，触发语写进 tmpdir/skill-triggers.json）。

- id 精确命中：tmpdir 放一个 1 步技能（`navigate` 某 URL），`runSkill({ id, dryRun:true })` → ok:true
- 触发语命中：登记一条 enabled 触发语「今天北京天气怎么样」指向该技能，key 用同文本（含全角/句末标点变体）→ 命中；`enabled:false` 后不命中
- 自然语言 query 不执行：key 用技能标题、别名（BUILTIN_ALIASES 里有的，如「比价」）→ ok:false、`未找到妙招`、`data.suggestions` 是数组且含该技能 id
- 子串不命中：标题改一个字 → ok:false
- `skillCatalogLines`：输出含 `- id: title（N 步）`；空 configDir 返回空串
