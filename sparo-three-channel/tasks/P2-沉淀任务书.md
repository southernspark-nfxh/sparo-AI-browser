## 0. 干什么

四件事：

1. **新任务通道**：understand 加 `coverage` 判定。大脑认为「清单里的妙招和现有流水线都盖不住」且现场编了计划 → 单子进 `propose`，复用现有「解题思路」卡给人确认，点「按这个做」才开工。**未覆盖任务不闷头跑。**
2. **沉淀四件套**：新任务通道跑成的单，关单时把内存里的 `findings` + `brainPlan` 压缩成技能草稿（route / params / pitfalls / contract + stats），`source:"taught"` + `distilled:true` 存盘，侧栏一句告知。**用户沉默即采纳，不出确认卡。**
3. **P0 遗留 · 当轮转脑**：门岗回放（`replayHabit`）失败不再硬顶——记账后把同一句原话放行给大脑续跑。
4. **P0 遗留 · 白名单删除**：`isOneShotSkill`（本地白名单，登记时标了过期 2027-01-23）整个删掉，「这技能是不是一步到位」改由大脑判定。

配套小改：runner 对 `distilled` 技能不逐字直放（返回脚手架文本给大脑当参考）；`runSkill` 真跑才记 `stats`；`skillCatalogLines` 给沉淀技能打标。

**P2 明确不做**：路线修订提议（同一偏离攒 2 次改 route，设计稿 §2.5 后半）不做，本期只把 stats 攒起来；不改 `verifyContracts`（微博修复刚动过）；不改 shell.html 渲染层；不改 runtime.ts 的 confirm 链路；不动门岗 normalize 与查表本身；不做触发语参数化（已拍板不做）。

**与设计稿的务实差异（保留）**：

1. 设计稿 §2.4「大脑回看 mission-journal 执行日志」→ 改为**关单时直接用内存里的 `findings` + `brainPlan`**。journal 行本来就是从这份内存写出去的（mission-journal.ts:174-188），内容同源，省掉 jsonl 解析。

## 1. 红线（违反就退回重做）

1. `coverage`、`oneShot`、四件套内容全部来自模型输出，本地只做：枚举校验（`"covered" | "new"` / `true | false`）、JSON 抠取、route 形状校验。**禁止**用关键词、正则、白名单在本地预判「这活是不是新任务 / 是不是一步到位」——刚删掉的 `isOneShotSkill` 就是反面教材，不许换皮复活。
2. 沉淀只存**路线级**四件套：fixed 里程碑只允许 `navigate / page_text / wait_for / report` 四种工具 + 槽位 URL；open 里程碑只有目标文字。**禁止**沉淀点击坐标、cssPath、选择器（设计稿 §2.5：网站一改全废，是负资产）。不存密码、验证码、带 token 的 URL（AI-LEARNING.md）。
3. `distilled` 技能永不逐字直放（run_skill 返回脚手架文本，见 2.4）、永不进门岗直放（`replayHabit` 见 2.5）。多步骤技能不做逐字直放是设计稿 §2.2 的死规则。
4. 门岗让路守卫（browser.ts:6118-6127）一个字不动；「运行妙招」窄路**保留**（设计稿 §4 末行的 P2 评估结论：登记入口的确定性仍靠它，留着，以后再说）。
5. 沉淀调用、one-shot 判定都在成功路径上多一次模型调用——**必须 try/catch 兜死**，失败就当没发生，不许挡关单、不许挡执行、不许把错误甩进侧栏。
6. 未配模型：不出「记住」卡（没有大脑判 one-shot）、不沉淀、coverage 不生效。门岗直放与窄路不受影响。
7. 脑区与非脑区不混提交（§5 两个 commit）。`src/main/agent/**` = 脑区；门岗行为改动（replayHabit / maybeOfferTrigger / 登记 IPC）算脑区，跟 understand 同 commit。
8. 只改 §3 列出的文件。`docs/listings/` 不许碰。不动 package.json 版本号。
9. 完成后：`npm test` 全绿 + `npm run typecheck` 退出码 0，再 `npm run start` 手动过 §6 QA 清单，截图当天归档 `qa-screenshots/p2-distill/`（文件名带步骤号），全绿才交。
10. 两个 commit，分开 add，禁止 `git add -A` / `git add .`。

### 2.3 沉淀四件套（脑区：distill.ts + browser.ts 关单 hook）

`distill.ts` 再加：

```ts

  | { kind: "fixed"; tool: "navigate" | "page_text" | "wait_for" | "report"; args: Record<string, unknown> }
  | { kind: "open"; goal: string; tools?: string[] };
```

### 2.5 当轮转脑（脑区行为：browser.ts replayHabit）

`replayHabit`（6130-6147）失败路径改向：

- `ran.ok` 成功：现状不动（recordOutcome、return 成功结果）。
- `!ran.ok`：照旧 `recordOutcome`、推失败原因一句、停用了就再推「已停用」一句、pushSidebarState——然后**不再 return 失败结果，而是返回一个带 fallthrough 标记的值**，让 `dispatchChatJob`（6206-6234）把同一句原话继续放进大脑流程。
- 实现要求：窄路只在「门岗压根没命中」时才进。建议签名改成返回 `ToolResult | "fallthrough" | null`，dispatch 处：

```ts
const replay = await this.replayHabit(text);
if (replay === "fallthrough") { /* 跳过窄路，直接放行到下面的大脑流程 */ }
else if (replay) return replay;
else { /* 未命中：窄路判定照旧 */ }
```

- 为什么必须跳过窄路：P0 QA 登记的触发语本身就是「运行妙招 QA门岗演示」这种句式——失败转脑时若不跳过窄路，同一技能会被窄路立刻重跑一次，永远到不了大脑。
- 转脑后大脑看到的是同一句话，从工作单流程重新理解——技能跑了一半的页面状态就是大脑的起点，这是设计稿 §2.2「失败不硬撑，转交大脑」的本意。
