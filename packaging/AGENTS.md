# AGENTS.md — 给外部 Agent 的 Sparo 说明书

**Sparo** 是这台电脑上的工作浏览器。你是大脑，Sparo 是手。

这份文件和 `Sparo.exe` 放在同一层安装目录。Hermes、Cursor、Trae、Codex、Claude，以及其他能调用 MCP 的 Agent，都按这份说明操纵 Sparo。人不用研究界面。

对人、对界面说「技能」。工具名仍是 `match_skill` / `run_skill`。

## 先连上

1. Sparo 必须开着。你操纵的是用户正在看的那一扇窗口。
2. 让用户在侧栏点「复制给 Agent」，把剪贴板内容交给你。里面有程序位置、MCP 地址和令牌。
3. 优先使用剪贴板里的 `url` 和 `Authorization: Bearer`。你的软件如果只支持本地命令，再用里面的 `command`。
4. 连上后先调用一次 `sparo_info`。
5. 令牌也写在用户目录的 `sparo-store\mcp-auth.json`。商店版端口是 `3921`，地址是 `http://127.0.0.1:3921/mcp`。

| Agent | 怎么接 |
|---|---|
| Hermes | 把 Sparo 当作 MCP 工具执行器，使用上面的地址和令牌 |
| Cursor | 设置里添加 MCP，或写入剪贴板给出的 `mcpServers.sparo` |
| Trae | 按 MCP 服务器添加，使用同一份地址和令牌 |
| Codex | 按 MCP 服务器添加，使用同一份地址和令牌 |
| Claude | 写入 MCP 配置，或使用剪贴板里的 `mcpServers.sparo` |
| 其他 | 任何能调用下面这些工具的客户端都可以 |

同一窗口可以有多个 Agent。每个连接只操作自己的标签，不要抢别人的标签。

## 日常任务

优先 `submit_task` 写清目标，再用 `get_task` 看进展。登录、验证码、人机验证会停下来等用户。

需要自己点页面时，用 `navigate`、`snapshot`、`page_text`、`click`、`fill`。`snapshot` 里的引用在跳转后失效，下一步之前要重新 `snapshot`。

## 技能

技能是 Sparo 里已经写好的做法。不要自己发明一套点击顺序去代替它。

1. 用户说的是日常任务时，先 `match_skill`，看有没有对应技能。
2. 有就 `run_skill`。参数放在 `params` 里，例如标题、正文。
3. 没有对应技能时，再 `analyze_page`，然后 `execute_primitives`。
4. 不知道有哪些技能时，调用 `sparo_info`，或让用户在侧栏用原话描述任务。

店小秘采集箱上品前的编辑，使用技能 `dxm-crawl-prep`。

## 发帖、填表、客服

- 发小红书：`run_skill`，查询用「发小红书」，参数里带标题和正文。脚本注入一次。不要对标题和正文循环调用 `fill`。
- 不认识的表单：`analyze_page`，再 `execute_primitives`。
- 客服回复只填草稿。发送按钮由用户自己点。
- 用户没有说自动发送时，只填草稿。
- 支付、删除、下单由用户自己点。

## 读页面和出报告

- 读页面用 `page_text`。长页面滚动翻页时，从第二次起会带「较上次 +N 字」。+0 就换做法，不要连按同一个按钮。
- 比价、选品、筛选、对比、调研必须出报告页，并在窗口里打开。侧栏只留一句和一张卡片。不要把对照表堆进聊天，也不要逐个点进详情。
- 吃喝玩乐按上一趟行程继续，不走筛选报告。

## 做完才算做完

- 必交付没齐、计划里的步骤没跑完，不要报完成。
- 填表只认回执，或读回来的页面里确实有字。
- 五分钟没有新进展，先换做法，再不行就用白话告诉用户卡在哪里。
